## 1. UI 화면 구성

### 1.0-A 최신 UI 구조 재검토 (2026-10-09)

**전체 VFX 후속 수정(2026-10-09):** 공격은 예고·진입·충돌·복귀를 분리하며 행동 서열 확장은 행동 종료까지 유지한다. 공통 모션은 원화 비율을 거의 유지하고 11Hz 감쇠 피격·절제된 squash를 쓴다. 등장 낙하는 `t^2.2`, 일반 동시 착지는 화면을 흔들지 않는다. 보호막은 투명 막과 얇은 가장자리, 버프는 작은 상단 수렴, 화염은 따뜻한 원소 색을 유지한다. `CombatHud` 레이어가 `CombatVfx`보다 앞에 이름/체력/자원 글자를 보존한다. 타격은 원화 중심, 진형 연기는 받는 진영 원화 범위를 넘지 않는다. 일반 접촉의 전역 focus/flash는 약하게 제한한다. 카메라 진폭은 .09 카드 범위의 soft-knee로 무게를 구분한다.

버튼/카드 피드백은 원래 배율을 보존하고 해제·밖 취소·비활성화 시 복원한다. 전장 포인터는 실제 원화/정보판을 먼저 판정하고 기존 바닥 콜라이더를 보조로 쓴다. 보상/상점 카드는 .04초씩(최대 .12초) 순차 .18초 페이드하며 등장 완료 전 입력을 차단한다. VFX와 모든 효과음/음성 변주는 전투 난수를 사용하지 않는다. `allvfx_presentation`은 실제 InputSystem 마우스와 드래그 취소/정지/복귀를 검사한다. `allvfx_skills`의 가시 픽셀 비교는 기능 증거이며 1920×1080 미술 검수를 대체하지 않는다. 고정 캡처 프레임의 60fps 영상은 연출 검토 자료이고 실행 성능 60fps 보장이 아니다. 구매 팩·스프라이트·임시 음성을 보존한다.

최신 사용자 지시: **Apple의 절제된 유리 재질 + 블루 아카이브의 밝은 청량함 + 원신 계열 게임의 화면 구성. 기존 적 카드의 스탠딩과 하단 정보판을 기준으로 아군도 같은 구조를 사용한다.**
원화를 새 흰 카드에 가두지 않는다. 이전의 좌하단 고정 파티 패널은 더 이상 기본 HUD에 생성하지 않는다.
상업 출시 수준으로 엄격하게 평가하되, 자동 기능 검사와 직접 시각 검수를 구분한다.

- 유리의 흐림과 반사는 헤더·탐색 크롬에만 둔다. 장문 본문은 불투명한 밝은 읽기 면이다. 군청을 기본 잉크로 쓰고 의미 있는 체력·원소·피해·상태 색을 보존한다.
- `PartyVitalsPanel` 소스는 보존하되 `BattleHud`는 생성하지 않는다. `UnitCardView`가 아군·적의 동일 정보판을 관리한다. 원화 크기와 월드 칸 좌표는 기존 적 구조를 유지한다.
- 체력 행은 현재값을 보여주고 최대값은 상세/툴팁에서 확인한다. 월드 이름·체력·자원은 전용 행 안에서 자동 크기를 조절한다. 옛 초월 오브와 중복 수리야 표시판을 숨긴다.
- `CombatFeedbackSurface.Clamp`의 기본 아래 경계는 154px다. 상태의 머리 위 기준은 실제 원화 화면 경계를 사용한다.
- 공통 헤더는 기능별24px 기호와 제목을 40px 간격으로 정렬한다. 흰 장식 프레임을 반복하지 않는다.
- `UIShapes`의 모서리와 반사선, `UIButtonStyle`의 호버·누름·키보드 선택을 공유한다. 일반 버튼에 상시 외곽 링을 반복하지 않는다. 명시적인 선택과 드롭 가능 표시는 남긴다.
- `ScreenKit`은 티어 눈금, 고정 높이 밴드, 작은 기능 아이콘, 선택 면, 목록 아래 페이드, 초상 창을 공유한다. 스프라이트 원본과 GUID를 수정하지 않는다.
- 용어 툴팁은 부모/자식 본문이 겹치지 않는 위치를 선택하고 실제 캔버스 경계에 맞춘다. 그림자는 클릭 영역이 아니다. 상세 링크는 군청 텍스트 링크로 표현한다.
- 실제 검증은 주요 화면, 코드 드래그/교환/보관, 상점 수신자와 소비, 검색/중첩/이전 위치, 글자/HUD 배율 9조합, 전투 속도·일시정지·확장 유지, 저장을 포함한다. 수행 결과와 잔여 사항은 `Logs/UIResetTreasure20261008/`에 남긴다.
- 출시 참고 조사와 항목별 판단 기준은 [Review_UI_Commercial_20261008.md](Review_UI_Commercial_20261008.md)에 둔다. 이전 `UIRefinement20261008`의 승인 표기는 당시 기능 검증 기록이며 최신 사용자의 시각적 승인으로 취급하지 않는다.

### 1.0-B 상용 미술 보정 및 로비 (2026-10-09)

- 공통 행동 면은 작은 10px 반경, 절제한 군청 명도 차, 얇은 보조 경계와 1.5% 이내 누름 수축을 쓴다. 원형 닫기/작은 조작은 별도 원형 반경을 유지한다.
- 코드 각인은 256px 안티앨리어싱 외환/마름모와 역할 기호를 재사용한다. 티어는 동일 크기 마름모 + T숫자다. 읽기 면의 장식은 낮은 명도로 두며 제목·효과를 덮지 않는다.
- 코드 상세는 내용 높이에 따라 320px부터 가용 높이까지 조절한다. 상점 가격/구매 띠는 실제 버튼이며 카드 전체 클릭과 수신자 선택/취소/확정 규칙을 유지한다.
- 로비에는 공통 모달 머리띠/창을 씌우지 않는다. 좌측 브랜드·캐릭터, 우측 주 행동과 독립 보조 타일을 분리한다. 명일방주 홈을 참고하되 없는 모집·재화·기지 기능을 장식으로 만들지 않는다. 밝은 배경/군청 잉크를 유지한다.
- 로비 스탠딩은 `Image.Type.Simple` + `preserveAspect = true` + 가로/세로 동일 배율이다. `UIBuild.Solid`의 기본 Sliced를 원화에 그대로 쓰면 비율 유지가 무시되어 눌리므로 반드시 표시 타입을 바꾼다. 원본 PNG와 GUID는 보존한다.
- 편성 스탠딩은 하단 설명과 겹치지 않는 남은 영역을 사용한다. 상단 여백을 48px에서 12px로 줄이고 원본 비율을 유지한다. 파티·상점·사건의 스탠딩 경로도 Simple 기본 이미지임을 확인한다.
- 큰 로비 기호는 192px, 작은 공통 기호는 96px를 사용한다. 정적 캐시이며 회전/점멸하지 않는다. 한글 현대 줄바꿈 규칙을 활성화하여 좁은 칸의 음절 분리를 줄인다.
- 이번 기준은 1920×1080이다. 실제 실행 근거와 중간 반려·최종 화면은 `Logs/UICommercial20261009/`에 기록한다. 기능 검증을 상용 미술 품질에 대한 외부 인증이나 사용자 승인으로 표현하지 않는다.

### 1.0 게임 판 크롬 개편의 기반 (2026-09-27)

> 위치·카드 정보·모달 범위는 위 1.0-A의 2026-10-08 사양이 우선한다.

- 화면 바탕은 `Board.Base #F7FAFC` · `Board.Field #EAF2F7` · `Board.SkyInset #D8EDF7`의 밝은 하늘 성채 판이다.
  은청색 선으로 구조를 나누고 샴페인 금속은 작은 접합점에만 써 고채도 면적을 10% 아래로 둔다.
- 전투는 상단 통합 레일 / 좌측 행동 순서 / 우측 피해 집계, 준비는 중앙 전장 / 하단 커맨드 레일로 역할을 나눈다.
- 전장은 불투명한 사각 카드 대신 자유 원화와 하단 리퀴드 글라스를 쓴다. 카드 바깥 기능 크롬은
  진주색 라이트 글라스 한 장과 1px 은청색 구분선으로 묶고, 원화 위 플로팅 띠만 스모크 글라스를 유지한다.
- 화면 고정 크롬은 `UITheme.ScreenEdgeInset = 24px`(1920×1080 기준)를 공유한다. 상단 바 · 좌우 전투 레일 ·
  준비 독 · 넓은 관리/보상/결과 화면의 좌우 끝선은 `UISafeArea` 안에서 같은 수직선에 놓인다.
  상단은 10px, 상단 바 높이는 72px, 그 아래 고정 패널과의 간격은 20px다. 단순 확인 창은 작은 모달을 유지한다.
- `UISafeArea`로 로비·모달·HUD·준비바의 기기 안전 영역을 반영한다. 배경은 전체 화면이다.
- 가로 양방향 회전을 사용한다. 전장 포인터는 마우스와 기본 터치를 통합하며, UI 위 드롭·취소 터치는 원위치로 돌린다.
- 툴팁은 마우스 호버와 터치 길게 누르기(0.55초)를 지원한다. 긴 내용은 임의로 잘라 버리지 않는다.
- 마우스 호버 툴팁은 우상단 원형 게이지가 0.85초 동안 차면 그 자리에 고정된다. 고정 전에는
  레이캐스트를 받지 않고, 고정 뒤에만 패널 안으로 포인터가 들어갈 수 있다. 캐릭터 툴팁의 전투 성향
  `[아이콘 | 태그]` 칩에 마우스를 올리면 설명을 보조 툴팁으로 띄운다.
- 전투 성향 아이콘은 `UILineIcons`의 동일 획 폭 선형 스프라이트다. 선택 화면에서는 액센트,
  다른 UI에서는 해당 문맥의 색을 `Image.color`로 입힌다. 기존 `Sprite/UI/UnitTags/` 원본 에셋은 보존한다.
- 한글 UI는 `NotoSansKR-Regular SDF`를 기본으로 쓴다. 없을 때 Variable → Maplestory 순으로 폴백하고,
  UGUI와 월드 TMP의 Distance Field 재질은 분리한다.
- 빠른 마우스 드래그는 Input System의 실제 누름·놓음 이벤트 좌표를 기록한다. 이전 프레임 좌표나 이동량으로 시작점을 추정하지 않는다.

#### 행동서열 삽입 슬롯

좌상단 `ACTION ORDER`는 행동 예측과 발동 알림을 한 레일에서 함께 표시한다. 실제 행동이나
특성 효과가 성립하면 별도 배너를 겹치지 않고, 서열 맨 위에 기존 초상 슬롯이 가로로 열리는
**끼어든 항목**을 삽입한다. 확장 슬롯은 `[유닛 이름] [종류] [행동 이름]`을 한 줄로 보여 주며,
아군은 하늘색 초상화 링·테두리, 적은 적색 링·테두리로 구분한다. 좌측 `I` 모양 강조 막대는 쓰지 않는다.
종류는 `일반행동` · `대체행동` · `추가행동` · `협동행동` · `궁극기(초월기)` · `특수행동` ·
`패시브(특성)` 중 하나이며, 궁극기·추가·협동·특수·패시브는 우상단의 작은 끼어들기 표식으로 구분한다.

`Combat.ActionAnnouncer`가 공용 진입점이다. `ActionScheduler`는 행동을 꺼내 실제로 시작할 때 알리고,
조건만 확인하는 패시브는 알리지 않는다. 패시브 코드는 자원 획득·상태 부여·후속 공격처럼 효과가
실제로 적용된 지점에서만 `AnnouncePassive`를 호출한다. 행동 이름은 `20_codes.yaml`의 표시명을 우선하며,
런타임 대체행동만 명시 이름으로 보완한다.

삽입 슬롯은 0.18초에 열리고, 유지 시간 2.8초는 사용자 1·2·4배속에 맞춰 줄어든다. 별도 일시정지에서는 유지 시간이 멈춘다. 연속 발동은 최대 세 줄까지
쌓고, 아래 예측 슬롯은 빈자리를 순간 이동하지 않고 지수 감쇠 보간으로 밀리고 올라온다.
예약 추가행동·궁극기는 같은 슬롯에서 표식과 두꺼운 진영 테두리로 보이며, `AdvanceAction`은 해당 유닛에
약 0.92초 동안 작은 `↑`를 붙인다. 지연은 `↓`다. 속도 변화·예약 삽입·사망 제거로 예측 순서가 바뀌어도
안정 키로 기존 슬롯을 재사용하므로 0.06~0.18초 범위의 짧은 이징으로 새 자리까지 이동한다.
구현은 `HUD/ActionQueuePanel`과 `ActionScheduler.Reservation.StableKey`가 맡는다.

**ESC는 가장 위의 창부터 닫는다.** `ModalScreen.TryEscapeTop`이 떠 있는 모달 중 정렬 순서가 가장 높은 것에
ESC를 넘긴다. 배경으로 닫히는 창(상점 · 스킬 · 메뉴 · 자료실)은 ESC로도 닫히고, 확인 창은 취소, 훈련은
돌아가기다. 진행을 막는 창(보상 · 사건 · 전투 결과)은 받지 않으므로 ESC가 평소처럼 메뉴를 연다.
TAB 파티 창이 떠 있으면 그 아래 층 창은 건드리지 않는다(§1.5-A). 창이 없고 덱 구성 모드가 켜져 있으면 모드를 끈다.

### 1.1-C 준비 페이즈 바

안전 영역 좌우 24px, 높이 176px(1080p 기준), 하단 18px의 판 매입형 커맨드 레일이다.
상태 · 자원을 상단 한 줄에, 행동을 하단 한 줄에 배치한다. 전투 시작은 가장 넓은 틸색 버튼이다.

| 줄 | 내용 |
| --- | --- |
| 머리 | `PREPARATION / COMMAND` 눈썹 · `작전 준비` 제목 · 대표 레벨/EXP · 골드 · 식량/긴 휴식 비용 · 짧은 휴식 횟수 |
| 커맨드 독 | [휴식] [상점] [공용 보급] [덱 구성] ｜ 큰 [전투 시작] CTA |

버튼마다 이름 아래 상태 한 줄이 붙는다 — 휴식 `짧은 휴식 N회 · 식량 M`, 상점 `구매 N회 남음`, 공용 보급 `공용 · N개`(2026-10-06 이름만 "인벤토리"에서 바꿈), 덱 구성 `배치 바꾸기` / 켜지면 [완료] `모드 끄기`, 전투 시작 `R-S`(보스면 `· 보스`).
꺼진 이유가 버튼 위에 있으므로 윗줄 문장을 읽지 않아도 된다.

### 1.1-D 전투 결과 화면 (BattleResultScreen)

모든 전투(사건 안 전투 포함)가 끝나면 뜬다. **확인(Enter · Space · 클릭)을 눌러야 다음으로 넘어간다.**
ESC로는 넘어가지 않는다 — 결과를 못 보고 지나치는 일을 막는 화면이다.

창보다 먼저 전장 위에 **판정 띠**가 1.4초 뜬다 — 글라스 띠에 `VICTORY 전투 승리` / `DEFEAT 전투 패배` /
`RUN TERMINATED 런 종료`. 누르거나 Enter · Space로 건너뛴다. 예전에는 마지막 적이 쓰러진 프레임에 창이 덮여
이긴 순간이 보이지 않았다.

| 자리 | 내용 |
| --- | --- |
| 판정 띠 | `MISSION COMPLETE` 작전 성공(민트) / `MISSION FAILED` 작전 실패(적색) / `RUN TERMINATED` 런 종료. 이유 한 줄(적 전멸 · 턴 초과 · 아군 전멸) · 스테이지 `R-S`와 테마 |
| 칸 넷 | 목숨(줄었으면 `18 → 14` 적색 강조, 차이와 남은 적 수) · 골드(처치 + 승리 보수) · 경험치 · 처치(토큰 획득) |
| 딜 그래프 | 출전한 아군을 딜량 순으로 한 줄씩 — 초상화 · 이름 · 막대(1등 기준 길이, 1등만 금색) · 딜량과 비중(%). 쓰러진 사람은 어둡게 + `전투 불능`. 머리에 합계와 `전원 생존` / `전투 불능 N명` |
| 버튼 | 승리 `보상 선택` · 패배 `다음 스테이지` · 런 종료 `메인 메뉴로` |
| 전투 로그 | `전투 로그` 버튼(또는 L)이 **전투 로그 창**(`CombatLogScreen`)을 연다. 아래 참고 |

값은 `GameManager`가 모은다 — 전투 시작 때 목숨 · 골드 · 누적 처치와 출전 파티를 적어 두고(`CaptureBattleStart`),
끝나면 **필드 복원 전에** 쓰러진 사람을 센 뒤(`BeginBattleResult`), 보수 지급이 끝나고 차이를 채운다(`FinishBattleResult`).
전투 불능이 된 아군은 전투 뒤 필드 복원으로 **전투 시작 때의 체력으로 돌아온다**(§4.5).

딜량은 `Combat.DamageMeter`가 센다. `Unit.AnyDamageDealt`에서 **방어막과 체력에서 실제로 깎인 양**만 받고,
소환수의 피해는 소환자 몫, 아군이 아군에게 준 피해는 제외한다. 전투 중에는 우측 **딜 그래프**
(`HUD/DamageMeterPanel`, 행동 순서와 마주 보는 자리)가 같은 값을 0.2초마다 다시 그린다.
사건 전투도 `CaptureBattleStart`를 거쳐 지난 판의 값이 남지 않는다.

**전투 로그 창** — 자동 전투라 플레이어가 고칠 수 있는 것은 편성뿐인데, 왜 졌는지 모르면 무엇을 고칠지도 모른다.
위쪽 **원인 요약**이 먼저 답한다: 끝난 이유 · 쓰러진 아군(턴 · 누구의 공격) · 아군에게 가장 많이 넣은 적(비중) ·
가장 많이 맞은 아군. 아래에 전체 기록이 턴 순서로 흐르고 탭으로 거른다 — **주요**(기본: 쓰러짐 · 궁극기 ·
최대 체력 30% 이상 한 방 · 시작/종료) · 전체 · 행동 · 피해 · 쓰러짐/반응/상태. 줄 색은 주인공 진영(아군 민트 · 적 적색).
기록은 `Combat.CombatLog`가 기존 전역 이벤트(`ActionScheduler.AnyActionStarted` · `Unit.AnyDamageDealt` ·
`AnyUnitDied` · `AnyElementalReaction` · `AnyHitNullified` · `AnyEvaded` · `AnyNegativeStatusGranted`)를
듣기만 해서 모은다. 한 판 3,000줄이 상한이고 넘치면 앞부분부터 버린다(원인은 대개 끝에 있다).
로그 창이 떠 있는 동안 Enter는 결과 화면을 넘기지 않는다. ESC · 바깥 클릭으로 닫는다.

목숨이 0이 되면 같은 화면이 런 종료를 알리고 메인 메뉴로 보낸다. 예전에는 아무 화면 없이 멈췄다.
자동 검증 도구(`DebugMode.SuiteRunning`)가 도는 동안에는 화면 없이 곧바로 넘어간다.

### 1.1-E 설정 창

왼쪽 레일에 탭 셋, 오른쪽에 줄마다 [이름 + 한 줄 설명 | 조작]. 선택지가 많으면 `‹ 값 ›` 스테퍼, 2~3개면 한 줄 세그먼트.

| 탭 | 항목 | 값 | 적용 |
| --- | --- | --- | --- |
| 화면 | 표시 방식 | 테두리 없는 전체 화면 · 전체 화면(윈도우에서만 독점) · 창 모드 | **[적용]** 뒤 12초 안에 [유지]를 안 누르거나 설정 창을 닫으면 되돌린다 |
| | 해상도 | 모니터 목록(1280×720 이상, 주사율 중복 제거) + 흔한 창 크기 | 위와 같음 |
| | 수직 동기화 | 끔 · 켬 | 즉시 |
| | 프레임 제한 | 30 · 60 · 120 · 144 · 240 · 제한 없음 (수직 동기화가 켜져 있으면 꺼짐) | 즉시 |
| 인터페이스 | 글자 크기 | ×1 · ×1.15 · ×1.3 (§1.3) | 즉시, 숨은 화면까지 |
| | HUD 크기 | ×0.9 · ×1 · ×1.15 — 상단 바 · 행동 순서 · 준비 바 · 툴팁 캔버스만. 전장 카메라가 비워 두는 픽셀(§1.9)도 같이 커진다 | 즉시 |
| 소리 | 음악 · 효과음 | 0~100 | 즉시 |

값은 `SettingsManager`가 PlayerPrefs에 둔다. 매니저는 첫 씬 로드 직후 스스로 생기며(`RuntimeInitializeOnLoadMethod`),
저장된 화면 설정이 있으면 그때 적용한다(에디터에서는 적용하지 않는다). [유지] 전 시험 적용값은 저장하지 않아 강제 종료 뒤에도 마지막 확정값을 복원한다. 플레이어 설정의 창 크기 조절(`resizableWindow`)을 켰다 —
창 크기가 바뀌면 전장 카메라가 다시 맞춘다. HUD 크기 1.15를 넘기면 1080p에서 상단 자원 띠와 우상단 바가 겹치므로 상한으로 둔다.

### 1.5-A ESC 메뉴와 TAB 창의 분리

두 창은 **따로 열리고 따로 닫힌다.**

| | ESC 메뉴 | TAB 파티 창 |
| --- | --- | --- |
| 여는 입력 | ESC · 우상단 ≡ (같은 입력, `UIManager.HandleEscape`) | TAB · 우상단 [파티] 버튼 · 전장 카드 클릭(그 유닛을 골라 연다) |
| 닫는 입력 | ESC · ≡ · 계속하기 · 바깥 클릭 | TAB · × · 바깥 클릭 · [공용 보급 열기] |
| 내용 | 설정 · 자료실 · 저장/불러오기 · 나가기 | 빌드 · 코드 |

**ESC가 위다.** 파티 창이 떠 있을 때 ESC를 누르면 파티 창을 닫지 않고 **그 위에** 메뉴가 뜬다.
메뉴를 닫으면 파티 창이 그대로 남아 있다. 메뉴가 떠 있는 동안 TAB은 무시한다.
ESC는 메뉴 묶음 안에서 가장 위의 것 하나만 닫는다(설정 → 자료실 → 메뉴).

캔버스 층은 `UITheme.Layer*` 상수 한 곳에서 정한다.

| 층 | 정렬 |
| --- | --- |
| 진행 모달(보상 · 상점 · 캐릭터 선택 …) | 70~80 |
| TAB 파티 창 | 120 |
| ESC 메뉴 | 130 |
| 자료실 | 135 |
| 설정 | 136 |
| 확인 창 | 140 |

**나가기 세 갈래** — 메뉴 안에서 `나가기` 머리글 아래 따로 묶는다. 이름에 결과를 적고, 버튼 오른쪽에 한 줄 설명을 붙인다.
예전 이름(저장 후 나가기 · 나가기 · 바탕화면으로 나가기)은 무엇이 저장되고 어디로 가는지 갈리지 않았다(QA).

| 버튼 | 설명 줄 | 저장 | 도착 |
| --- | --- | --- | --- |
| 저장하고 메인 메뉴로 | 이어하기로 여기서 계속 | 저장한다 (`CanSaveNow`일 때만 켜짐) | 메인 메뉴 |
| 저장 없이 메인 메뉴로 | 마지막 저장 이후는 사라짐 | 하지 않는다 | 메인 메뉴 |
| 게임 종료 | 저장하지 않고 끔 | 하지 않는다 | 게임 종료 |

셋 다 확인 창을 거친다. `게임 종료`가 몰래 저장하지 않는 것은 의도다 — "그냥 끄기"를 고른
사람의 저장본을 덮어쓰면 안 된다. 저장이 필요하면 `저장` 또는 `저장하고 메인 메뉴로`를 먼저 쓴다.

### 1.5 TAB 화면 — 파티 창 (CodexScreen)

**지금 파티의 상태만 다룬다.** 런과 무관한 참고 자료(전체 캐릭터·코드·아이템·적,
추천 조합)는 §1.5-B 자료실이 맡는다. 장비 · 중량은 없다. 아이템은 공용 보급, 보상 코드는 유닛별 활성 7칸과 개인 보관함에 둔다.

2026-10-06 개편: 예전에는 다섯 명을 좁은 다섯 열에 세워 보상 코드 7칸 · 스탯이 모두 작게 눌렸고, 카드를 눌러 열어도
그 유닛을 고르지 않았다(`Show(Unit focus)` 무시). 지금은 **한 명을 골라 오른쪽 전체를 그 유닛에 쓴다.**

```
┌ PARTY BUILD ───────────── [빌드][코드] ─────── [공용 보급 열기] [×] ┐
│ ┌파티 레일┐ ┌머리: 원화 · 이름 · Lv/EXP · 원소 · 자리 · 체력/자원 · 태그 ┐ │
│ │세이     │ ├───────────────────────────────┬──────────────────┤ │
│ │Lv·전열  │ │ 보상 코드 n / 7                 │ 칸 k 상세(스크롤)   │ │
│ │코드 7/7 │ │ 1 T1 ▏효과 한 줄                 │ 효과 전문 · 이름 · │ │
│ │인드라   │ │       이름 · 태그 · ▲상위        │ 태그 · 상위 경로    │ │
│ │…(5명)   │ │ … 7칸(빈 칸은 테두리 · 얻는 길)   ├──────────────────┤ │
│ │         │ │                                │ 스탯(기초 → 최종) 8 │ │
└─┴─────────┴─┴────────────────────────────────┴──────────────────┴─┘
```

| 구획 | 내용 | 코드 |
| --- | --- | --- |
| 파티 레일 | 파티원 한 줄씩(최대 5) — 초상화 · 이름 · `Lv.n · 전열/후열/대기석/전투불능` · `코드 n/7`(가득 차면 금색). 소환수와 같은 영웅의 중복은 뺀다. 누르면 그 유닛을 고른다(`Member_{이름}`) | `CodexScreen.BuildRail` · `PartyMembers` · `PlacementText` |
| 선택 규칙 | `Show(focus)`에 파티원이 오면 그 유닛을 고른다(소환수면 소환자). 포커스 없이 다시 열면 지난 선택 · 탭을 유지한다. 파티가 바뀌어 보던 유닛이 사라지면 같은 영웅의 새 인스턴스, 없으면 첫 유닛 | `CodexScreen.Show` · `Refresh` |
| 머리 | 원화 · 이름(30) · `Lv · EXP · 원소 · 자리` · `체력 · 마나`(상시 초월기는 `초월기 상시 발동`, 중첩형은 `초월기 중첩`)와 전투 자원 · 성향 태그 칩 · 한 줄 소개 | `BuildIdentity` · `VitalsText` |
| **보상 코드 7칸** (빌드 탭 가운데) | 칸 번호 · `Tn` · 티어 색 띠. **번호·티어·이름·효과를 한 행(22)으로 비교**한다. 태그·상위는 상세와 툴팁에서 읽는다. 빈 칸은 안쪽을 칠하지 않은 짙은 테두리 + `전투 보상 · 상점 코드 탭에서 획득`. 칸을 누르면 오른쪽 상세가 바뀐다(`RewardSlot{i}`) | `BuildRewardSlots` |
| 칸 상세 | 효과 전문 → 이름 · 티어 · 칸 번호 → 태그 → 상위 경로(`하위 → [이 코드] → 상위(Tn) → …`, 상위를 받으면 이 칸에서 바뀐다) → 꼬리표. 넘치면 굴린다. 빈 칸을 고르면 얻는 길(전투 보상 · 상점) · 7칸이 차면 보관함으로 수령 · 상위 획득 시 하위 보관 · 인장은 공용 보급이라는 안내 | `BuildSlotDetail` · `DetailText` · `EmptySlotGuide` |
| 스탯 | 여덟 스탯 `기초 → 최종`(달라지면 초록). 보상 코드의 깡 · 퍼센트 보정과 영혼은 최종값에 이미 들어 있다 | `BuildStats` |

**빌드 탭 아래 개인 코드 보관함**은 3열 스크롤이다. 준비 중 활성↔보관과 아군 간 이동을 무료 드래그로 한다. 점유 칸은 출발 위치와 교환하고 왼쪽 아군 초상화는 그 아군의 보관함으로 이동한다. 동일 활성·상하위·오래된 출발·준비 밖은 거절한다. main의 `UIDragSource`/`UIDropTarget`/`UIDragRuntime`을 재사용한다(Detail_17 §2).
[공용 보급 열기]는 준비 페이즈에서만 켜지고, 누르면 이 창을 먼저 닫은 뒤 정식 경로(`GameManager.OpenInventoryFromPreparation` → `UIManager.ShowInventoryPanel`)로
공용 보급을 연다 — 층이 다른 두 창(120 · 73)이 겹치지 않게 한다.

**항상 열 수 있다** — `BattleHud.Update`가 매 프레임 TAB을 검사하며, 캔버스 정렬 순서가 120이라
보상·사건 같은 모달(80)보다 위에 뜬다. 어느 페이즈에서든 파티의 현재 스탯과 코드를 확인한다.
단 ESC 메뉴(130)보다는 아래다 — §1.5-A.

**열린 동안의 갱신.** 전투 중에도 열 수 있으므로 고른 유닛의 체력 · 마나/자원 · 레벨 · EXP · 자리 · 8스탯과 레일의 `Lv · 자리 · 전투불능` · `코드 n/7`은
`CodexScreen.Tick`이 매 프레임 읽어 글자 · 색이 달라질 때만 고친다(계층을 다시 만들지 않아 스크롤 · 고른 칸 · 툴팁이 그대로다).
파티 구성이나 고른 유닛의 코드 칸이 바뀌면(6프레임마다 구조 해시 비교) 다시 그리되 목록 · 상세의 스크롤 위치와 선택 · 탭 · 고른 칸을 지키고,
고른 유닛이 사라졌으면 남은 첫 유닛으로 바꾼다. 표에 설명이 없는 코드는 화면에 "효과 정보를 불러오지 못했습니다."만 보이고 슬롯 · ID는 로그에 남긴다.

**코드 탭** — 고른 유닛의 고유 특성 · 일반행동 · (가진 유닛만) 특수행동 · 초월기를 한 목록에 놓고 등급(은 · 금 · 보라)으로 이름에 색을 준다.
특수행동이 없는 유닛에는 항목을 만들지 않는다. 그 아래에 **보상 코드**를 칸 순서대로(`n번 칸 · Tn · 태그`, 효과 전문, 상위 코드 줄),
사건이 준 비보상 패시브는 "그 밖의 패시브"로 따로 모은다. 본문 폭 전체를 한 유닛이 쓰므로 문구를 줄이지 않고 다 적고, 넘치면 굴린다.
이 런의 현재 값에 따라 달라지는 코드는 설명 아래에 강조색 **실시간 줄**을 하나 더 단다 — 지금은 쿠베라 골드 러쉬의 `현재 금력 배율 ×n.nn` · `보유 골드 · 스테이지`뿐이다
(`CodexScreen.LiveTextOf`, 값은 코드의 `KuberaGoldRush.GoldMultiplier(out, out)`). 창이 열려 있으면 `BattleHud.Update → CodexScreen.Tick`이 매 프레임 읽어 글자가 달라질 때만 고치고,
그 항목의 툴팁이 떠 있으면 `TooltipTrigger.RefreshIfShown` → `UITooltip.Refresh`로 위치 · 고정 상태를 둔 채 내용만 고친다. 자료실 · 선택 화면에는 런 값을 넣지 않는다.
2026-10-05 구현 · 실제 Unity Play 검증 완료(`kubera_followup_core` · `kubera_followup_lokapala_ui`, 당시 5열 화면).
2026-10-06 1인 화면으로 바꾸면서 두 시나리오는 레일의 실제 버튼으로 유닛을 하나씩 골라 같은 검사를 한다. 이후 실제 Unity에서 새 레일/코드 탭 회귀를 검증한다(아래 최신 검증 기록).

**이름 아래에 효과 문장이 붙는다.** `20_codes.yaml`의 `description`을 `CodeCatalog`가 읽어,
`<고유 패시브>` 같은 꼬리표와 `#물리` 같은 피해 태그를 걷어 낸 문장을 전문으로 싣고 꼬리표는 그 아래 흐린 줄로 둔다.
마우스를 올리면 전문 · 등급 · 꼬리표가 툴팁으로 뜬다. 코드가 많으면 목록이 스크롤된다.

코드 인스턴스는 제 ID를 모르므로 `CodeFactory`가 만들 때 `Code.CatalogId`를 새긴다(슬롯별 네임스페이스라
조회는 슬롯과 함께). 팩토리를 거치지 않은 코드는 클래스 이름(`codeName`)으로 찾되, 한 클래스를
여러 항목이 나눠 쓰면 찾지 않는다. 표에서 빠진 코드는 빈칸 대신 `설명 없음 — 슬롯 #ID`가 찍힌다.

### 1.5-A2 미해금 캐릭터 표시

해금 조건이 남아 있는 캐릭터는 **선택 화면에 미해금 타일로 뜨고 조건 한 줄을 달고 있다.**
예전에는 라부아지에 한 명만 하드코딩돼 있었는데, 0.4.8에서 데이터 기반으로 일반화했다.

| 요소 | 위치 |
| --- | --- |
| 조건 문구 | `10_units.yaml`의 `unlockCondition` — 이 칸이 비어 있지 않은 유닛만 잠금 표시 대상이다 |
| 판정 | `CharacterSelectionManager.IsPendingUnlock` — 해금되지 않았고 조건 문구가 있을 때 참 |
| 표시 | `CharacterSelectScreen` — 타일 이름은 `미해금 · 이름`, 초상화는 어둡게, 본문은 조건 한 줄만 |

**코드에 캐릭터 이름을 적지 않는다.** 새 캐릭터에 해금 경로가 생기면 `unlockCondition` 한 줄을
더하는 것만으로 화면이 따라온다.

누적 수치로 열리는 조건은 계정 저장이 세고 있다 — `unlockAfterSummonCount`(소환),
`unlockAfterSingleTargetHits`(단일 피해), `unlockAfterShieldGrants`(방어막).
단일 피해는 한 전투에서만 수백 번 일어나므로 타격마다 저장하지 않고 메모리에 모았다가
라운드가 끝날 때 `SaveSystem.FlushUnlockCounters`가 한 번에 기록한다.

### 1.5-B 자료실 (WikiScreen)

ESC 메뉴 또는 설명 속 용어 사전의 **자료실에서 자세히 읽기**로 연다. 자료실이 직접 진입 전의
`Time.timeScale`을 보관하고 0으로 멈추며, 닫으면 해당 배속으로 돌아간다. 메뉴가 이미 멈춘 상태이면
닫은 뒤에도 0을 보존한다. 자료실은 저장·파티 편성·현재 코드 효과를 변경하지 않는다.

| 갈래 | 목록과 본문 | 원본 |
| --- | --- | --- |
| 가이드 (기본 화면) | 시작·자동 전투·원소·빌드·야영·생존의 6장 카드. 설명 → 편성 예시 → 함께 읽기 | `GameGuideCatalog.Guides`, Detail_01/02/03/05/16/17 |
| 캐릭터 | 소개·기본 정보 → 특성/일반/초월기/선택형 특수행동 → 추천 조합 → 성장 스탯 | `10_units` · `20_codes` · `30_synergies` |
| 코드 | 현행 보상 코드와 실제 아군의 모든 스킬 슬롯. 보상 티어·상위 코드·사용 캐릭터 상세 연결 | `RewardCodeCatalog.All` · `10_units.codes` · `CodeCatalog` |
| 보급품 | 현행 식량·비약·코드 도구·귀중품. 효과와 획득처 | `40_items` · `60_enemies` |
| 적 도감 | 테마·보스/정예/일반, 실제 스탯·스킬·전리품 | `60_enemies` · `80_stages` |
| 용어 사전 | 전투 규칙·편성·원소 반응·캐릭터 메커니즘·역할·편성 유형 | `GameGuideCatalog.Terms` · `30_synergies` |

밝은 문서 면, 남색 머리, 얇은 청록 선택선, 장별 카드와 독립 스크롤 목록을 사용한다.
주요 본문은 24, 목록·보조 본문은 22 기준 크기다. 전체 분류를 함께 검색하며,
**돌아가기**는 이전 분류·검색어·선택 항목·본문 스크롤을 복원한다. 목록의 첫 화면·닫기 버튼은 고정된다.

**용어 사전 툴팁** — `UIBuild.Text`의 줄바꿈 본문에 `GameTermLinks`가 연결되고,
실제 TMP 링크 문자를 포인터로 찾는다. 코드 설명·캐릭터 선택·상점/보상 설명·자료실·공용 툴팁에 같은 사전을 쓴다.
밑줄 용어에 0.3초 머무르면 짧은 설명이 열리고, 0.65초 뒤 패널이 고정돼 버튼과 관련 용어를 조작할 수 있다.
클릭/터치로도 즉시 고정할 수 있다. 관련 용어를 열면 부모를 남기며 최대 4층까지 탐색한다.
포인터가 사전 밖으로 나가면 0.7초 유예 뒤 닫힌다. ESC는 사전 한 층부터 닫고 그 다음 자료실/메뉴를 닫는다.
일반 카드 툴팁은 용어 사전을 탐색하는 동안 유지하며 현재 값 갱신 기능도 보존한다.
상세 읽기는 해당 항목을 직접 열고, 함께 읽기와 스킬의 사용 캐릭터 링크도 같은 탐색 경로를 사용한다.

용어의 짧은 설명과 상세는 `GameGuideCatalog`에서 함께 관리한다. 캐릭터 고유 메커니즘의 상세는
해당 코드의 실제 표시 설명을 사용한다. 같은 이름의 **활성 코드/성장치**를 원소 반응으로 연결하지 않으며,
아그니의 **집중 포격**을 지속 규칙인 집중으로 잘못 연결하지 않는다.
옛 CON 반응 위력·은/금 코드 안내·폐기된 패시브 ID 범위는 자료실에서 제거했다.

검증: `guide_rework`가 실제 문자 히트·마우스 호버·부모/자식 사전·ESC·상세 이동·뒤로 가기·전체 검색·
특수행동·배속 복원·메뉴 일시정지 보존·실제 파티 스킬 설명을 Play Mode에서 검사한다.
`kubera_followup_lokapala_ui`와 `ui_overhaul`로 금력 실시간 갱신과 코드 드래그도 회귀 검증한다.

**추천 조합은 TAB에서 자료실 캐릭터 본문으로 옮겼다.** 아래 구성은 그대로다.
기획 원본은 [Detail_15](Detail_15_Party_Synergy.md)다.

| 순서 | 내용 |
| --- | --- |
| 1. 역할 | 역할군 ID를 한국어 이름으로 풀어 나열 |
| 2. 기여 | 전투 기여를 ●○ 눈금 5칸으로. 권장 열(전열/후열) 병기 |
| 3. 강점 | `provides[].text` 를 줄바꿈 되는 문단으로 |
| 4. 주의 | `caution`. 붉은색 |
| 5. 편성 | 이 캐릭터가 대표일 때의 고점·대체 두 벌을 아키타입 이름과 함께. 추천이 없으면 이 캐릭터를 부르는 대표 목록 |

**아직 손에 넣지 못한 이름은 흐리게 찍는다**(`SynergyCatalog.IsAvailable`).

**원소 반응**은 `ElementalReaction.AllReactions()`가 돌려주는 28쌍을 그대로 쓴다. 화면에 표를 다시
적지 않으므로 반응이 늘거나 이름이 바뀌면 자료실이 저절로 따라간다. 목록에는 반응 이름마다 한 항목이
서고(확산은 여섯 쌍이 한 항목), 맨 앞 `반응이란` 항목이 부착 · 세기 · 우선순위와 전체 표를 보여 준다.
기획 원본은 [Detail_16](Detail_16_Elements.md)다.
판정은 해금 여부 하나다(`CharacterSelectionManager.IsUnlocked`).
"지금 짤 수 있는 조합"과 "다 모으면 되는 조합"이 같은 화면에서 갈린다.
자료실 캐릭터 목록도 같은 판정으로 아직 못 얻은 캐릭터를 흐리게 `미해금`으로 찍는다 — 스포일러를 가리지는 않는다.

**데이터에 없는 문장은 '용어 › 기본 규칙' 여덟 항목뿐이다**(`WikiScreen.Rules`). 공식의 원본은
[Detail_02](Detail_02_Combat.md) · [Detail_03](Detail_03_Character.md)이며, 공식이 바뀌면 이 문장도 함께 고친다.

### 1.5-C 보상 코드 선택 흐름 · 공용 보급 사용

보상 · 상점 · 공용 보급이 같은 규칙 · 같은 문구를 쓰도록 판 두 개(`UnitTargetPicker` — 아군, `CodeChoicePicker` — 코드)를
`RewardCodeFlow`가 번갈아 연다. 흐름이 끝나거나 취소되면 호출한 화면의 원래 자리(보상 카드 · 매대 · 보급 목록)로 돌아간다.
선택 판은 Body 전체를 덮으므로 흐름 중에는 겹치는 줄(목록 · 요약 · 안내 · 닫기, 상점은 행상인 기둥까지)을 숨긴다.

| 흐름 | 진입 | 순서 |
| --- | --- | --- |
| 코드 받기 | 보상 화면 코드 카드 · 상점 코드 탭 | 받을 아군(각 아군에 `칸 n/7` · `▲ ○○ 대체` · 사유 미리보기) → 칸이 찼으면 버릴 코드 → 확정 |

**공용 보급 사용 규칙.** 비약 · 코드 도구 카드에는 "눌러서 사용"이 적히고, 준비 페이즈 밖에서는 "준비 중에 사용"으로 바뀐다
(눌러도 "준비 중에만 쓸 수 있습니다"). 결과나 막힌 사유는 목록을 다시 그려도 남도록 요약 줄 아래 안내 줄에 따로 적는다
(`InventoryScreen.Notify`). 올릴 코드 · 옮길 코드가 없으면 판을 열지 않고 안내 줄에 사유를 쓴다.
**선택 판 글자(2026-10-06).** 받을 아군 판(`UnitTargetPicker`)은 안내 24 · 이름 26 · 미리보기 22 · 돌아가기 22, 코드 판(`CodeChoicePicker`)은
안내 24 · 코드 이름 26 · 설명 22다. 버릴 코드 · 옮길 코드 선택지는 `Tn · 효과 요약`(두 줄, 넘치면 말줄임)을 싣고 선택지마다 효과 전문 · 태그 · 상위 툴팁
(`RewardCodeFlow.TooltipLines`, 파티 창 · 상점과 공용)을 붙여 지워질 코드와 받을 코드를 비교할 수 있다. 취소는 여전히 아무것도 바꾸지 않는다.

카드는 이름 · 효과 한두 줄(`ItemTooltip.EffectLine` — 아이템 데이터에 설명 문장이 없어 `tonic*` · 인장 최대 티어 · 두루마리 · 식량 필드에서 짓는다) ·
`×수량 · 사용 안내`다. 4열 격자를 세로로 굴리므로 열세 종 이상도 모두 닿는다. 비어 있으면 "전투 보상 · 적 처치 드랍 · 상점 '공용 보급' 탭에서 채운다"는
다음 행동을 안내한다. 화면 위 안내 줄은 "파티 전체가 함께 쓰는 보급품 · 비약은 전투당 1개 · 인장/두루마리는 준비 중"을 적는다.

목록은 `UIBuild.ScrollArea`라 진열 수와 상관없이 모두 닿는다(예전 고정 칸 매대는 회복 · 성장 11종 중 뒤쪽 물건에 손이 닿지 않았다).
값을 받는 순간은 하나다 — **대상(코드는 버릴 칸까지)을 다 고른 마지막 확정**. 그 순간 `ConfirmBlockReason`이
준비 페이즈(`CanOpenShop`) · 남은 구매 · 골드 · 대상 유효성(코드는 `CanReceiveRewardCode`와 버릴 코드 보유)을 다시 보고, 걸리면
`… 값을 치르지 않았습니다`를 띄우고 아무것도 바꾸지 않는다. 적용이 실패하면 값을 돌려준다. 취소(`매대로 돌아가기`)는 재고 · 골드 · 횟수를 건드리지 않는다.
매대의 막힌 이유(`BuyBlockReason`)는 `준비 중에만 구매` → `구매 한도` → `골드 부족` → `받을 아군 없음` / `되살릴 아군 없음` / `다친 아군 없음` 순이다.
선택 판이 열려 있는 동안 행상인 기둥과 매대를 함께 숨긴다. 대신 선택 판 안내 아래에 거래 요약
`가격 n G · 보유 n G · 남은 구매 n/2 · 고르면 그때 결제`를 싣는다(코드는 `RewardCodeFlow.Note`, 대상 약은 안내문 둘째 줄). 값은 여전히 마지막 확정의 재검사를 거친다.
가격 · 횟수 · 재고 규칙은 Detail_05 §5가 원본이다.

### 1.6 캐릭터 선택 화면

전체 화면형 편성 작업 공간이다. 좌측 약 40%는 **스탠딩 쇼케이스**와 역할·기술 설명,
우측 약 60%는 편성 안내와 **5열 초상화 로스터**를 배치한다.
카드는 120px 상한이나 세 줄 맞춤 없이 가용 폭을 채우며, 이후 후보는 세로 스크롤한다. 하단에는 대표를 구별한
**5인 파티 레일**과 큰 여정 시작 버튼을 고정한다. 추천 편성·시작 자격·기술 조회 규칙은 유지한다.

2026-09-21: 파티 레일을 108px로 줄이고, 메인 단계에서 비어 있던 추천 영역을 로스터에 돌려준다.

**2026-09-21 직접 검증:** 저장 격리 Play Mode에서 1920×1080·1440×1080의 메인/서포터 화면,
첫 행 선택 테두리, 세이의 네 태그·긴 소개, 기술/요약 전환과 창 너비 변경, 추천 네 명 편성,

**미리보기 설명 — 요약.** 전투 성향 태그 → 한 줄 소개(`10_units.yaml`의 `tagline`) → 원소 · 기초 공격 · 방어 · 체력 · 속도를 싣는다.
중복 운용 설명·입문 추천 문구/배지·스타터 등 편성 자격 문구는 표시하지 않는다. 미해금 캐릭터의 해금 조건만 남긴다.

**미리보기 설명 — 기술.** `기술 보기` 버튼(Q · 패드 Y)으로 전환한다. 초상화를 걷고 이름을 위로 올린 뒤,
남은 자리에 **고유 특성 · 일반행동 · 초월기**를 `20_codes.yaml` 설명과 꼬리표로 싣는다. 넘치면 칸 안에서 스크롤된다.
코드 조판은 자료실과 같은 `CodeText.AppendBlock`이다. 전환 상태는 커서를 옮겨도 유지된다 —
여러 캐릭터의 기술을 견줘 보는 용도다.

**키보드 · 패드 조작** (`UINavInput`, 입력은 `UIManager.Update` → `CharacterSelectScreen.Tick`)

| 동작 | 키보드 | 패드 |
| --- | --- | --- |
| 커서 이동 | WASD · 방향키 | 십자키 · 왼쪽 스틱 |
| 타일 고르기/해제 · 버튼 누르기 | Space · Enter | A (South) |
| 요약 ↔ 기술 | Q | Y (North) |
| 편성 비우기 | Backspace | B (East) |
| 여정 시작 | (버튼 줄에서 결정) | Start |

커서(흰 테두리)는 격자와 아래 버튼 줄을 오간다. 맨 아랫줄에서 더 내리면 버튼 줄의 `여정 시작`에
서고, 위로 올리면 격자로 돌아간다. 방향은 누르고 있으면 0.35초 뒤부터 반복된다. 마우스를 올린 타일로도
커서가 따라온다. **ESC는 쓰지 않는다** — 어느 화면에서든 인게임 메뉴가 받는다. 메뉴나 TAB 창이 떠 있으면
(`UIManager.IsOverlayOpen`) 입력을 읽지 않는다. 마우스로 누른 버튼이 EventSystem에 '선택'으로 남으면
Space·A가 그 버튼까지 눌러 두 번 처리되므로, 화면이 떠 있는 동안 선택을 매 프레임 비운다.

**추천 동료.** 편성 첫 자리(대표)가 정해지면 그 캐릭터의 추천 조합(`30_synergies.yaml` `recommendations`)으로
추천 동료 넷을 정한다. **고점 조합(`best`)에서 지금 격자에 오른 사람을 먼저** 담고, 빈자리는 대체 조합(`basic`)으로 채운다.
추천 타일에는 `★ 추천 N` 띠가 붙고, 요약 줄에 이름 · 조합명 · 이유의 첫 문장이 뜬다.
`★ 추천 동료 채우기`는 대표 뒤 네 자리를 추천 넷으로 통째로 바꾼다. 대표는 건드리지 않는다.

**흐름** — 게임 모드가 무한 모드 하나라 단계가 없다.

- 후보는 **해금한 캐릭터**와, 해금 조건이 적힌 미해금 캐릭터(회색 타일, 고를 수 없음)
- 타일을 누르면 편성에 더하고, 다시 누르면 뺀다. 첫 자리가 대표다
- 한 명이라도 고르면 `여정 시작`이 켜진다. `편성 비우기`는 편성이 있을 때만 보인다

### 1.8 전장 초상화 크기 정규화

초상화 원본 해상도가 제각각이다 — 아군 1254px, 적 512px, 일부 1024px.

드래그 미리보기도 같은 배율을 따른다.

### 1.9 전장 카메라 프레이밍

배치 상수를 바꿀 때마다 씬의 카메라를 손으로 옮기면 금방 어긋난다.
`GridManager.FrameCamera()`가 **실제로 만들어진 셀 좌표에서 경계를 구해** 그 중심에 카메라를 두고
`orthographicSize`를 잡는다. 전열/후열 간격이나 대기석 위치를 바꿔도 프레이밍이 따라온다.

**경계는 카드가 실제로 덮는 영역이다.** 칸 중심에서 위로 카드 반 변 + 궁극기 게이지(`UnitCardView.HudAbove`),
아래로 카드 반 변 + 패널의 실제 돌출분(`HudBelow`)까지 넣는다. 현행 패널은 카드 안 `y=100`에서 끝나 돌출분이 0이고, 보스 단독 편성은
가장 큰 카드 배율(`Cell.FeatureScale`)로 잰다. 가로로는 소환수 소형 카드가 걸치는 폭까지 넣는다.

**HUD는 픽셀로 비운다.** 예전에는 "전장 높이의 7% · 16%"처럼 전장에 비례해 여유를 줬는데, HUD는 전장과 무관한
고정 픽셀이라 인원이 늘어 전장이 커질수록 어긋났다 — 5대5에서 맨 아래 카드의 체력·상태 줄이 잘리고,
맨 위 적 카드가 상단 체력 띠 아래로 들어간 원인이다. 이제 아래 픽셀(1080p 기준)을 CanvasScaler와 같은 식
(`√(W/1920 × H/1080)`)으로 화면 비율로 바꿔 비우고, 남은 영역의 가운데에 전장을 둔다.

| 여유 | px | 이유 |
| --- | ---: | --- |
| `TopHudPixels` | 196 | 110px 통합 상단 HUD · 엘리트 체력 띠 |
| `BottomHudPixelsPreparation` | 208 | 준비 커맨드 바(18 + 176) + 14 |
| `BottomHudPixelsBattle` | 28 | 전투 중에는 가장자리 여백만 |
| `SideHudPixels` | 252 | 236px 피해 집계 레일 + 전장과의 16px 안전 간격 |

위 값에는 설정의 HUD 크기 배율이 곱해진다. 창 크기나 HUD 크기가 바뀌면 다시 맞춘다.

| 간격 | 값 | 이유 |
| --- | ---: | --- |
| `ColumnSpacing` | 13.2 | 덱 구성에서 카드(9.75)와 슬롯 사이를 또렷하게 나눈다 |
| `BattleColumnSpacing` | 9.9 | 빈 칸을 숨긴 구도에서 실제 카드 폭 가까이 두 열을 모은다 |

**기본 준비/전투에서는 빈 슬롯과 대기석을 숨기고 실제 배치된 유닛을 프레이밍한다.**
덱 구성 모드일 때만 전체 슬롯과 대기석을 펼친다. 전열이 비면 후열을 안쪽 표시 열로 당기며,
총 점유 카드 수가 1~3 / 4~5 / 6~7 / 8 이상일 때 카드 밀도 배율은 1.28 / 1.14 / 1.0 / 0.88이다.
사망·등장으로 경계가 달라지면 목표 프레임을 다시 계산하고 카메라가 unscaled time 기준 0.30~0.34초 동안 따라간다.
마지막 파괴의 `HoldCamera` 동안에는 목표를 갱신하지 않아 연출을 화면 밖으로 밀어내지 않는다.

> 🔸 **씬에 저장된 범위가 구조를 깨뜨릴 수 있다.**
> `CalculateFieldCellPosition`은 |x|=1을 전열, 그 외를 후열로 보므로 x가 ±2를 넘으면
> 여러 x가 같은 좌표로 계산되어 셀이 겹쳐 쌓인다. 실제로 씬에 구 레이아웃 값
> (`xMin -3 / xMax 3 / yMax 3 / benchSize 9`)이 남아 x=−3과 −2가 포개져 있었다.
> `EnforceLayoutBounds()`가 진영당 2열 × 4행, 대기석 5칸으로 바로잡고 경고를 남긴다.

## 1.10 공격 연출 — 카드 단위 모션

2026-09 개편으로 옛 연출(`AttackVisuals` · `MeleeVfx` · `CombatVfx` · `Effects/Projectiles` · `CharacterView`)을 모두 걷어내고
**카드가 직접 움직이는** 하스스톤식으로 다시 만들었다. 규칙 · 모듈 구성의 원본은 [Detail_02 §10](Detail_02_Combat.md)이다.

| 공격 | 화면 |
| --- | --- |
| **접촉** (`IsContact`) | 카드가 들리고 → 뒤로 젖혔다가 → 가속해 대상 카드로 **날아가 부딪힌다**. 부딪히는 프레임에 피해가 들어가고 충격 고리 · 파편(`ImpactFx.Slam`)이 터진 뒤 제자리로 돌아온다 |
| **비접촉** | 카드가 들썩이며 **카드 정중앙에서** 투사체가 떠나 대상 카드 정중앙에 꽂힌다(`ProjectileFx.Fly`, 호 궤적 + 꼬리) |
| **특성 · 초월기** | 카드가 떠올라 빛을 모은 뒤(`CardMotion.Channel`) 코드마다의 연출(`GeoFx` 등) |

기하·타이밍은 코드로 만들고, 질감이 중요한 판석·먼지·인장·보호막 원화는 `Resources/VfxTex/Gen/`에서 읽는다.
`VfxArt`는 `Resources.Load<Texture2D>` + 런타임 `Sprite.Create`를 사용하므로 Sprite 임포트 타입에 의존하지 않는다.
`VfxSpace`의 절차 스프라이트와 가산 재질(`Resources/Materials/CombatVfxAdditive`, Hovl `Add_CenterGlow` 셰이더),
`VfxParticles`의 SpriteRenderer 풀을 함께 쓴다. 기준점은 언제나 `Cell.CardCenter`다.
밝은 안 2에서는 가산 재질을 코어·좁은 광맥에만 쓰고, 먼지·외곽·접촉 그림자·투사체 받침은 기본 알파 재질을 쓴다.
`ProjectileStyle.BodyUnderlay`와 `RibbonAdditive`/`ShellAdditive`가 공허 화살 같은 밝은 투사체의 형태를 흰 배경에서 보존한다.
`VfxTiming`은 판정 시간을 바꾸지 않고 표시 수명만 보정한다. 8배속에서 단발 스프라이트·파티클은 최소 2프레임,
투사체 비행과 등장 낙하는 각각 최소 3프레임을 남겨 착탄 코어와 고유 실루엣이 통째로 건너뛰지 않게 한다.

**날아가는 카드는 모든 카드 위에 그린다**(정렬 +600). 애니메이션은 `UnitCardView.LateUpdate`에서 돌고,
`Tick`은 HUD만 갱신한다 — 셀 배치가 카드 위치를 덮어쓰지 않게 하기 위해서다.

**등장 · 파괴** — 전투 시작 때 `EntrySeal_SilverBlue_v2.png`의 은청색 바닥 인장과 단일 비가산 엣지 스윕 뒤에서 카드가 떨어져 착지 먼지와 약한 흔들림을 남긴다
(`PlayEntry`, 적은 0.15초 + 카드당 0.1초 간격). 얼굴을 가리던 빛기둥·수렴 마름모·4변 이중 외곽광은 쓰지 않는다.
쓰러지면 카드를 유령으로 떼어 판 · 창 · 초상 · 테두리 텍스처를 조각으로 잘라 흩뿌린다(`CardLifecycleFx`, `CardShatter`).
셀이 곧바로 비워져도 연출이 끊기지 않는다.

## 1.11 타격 피드백

전투가 자동으로 굴러가므로 **무엇이 얼마나 아팠는지**를 체력 바의 변화만으로 읽게 두면 놓친다.
피해가 정산된 자리(`Unit.DefaultTakeDamageEvent`)에서 `Effects.CombatFeedback`이 세 가지를 함께 친다.
하나만으로는 약하고, 셋이 같은 프레임에 겹쳐야 '맞았다'가 된다.

| 반응 | 내용 |
| --- | --- |
| **숫자** | 붕괴: 스타레일식(`DamagePopup`). 크게(1.75배) **찍혀 0.1초에 제 크기로 내려앉고**, 머물다 위로 떠오르며 마지막 3할에서 사라진다. **굵은 기울임체 + 어두운 외곽선**. 체력에 들어간 피해는 **원소색**, 방어막이 대신 받으면 방어막색, 회복은 `+N` 초록, 해로운 효과를 피하면 '회피', 고정 피해는 흰색, 치명타는 **금색 + 1.32배**. 같은 카드에 0.55초 안에 또 뜨면 위로 한 단씩(최대 4단) 올리고 좌우로 번갈아 벌려 겹치지 않는다 |
| **카드** | 하얗게 번쩍이며 뒤로 밀리고, **접촉 타격이면 떤다**(`UnitCardView.PlayHitReaction`). 비접촉은 떨지 않고 번쩍이기만 한다 |
| **화면** | 큰 한 방에만 아주 짧게 흔들린다(`CameraShake`) |
| **시간** | 치명타 · 궁극기 · 한 방이 큰 공격에서만 **30~50ms** 멈춘다(`HitStop`) |

**전투 자원은 카드 이름표에 붙는다**(`Combat.CombatResourceLabels`). 이름이 등록된 자원은 전부 띄우고
0이면 숨긴다 — 세이의 `창세의 결정`은 카드 위 자원 점으로 찍힌다. 이름이 없는 자원은 첫 하나만 `◆현재/최대`로 띄운다.

> 🔸 **숫자는 대상을 따라가고, 대상을 잃으면 화면 좌표에 못 박는다.**
> 생성 시점의 월드 좌표를 붙들고 있으면 허공에 숫자가 남는다 — 유닛이 쓰러지면 칸이 비고,
> 빈 칸이 지워지며 남은 카드가 가운데로 다시 모이고 카메라까지 다시 잡히기 때문이다.
> 실제로 전장 빈 자리에 433이 떠 있었다. 마지막 일격의 숫자를 지우지 않으려고
> **즉시 종료가 아니라 그때의 화면 좌표에 고정**하는 쪽을 택했다.

**멈춤(hit-stop)은 자격을 좁게 준다.** 잔매마다 서면 전투가 끊긴 것으로만 보인다.
치명타이거나, 궁극기이거나, 한 번에 최대 체력의 **55%** 이상을 깎았을 때만 선다.
멈춤 사이 최소 간격은 **0.12초**이고 길이는 **실시간**으로 재므로 8배속에서도 같은 길이다.
배속이 `Time.timeScale`이라(§1.2) 멈춤은 그 값을 기억했다가 되돌리며,
되돌릴 때 <b>우리가 넣어 둔 값이 그대로 남아 있을 때만</b> 손댄다.

**세기는 절대 피해량이 아니라 "최대 체력의 몇 할을 한 번에 잃었는가"로 잰다.** 같은 50이라도
레벨에 따라 뜻이 달라지기 때문이다. **22%**를 한 번에 깎으면 최대 세기가 되고, 숫자 크기도
같은 값을 따라 커진다. 지속피해는 때린 사람이 없으므로 떨림을 **35%**로 줄이고 화면은 흔들지 않는다.

**때리는 쪽도 움직인다.** 맞는 카드만 흔들리면 누가 쳤는지가 화면에서 사라진다 — §1.10의 돌진 · 들썩임이 그 몫이다.

> 🔸 **카메라 흔들림은 프레이밍과 싸우지 않는다.** 카메라 위치의 주인은 `GridManager.FrameCamera()`다.
> `CameraShake`는 매 프레임 **직전에 넣은 흔들림을 먼저 빼고** 기준 위치를 다시 읽으므로,
> 전투 중 빈 칸이 지워져 프레이밍이 다시 잡혀도 카메라가 옛 자리로 끌려가지 않는다.

## 1.12 전장 배경 — 테마 원화 + 밝은 크롬

`Effects.BattlefieldBackdrop`은 `80_stages.yaml`의 테마별 `backgroundKey`를 읽는다. 키는
`Resources/` 상대 경로이며 확장자를 쓰지 않는다. 값이 없거나 로드에 실패하면
`UI/Chrome/board_environment_bright_1672x941`(밝은 하늘 성채)로 폴백한다. 테마/배경 키가 바뀌면
이전 원화와 새 원화를 0.45초 동안 교차 전환하므로 라운드 경계에서 화면이 번쩍이지 않는다.

`ambientColor`는 배경 원화를 고르는 값이 아니다. 원화 위 공기 베일(4.5%)과 카드 영역 틴트(6%)에만
낮은 농도로 섞어 같은 장소의 시간대·원소 분위기를 미세 조정한다. 서로 다른 장소는 반드시
`backgroundKey`를 달리하고, 같은 원화의 색조 변형만 `ambientColor`로 표현한다.

| 겹 | 내용 |
| --- | --- |
| 환경 원화 | `backgroundKey` 원화를 화면 비율을 보존한 cover 방식으로 채운다. 중앙은 안전 면으로 비우고 좌우 크롭 여유를 둔다 |
| 바닥 패턴 | `board_floor_bright_1672x941.png`를 카드 영역에 7.5%만 얹어 넓은 원호와 약한 반사만 남긴다 |
| 테마 틴트 | `ambientColor`를 하늘 4.5%, 카드 영역 6%만 얹어 밝기와 재질을 보존한다 |
| 진영 분리 | `center_divider_bright_2172x724.png`를 세로로 돌려 x=0 축에 맞춘다. 은청색 선과 작은 중앙 접합만 남긴다 |
| 칸 각인 | `GridManager.FrameCamera`가 실제 카드 중심을 넘긴다. 청회색 접지 음영 + 저대비 원·마름모로 흰 원화의 발밑을 분리한다 |

### 배경 휘도 자동 보정

배경을 읽을 때 32×18 샘플의 선형 평균 휘도를 한 번 계산한다. 휘도 0.28~0.78 구간을 보정 곡선으로 삼아
밝아질수록 `UIBuild.ChromePanel`의 라이트 글라스 알파(0.88→0.97), `UIBuild.Glass`의 스모크 알파
(기본값에 +0.01→+0.13), 월드 TMP의 청흑 언더레이(0.16→0.52), 칸 접지 각인(0.82→1.45배)을 올린다.
배경 원화와 바닥만 조절하므로 카드·HUD 위에서 동작하는 `PushFocus`/`PulseFlash`/`ClearFocus`의 청흑 곱하기,
비네트, 국소 스포트 API와 시간 곡선은 유지된다.

### 새 배경 원화 규칙

- 평균 선형 휘도 권장 범위는 **0.18~0.75**다. 현재 기본 하늘 성채는 하네스 측정 0.732이며, 범위를 벗어나도 자동 보정은 동작하지만 암부 뭉침/백색 클리핑 검수가 필요하다.
- 화면 외곽 12%와 상단 15%는 저세부·저대비 여백으로 남긴다. 4:3과 21:9 cover 크롭을 모두 고려한다.
- 카드가 서는 중앙 55%에는 얼굴 크기의 고대비 문양, 광원 원반, 기둥 모서리, 수평 절단선을 두지 않는다.
- 크림색 바깥 배경, 흐린 갈색 테두리, 화면 중앙의 큰 금빛 덩어리, 순백/순흑 클리핑, 글자·로고는 금지한다.
- 추가 뒤에는 기본/궁극기 톤 다운 캡처에서 라이트 글라스, 카드 스모크, HP/피해 숫자, 흰 원화의 접지 그림자를 함께 확인한다.

> 🔸 **배경은 가장 아래 정렬 레이어에 둔다.** `sortingOrder`만 낮추면 카드가 다른 정렬 레이어를
> 쓸 때 배경이 카드를 덮는다. 카메라의 자식이라 프레이밍이 다시 잡혀도 따라온다.

은청색은 1px 구조선, 샴페인 금속은 작은 접합부에만 쓴다. 밝은 면의 버튼 아이콘과 진행 글리프는 짙은 단색이며 원소색은
카드 오브·HP·현재 VFX 밖으로 확장하지 않는다.

| 요소 | 규칙 | 코드 |
| --- | --- | --- |
| 면 | 둥근 모서리(반지름 = 예전 컷 크기, 3~16px) + 1px 헤어라인 + **위쪽 안쪽 1px 하이라이트**(불투명 면만) | `UIShapes.CutCorner` — 이름·인자는 그대로, `Corner.None`만 각진 사각형 |
| 층 | 한 층 위의 면(모달 · 캐릭터 창 · 설정 · 준비 바 · 툴팁)에만 부드러운 그림자. 전부에 깔면 층이 사라진다 | `UIShapes.SoftShadow` · `UIBuild.Elevate` |
| 장식 | 큰 레일은 절차형 라이트 글라스 한 장을 쓰고, 내부 행은 1px 구분선만 쓴다. 정사각 생성 9-슬라이스를 좁은 세로 레일에 쓰면 모서리 광이 합쳐져 타원으로 보이므로 사용하지 않는다 | `UIBuild.ChromePanel` |
| 등장 | 창이 열리면 0.16초 동안 배경이 어두워지고 면이 96.5% → 100%로 떠오른다(unscaledTime — 일시정지 중에도) | `UIPopIn` |
| 호버 | 버튼은 평소 94% 밝기 → 호버 100% → 누름 80%. 예전 호버 값(118%)은 정점 색 상한에 잘려 반응이 없었다. 카드처럼 Button이 아닌 누를 수 있는 면은 호버에 테두리가 떠오른다 | `UIBuild.Button` · `UIHoverRing` |
| 글자 위계 | 라틴 대문자 눈썹(자간 넓힘, 흐린 색) → 굵은 제목 → 흐린 설명 | `UIBuild.Label` |

**텍스트 대비 기준선은 4.5:1이다.** 가라앉은 면(`SurfaceSunken`) 위에서 실제 렌더링으로 다시 확인한다.

| 색 | 쓰임 | 성격 |
| --- | --- | --- |
| `TextOnLight` / `TextPrimary` | 이름·값 | 짙은 청회색 `#253443`. 밝은 면에서 가장 먼저 읽힌다 |
| `TextSecondary` | 본문·부연 | 청회색 `#536E80`. 진주색 면에서도 약 4.7:1을 유지한다 |
| `TextOnDark` | 스모크 글라스 | 냉백색 `#F8FCFF`. 원화 위 플로팅 띠 전용이다 |
| `TextDisabled` | 꺼진 버튼 글자 | `#253443` 62%. 형태와 굵기는 유지해 고장 난 빈칸처럼 보이지 않는다 |

밝은 바탕에서는 큰 백색 판을 여러 겹 겹치지 않는다. `FaintFill` · `SubtleFill` · `Track`의 하늘색
알파 토큰과 은청색 헤어라인으로 슬롯과 게이지를 나누며, 상태 설명 · 구매 불가 사유는 2560×1440과 1920×1080 실제
화면에서 읽히는지 함께 확인한다.

**타이포(1080p 기준)** — Display 38 · Title 27 · Heading 21 · Body 18 · Caption 15 · Micro 13.
**관리 화면 가독 크기(2026-10-06)** — ReadTitle 30 · ReadHeading 26 · ReadBody 24 · ReadSmall 22(`UITheme.FontRead*`).
기준 해상도의 반인 960×540에서는 Body 18이 9px로 그려져 파티 창 · 상점 · 공용 보급의 주요 글자를 22~26으로 올렸다(960에서 11~13px).
이 세 화면과 선택 판(`UnitTargetPicker` · `CodeChoicePicker`)만 다시 그린 뒤 `UIScaledText.KeepReadable(root)`를 불러, 그 안의 22 이상 글자에
하한 `UITheme.FontReadFloor`(20.9 × 글자 크기 배율, `UIScaledText.MinimumBaseSize`)를 건다 — 자리가 모자라면 줄이지 않고 말줄임 · 스크롤로 넘긴다.
**전역 규칙이 아니다.** 다른 화면(사건 화면의 24 · 26 글자 등)은 기본 하한(기준의 82%, FontFloor) 그대로다.
예전(34/24/19/16/13/11)보다 한 단계 크다. `UIBuild.Text`가 만드는 글자는 전부 **자동 맞춤**이다
(`UIScaledText`) — 최대는 기준 × 글자 크기 설정, 최소는 기준의 82%(하한 11). 관리 화면이 `KeepReadable`로 명시한 글자만 20.9 × 배율. 칸에 자리가 있으면 커지고,
좁은 칸에서는 예전 크기 근처까지만 줄어 넘치지 않는다. 설정에서 글자 크기(×1 · ×1.15 · ×1.3)를 바꾸면
숨어 있는 화면의 글자까지 즉시 다시 잰다. 캔버스 전체를 키우지 않는 이유 — 캐릭터 창처럼 기준 해상도로
칸 폭을 계산하는 화면이 있어, 캔버스를 키우면 칸이 화면 밖으로 밀린다.

**버튼 상태** — 켜진 보조 버튼은 백색 면 + 은청색 1px 헤어라인, 주 행동은 짙은 하늘색 면이다.
꺼진 버튼도 진주색 면과 헤어라인을 유지하고 글자만 `TextDisabled` 62%가 된다(`UIButtonStyle`).
화면 코드가 켜져 있는 동안 바꾼 면·글자색은 기억했다가 다시 켜질 때 돌려준다.

**스크롤 영역**(`UIBuild.ScrollArea`)에는 오른쪽 5px 스크롤 막대가 붙는다. 내용이 짧으면 숨는다.
안의 항목에는 **EventTrigger를 붙이지 않는다** — 휠 · 드래그까지 먹어 항목 위에서 목록이 굴러가지 않는다
(캐릭터 선택창의 초상화 위 휠이 이렇게 막혔다). `UIBuild.OnClick`과 호버는 클릭 · 진입만 받는
`UIPointerEvents`를 쓴다.

**포인터 종류는 `UIPointerKind`로 묻는다.** 새 입력 시스템의 UI 모듈은 마우스에도 양수 `pointerId`(장치 ID)를
준다. `pointerId >= 0`을 터치로 보던 예전 판정은 마우스를 터치로 읽어 TAB 창의 장비 끌기가 시작하자마자 끊겼고
마우스 호버 툴팁도 뜨지 않았다. 누르면 뜨는 떠 있는 카드(TAB 창 장비 상세)는 바깥을 누르면 닫힌다
(`UIDismissOnOutsideClick`).

**글라스 면** — 상단/좌우/하단의 큰 기능 레일은 `UIBuild.ChromePanel`의 백색 88% 면 + 2px 은청색 림
한 장을 쓰고 내부 행마다 프레임을 반복하지 않는다. 보스 체력 띠처럼 원화 위에 직접 뜨는
`UIBuild.Glass`만 `#26384A` 스모크 + 냉백색 글자를 쓴다. 전투 카드 하단 글라스는 원화 블러 사본을 쓰지 않는다.
밝은 바닥 위에서도 검은 형체가 비치지 않도록 진영 공통 `#26384A` 72% 스모크 한 면·1px 냉백색 림 72%·
0.45 높이 상단 스펙큘러 28%·아래쪽 그림자 10%만 쌓는다. 생성형 캡슐 굴절층과 바깥 키라인을 빼
내부 링이 겹치지 않게 한다.

**준비 바는 떠 있는 동안 0.25초마다 값을 다시 읽는다**(`PreparationScreen.Tick`). 스킬 Pt · 습득 가능 수를
바꾸는 경로(스킬 창 · 훈련 결과 · 보상 · 사건)가 여럿이라 각자 알리게 하지 않는다.

**빈 목록은 비워 두지 않는다.** 카드 자리가 통째로 비는 화면(스킬 힌트가 없는 스킬 화면 등)은
도형으로 그린 빈 상태 판과 **행동 유도 버튼**을 세운다. 버튼을 누를 수 없는 상황이면
버튼을 끄는 데서 그치지 않고 **왜 못 누르는지**를 함께 적는다 — 꺼진 버튼만 남기면 고장으로 읽힌다.

### 1.4 셀 UI 규칙

**카드 HUD는 8배속에서 읽혀야 한다.** 자동 전투라 플레이어가 할 수 있는 일은 보는 것뿐인데,
그 화면이 가장 빠를 때 읽히지 않으면 아무것도 읽히지 않는 것과 같다.

| 자리 | 규칙 |
| --- | --- |
| **궁극기 게이지** | main의 카드 우상단 앵커·피벗·돌출2단위를 유지하며 원을30 × 30으로 확대(100단위 카드 기준). 별도 전면 HUD 캔버스에서 원화가 가리지 않는다. 스타레일 참고: 회색 원 안이 캐릭터 고유 원소색으로 아래부터 차며, 미니멀 고딕 원소 아이콘과 얇은 외곽으로 상태를 읽는다. 퍼센트 글자는 없다. 완충 시 원소색 외곽과 낮은 호흡광 |
| **고유 자원 표기** | 유닛별 HUD 표시 자원을 명시한다(세이=`SeiBigBang.ResourceId`). 현재값이 1 이상일 때만 오브 윗링 안쪽 9.2 × 7.2 받침에 한 자리 숫자를 각인한다. 0이면 받침까지 숨긴다 |
| **하단 글라스** | `x=2.5..97.5`, `y=72.5..100`의 95 × 27.5 A안 글라스 한 장이다. 상태가 없으면 `y=91.2`까지 18.7 높이로 접고, 상태가 생겨도 상단과 이름·HP 좌표는 움직이지 않는다. 원화별로 한 번 만든 런타임 사본의 하단 30% 알파를 감쇠한다. 좌·우·하단 어느 변이든 불투명 영역이 경계에 최소 24px 연속으로 닿으면 해당 변 전체를 폭/높이 7%에서 녹이고, 짧은 발·꼬리는 보존한다. BC7 입력의 1~16/255 알파 잡음은 런타임 사본에서 제거한 뒤 1px 침식 + 반 픽셀 평활을 적용한다. 1행 이름+`현재 / 최대`, 2행 HP/보호막, 선택적 3행 상태를 넣고 행동 게이지는 높이 0.7 무채색 보조선으로 둔다 |
| **상태 아이콘** | 일반 LOD는 7.5 최대 6칸이다. 화면상 카드 폭 260px 미만은 8.6~9.8로 키우고 300px 이상에서 일반으로 복귀한다. 소형은 상위 3개와 네 번째 `›`만 남긴다. 글리프는 `status_glyph_atlas.png`의 `#F7FBFF` 단색이고 이로움=원, 해로움=마름모, 행동 불가=이중 마름모 받침이다. 받침은 `#172534` 10% 채움 + 냉백색 42% 윤곽이며, 우상단 ↑/↓와 우하단 `#132033` 원+흰 중첩 숫자를 쓴다 |
| **이름·HP** | 흰 이름 띠와 초록 세로 바를 만들지 않는다. 글라스 첫 행 왼쪽은 이름, 오른쪽은 `현재 / 최대` HP로 고정한다. 큰 카드에서도 정보판은 슬롯 폭 98% 기준 안으로 균일 축소하고 글자도 함께 줄인다. 돌진 중 이동·크기는 따라가되 회전은 상쇄해 수평을 지킨다 |
| **체력 바** | 글라스 안 `y=84.4..85.95`의 1.55 높이다. 아군은 청록, 적은 적색이며 보호막은 최대 체력 대비 길이의 얇은 금색 선으로 윗면에 겹친다. 소형 LOD는 이름·HP를 숨기지 않고 화면 폭 보정 최대 1.14배로 최소 픽셀 크기를 지킨다 |
| **호버** | 카드에 마우스를 올리면 **원소 · 전투 성향 · 주/부 스탯 · 한 줄 소개**(`UnitInfoText`)로 누구인지 먼저 소개하고, 그 아래 상태를 **이름 · 중첩 · 남은 턴 · 설명**으로 풀어 적는다. 체력은 적지 않는다. 아이콘은 모여 있으므로 무엇이 모였는지는 여기서 본다 |
| **상태 색** | 전부 냉백색. 성격은 낮은 알파의 `#172534` 받침과 얇은 원/마름모/이중 마름모 윤곽, ↑/↓로만 구분한다 |

> 중첩은 같은 상태를 여러 개 들고 있는 것으로 구현돼 있어(`StatusStackPolicy.Stack`),
> 목록을 그대로 늘어놓으면 화상 5중첩 하나가 다섯 칸을 전부 먹었다.

> 행동 불가는 이중 마름모 받침으로 먼저 튀어나온다. 상태 의미를 색에 맡기지 않아 색각과
> 원화 팔레트가 달라도 같은 속도로 읽힌다.

중첩 수 글자는 `StatusIcons.StackDigit`이 생성 아틀라스의 탭형 숫자를 고른다. TextMeshPro를 쓰지 않는
이유는 이 캔버스가 월드 스페이스라서다 — `TextMeshProUGUI`는 여기서 아예 그려지지 않고(§1.2의
카드 이름표가 겪은 문제), 카드마다 월드 텍스트를 몇 개씩 세우는 것은 두 자리 숫자 하나에 과하다.

| 규칙 | 내용 |
| --- | --- |
| 책임 분리 | `Unit.cs`는 게임 로직, `Cell.cs`는 UI 표시 |
| 필드 전용 | 대기석 유닛은 UI를 표시하지 않는다 |
| HP 바 | 체력 100% = scale 9, 위치 이동으로 감소 표현 |
| **z값 통일** | 모든 바의 z = 0 |
| 깊이 제어 | z축이 아닌 정렬 순서를 사용한다. 카드 내부는 **배경 < 오브 캔버스 < 원화 `SpriteRenderer` < 원화형 피격광 < 하단 HUD 캔버스·글자**다. 카드 크기의 컷코너 프레임과 피격 사각 보조면은 만들지 않는다 |
| 런타임 재조립 | Play 중 도메인 리로드 뒤 코드 생성 HUD 배열이 비어 있으면 `UnitCardView`가 몸체·원화는 보존하고 HUD 구획만 다시 만든다. 캔버스 존재만으로 완성을 판정하지 않는다 |

```csharp
// HP 바 스케일 계산
float targetScale = hpRatio * 9.0f;
float xOffset = (9.0f - targetScale) * -0.5f;

// 렌더 순서
currHpRenderer.sortingOrder = maxHpRenderer.sortingOrder + 1;
```

> **교훈** — 2D에서는 z축 위치보다 `sortingOrder`가 안정적이다.
> 과거 HP 바에 임의 z값(-0.1f)을 쓴 결과, 드래그 앤 드롭의 z 좌표계와 충돌해 위치가 왜곡됐다.

## 1.13 엘리트·보스 단독 연출

**판정이 둘이다.** 상단 체력 띠와 카드 확대는 조건이 다르다. 띠는 화면 위쪽의 빈 자리를 쓰지만
커진 카드는 옆 칸을 침범하므로, 잡졸이 함께 선 판에서 카드를 키우면 서로 가린다.

| | 상단 체력 띠 | 카드 확대 |
| --- | --- | --- |
| 판정 | `FeatureEnemies.BannerTargets()` | `FeatureEnemies.SoloStageTargets()` |
| 조건 | **엘리트가 하나라도 있으면** | 살아 있는 적이 1~2기이고 **전원이** 엘리트·보스 |
| 인원 | 최대 2 (`MaxCount`). 셋 이상이면 보스 먼저, 그다음 최대 체력 순 | 1~2 |
| 효과 | 상단 중앙에 이름·체력·상태 | `Cell.FeatureCardScale` = **1.5배** |
| 적용 시점 | 매 프레임 (`BattleHud.Update`) | 편성 배치 직후 (`RoundManager.ApplyFeaturePresentation`) |

호위를 달고 나오는 중간 보스는 **띠는 뜨지만 카드는 그대로**다. 라그나르가 광전사 둘과
볼바 둘을 데리고 서는 4슬롯이 그 경우다.

**배율은 칸에 붙어 있으므로 편성을 깔 때마다 먼저 모든 칸을 1배로 되돌린다**(`GridManager.ResetFeatureScales`).
예전에는 되돌리지 않아, 엘리트 단독 판을 한 번 치른 칸이 이후 그 자리에 서는 잡졸까지 크게 그렸다
(메히코의 독수리 전사 하나만 커지고, 판이 지날수록 커진 칸이 늘었다).

**카드 확대는 칸 안에서 일어난다.** `Cell.SetFeatureScale`이 카드와 초상화에 같은 배율을 먹인다.
초상화는 카드와 별개의 렌더러라 배율을 직접 다시 먹여야 하므로, 스케일을 바꾸면
`SetPortrait`를 다시 태운다. 옆 칸이 비어 있을 때만 켜지므로 커진 카드가 다른 유닛을 가리지 않는다.

### 상단 중앙 체력 띠 (`FeatureEnemyBanner`)

자원 표시줄 아래에 붙는다. 한 명이면 폭 560을 다 쓰고, 둘이면 가운데 틈을 두고 반씩 나눈다.
칸 하나에 이름과 체력 바, 현재/최대 수치, 상태 아이콘 여섯 개까지 들어간다.

카드 위의 작은 바는 **잡졸 다섯을 한눈에 훑기 위한 것**이라, 한 마리를 오래 때리는 판에서는
정보가 너무 멀리 있다. 2인조에서 좌우로 나누면 둘 중 누구를 먼저 깎고 있는지가
화면 한가운데에서 읽힌다. 방어막은 체력 바 위에 겹쳐 그려 껍질이 남았는지를 함께 보여 준다.

### 4.2 유닛 저장 (`UnitSaveData`)

`unitId`, `currentHP`, `xPos` / `yPos` / `isBench`, `ultimateResource`, `level` / `exp`, **`activeRewardCodeSlots`**(v13 — 빈 칸 0을 포함한 활성 7칸), **`storedRewardCodeIds`**(v13 — 개인 보관 순서), **`grantedPassiveCodeIds`**(v12 — 보상 코드와 사건 패시브의 ID, **칸 순서 그대로**), **`permanentStacks`**(v12 — 영구 중첩 목록 `PermanentStackSaveData { key, value, fraction }`, 소수 몫까지)

(v11에서 `equippedItemIds` · `carriedItemIds`는 장비 폐지와 함께 사라졌다.) 전투 시작 스냅샷 · 전투 종료 덮어쓰기 · 런 저장이 모두
`Unit.WriteRunState` / `RestoreRunState` 한 쌍을 쓴다 — 세 경로가 따로 적으면 하나를 빠뜨려 보상 코드나 영혼이 라운드마다 사라진다.

### 4.3 영구 저장 (`TrainedCharacterCollection`)

계정 해금 기록만 남았다 — `unlocked` / `pending` 두 목록. 키는 `NTL_UnlockedCharacters_v9`, 보스 처치 기록은 `NTL_BossDefeated_v9_`.

### 4.4 저장/삭제 시점

| 시점 | 동작 |
| --- | --- |
| 스테이지 전진 | `SaveCurrentRun()` |
| 전투 시작 직전 | `SaveCurrentRun()` |
| 사건 발생 기록 | `MarkEventTriggered()` → 즉시 저장 |
| 앱 일시정지 / 종료 | `OnApplicationPause` / `OnApplicationQuit` — `CanSaveNow`일 때만 |
| 인게임 메뉴 `저장` · `저장하고 메인 메뉴로` | `SaveCurrentRun()` — `CanSaveNow`일 때만(아니면 버튼이 꺼진다) |
| 런 시작 | `SaveSystem.DeleteSave()` — 기존 진행 폐기 |
| 게임 오버 / 런 완료 | `SaveSystem.DeleteSave()` |

**`RunManager.CanSaveNow`** — 준비 · 사건 페이즈에서만 참이다. 전투 중에 저장하면 쓰러진 아군이
`BuildHeroSaveData`에서 빠지고, 보상 선택 중에 저장하면 경험치를 받은 채 같은 전투로 되돌아가며,
캐릭터 선택 중에는 파티가 비어 있다. 그때는 전투 직전 자동 저장을 그대로 두고 덮어쓰지 않는다.

인게임 메뉴의 `불러오기`는 `GameStartIntent.Continue`로 Game 씬을 다시 연다. `저장 없이 메인 메뉴로`와 `게임 종료`는
저장하지 않는다 — 마지막 저장 이후의 진행을 버리는 출구이고, 메인 메뉴의 이어하기로 그 시점부터 잇는다(§1.5-A).

### 4.5 복원 순서

```
LoadSavedRun()
  1. 모드/생명력/킬 수 복원
  2. 인벤토리 복원 (토큰, 골드, 티켓, 아이템)
  3. 우정도 / 사건 이력 복원
  4. RoundManager.InitializeStage(stage)
  5. 기존 아군 전부 비활성화 → 저장된 아군 스폰 → RestoreRunState()
     (레벨 · EXP → 보상 코드를 칸 순서대로 다시 붙임 → 영구 중첩 → 스탯 재계산 → 그 뒤에 현재 체력을 최대 체력으로 자름)
  6. RoundManager.LoadRound(stage)
  7. UI 갱신 → EnterNextStageAfterLoad() → 준비 행동 상태 복원 → 써 둔 전투 비약 예약 복원(RestorePendingTonic)
```

**구버전 세이브는 로드 시 폐기된다** (`RunSaveData.version`).

`SpriteResource`가 위 네 분류 폴더를 먼저 뒤지고 이전 평면 루트를 마지막으로 본다. 따라서 YAML과
코드에는 분류 경로를 넣지 않고 기존 스프라이트 키를 그대로 유지한다. 아군·적이 같은 원화를 공유하는
경우에는 파일을 `Allies`에 한 번만 두고 양쪽에서 같은 키로 불러온다.

> **초상화·스탠딩은 `Resources.Load`를 직접 부르지 않는다. 반드시 `SpriteResource`를 거친다.**
> 데이터가 들고 있는 것은 키(`SEI_PORTRAIT`)이고 실제 파일은 분류 폴더 안에 있어서, 키를 그대로
> `Resources.Load`에 넘기면 **조용히 null이 돌아온다.** 분류 폴더로 옮기던 날 소환수 카드·행동
> 대기열·도감·육성 화면이 한꺼번에 빈 칸이 된 것이 이 때문이다.
> `SpriteResource`는 키와 해석이 끝난 전체 경로를 모두 받으므로 진입점을 하나로 둘 수 있다.
>
> `Unit.PortraitPath`는 **해석에 성공하면 전체 경로, 실패하면 키 그대로**를 담는다. 어느 쪽이든
> 그대로 `SpriteResource.LoadPortrait`에 넘기면 된다.
>
> 아이템 아이콘(`Sprite/Items/`)만은 분류가 없는 평면 폴더라 직접 로드해도 된다.

## 6. 사운드 규약

### 6.1 논리 큐와 파일

호출부는 파일명이 아니라 `sei.ground.hit`, `common.death`, `ui.confirm` 같은 **논리 큐 이름**만 안다.
`Resources/Data/95_sfx_cues.yaml`이 큐를 `Resources/Audio/Sfx/` 아래 클립 후보에 연결한다.
후보가 여럿이면 매번 하나를 무작위로 고른다. 큐 레코드는 다음 값을 가진다.

| 필드 | 의미 |
| --- | --- |
| `clips` | Resources 상대 후보 목록. 확장자는 쓰지 않는다 |
| `volumeMin/Max`, `pitchMin/Max` | 재생마다 고르는 음량·피치 범위 |
| `mixerGroup` | `SFX` · `UI` · `Voice`. 실제 AudioMixer 에셋 전까지 코드 버스 게인을 쓴다 |
| `maxVoices` | 같은 큐가 동시에 날 수 있는 수 |
| `minInterval` | 같은 큐를 실제 시간 기준으로 합치는 최소 간격 |
| `speedMerge` | 4×·8×처럼 행동이 몰릴 때 전역 하한까지 간격을 넓힐지 |
| `duckBgm`, `duckSeconds` | 궁극기 등에서 BGM을 잠깐 낮추는 배율·실제 시간 |

`AudioManager`는 18개의 2D `AudioSource`를 풀링한다. SFX는 `Time.timeScale`을 따라 피치를 올리지 않으며,
히트스톱(`timeScale = 0`)에서도 재생은 이어진다. 재발 간격은 `Time.realtimeSinceStartup`으로 재므로
8×에서 한 프레임에 몰린 다단 히트는 HUD의 사용자 배속을 기준으로 `interval_merge`로 합쳐진다. 궁극기 Cast 큐는 BGM을 약 70~74%로
낮췄다가 실제 시간으로 복구한다. Music/Sfx의 최종 게인은 `SettingsManager` 설정을 마지막에 곱한다.

UI 큐는 Kenney `Interface Sounds 1.0`(CC0)의 짧은 클립만 `Audio/Sfx/Kenney/Interface/`에 둔다.
`UIBuild.Button` · `UIBuild.OnClick`이 기본 `ui.click`을 내고, 확인/취소 · 보상 선택 · 전투 시작/승패는
각각 `ui.confirm`/`ui.cancel` · `ui.reward.select` · `ui.battle.*`의 의미 피드백을 덧붙인다.

### 6.2 누락과 검증

클립 후보가 비었거나 Resources에서 찾지 못해도 전투·UI 흐름은 계속된다. 에디터/개발 빌드만 같은 큐에
한 번 경고하고 출시 빌드는 조용히 넘긴다. 이 정책 때문에 등장·퇴장 같은 공용 전투 큐를 데이터에 먼저 세우고
무료 팩을 나중에 채울 수 있다.

검증 하네스의 `result.json.sfxEvents`는 `scenario`, 실제 시각, 큐, 선택 클립, 믹서 그룹, 음량, 피치,
배속과 `played`/생략 사유(`no_candidates`, `clip_missing`, `interval_merge`, `concurrent_limit`, `pool_full`,
`muted`)를 남긴다. `visualEvents`에는 같은 실행의 연출 태그와 프레임을 기록하므로 소리를 들을 수 없는
자동 검증에서도 시전·발도·투사체·타격·화면 단계의 호출 차이를 프레임 단위로 대조한다. 기본 검수는
세이·시·찬드라·히미코·피그말리온 5명 대 적 4명으로 일반·특성·초월기·찬드라 특수행동, 적 공격,
등장·퇴장, UI·보상·결과 화면과 8× 연발을 한 Play 세션에서 돈다.

2026-10-01 전수 검수 기준 데이터에는 논리 큐 70개와 읽을 수 있는 고유 OGG 61개가 있다. 모든 큐를
실제 요청했고 후보가 있는 62개 큐는 전부 `played`를 확인했다. 파일 누락·디코드 실패·클리핑·긴 무음 꼬리·
`pool_full`은 0건이었다. 후보가 비어 `no_candidates`만 남는 공용 큐는 `common.hit.contact`,
`common.death`, `common.entry`, `common.shield`, `common.status.positive`, `common.status.negative`,
`common.ultimate.ready`, `common.crit` 여덟 개다. 이는 음원 미수령 상태를 드러내기 위해 빈 큐로 유지한다.

연출과 SFX 단계는 다음처럼 맞춘다.

- 시의 멸참은 적 방향 검격에 `cast`/`draw`, 검붉은 3갈래 할퀴기의 단일 판정 프레임에 `hit`을 낸다.
  3/6/9타 만종은 새 시전 큐 없이 멸참 피격 종료 직후 `screen`/`hit`만 내며, 3타는 같은 대상,
  6·9타는 받는 적 원화 행마다 시각 연기를 나누어 재생하되 논리 정점과 적별 피해는 한 번씩만 낸다(2026-10-09 보정).
- 히미코 일반행동은 시전에 `cast`, 0.05초 간격의 화염탄 여섯 발에 `projectile`, 셋째 탄 착탄 정점의
  단일 판정에 `hit`을 낸다. 피그말리온은 화염 발도에 `cast`/`draw`, 0.28초 한 획의 중심 통과
  0.10초 단일 판정에 `hit`을 낸다.
- 찬드라의 샤친은 6발 발사마다 `projectile`, 공용 파쇄 착탄에 `hit`을 낸다. `maxVoices: 3`으로
  연발의 절반을 살리고 나머지는 `concurrent_limit`으로 합친다.
- 소마/창야는 축복 강림에 `cast`, 파장 시작에 `screen`, 절제된 적중 파쇄에 `hit`을 낸다.
- 공허 사수·공허룡의 반전 6연발은 `cast` 뒤 탄마다 `projectile`, 셋째 탄 착탄의 단일 판정에
  `hit`을 낸다. 공허 늑대 할퀴기는 후퇴 준비에 `cast`, 실제 세 줄이 그어질 때 `draw`, 가운데 선두의
  단일 판정에 `hit`을 낸다. 세 큐는 모두 `Hyacine ... no voice` 절단본이라 사람 목소리가 없다.
- 히미코·피그말리온 초월기의 `hit`은 시전 직후가 아니라 각각 0.14초/0.15초 뒤 화면 문양 정점에 낸다.
  뒤 대기를 줄여 전체 연출·판정 시간 0.36초/0.38초는 바꾸지 않는다.
- 8× 세이 6연발은 첫 투사체음만 재생하고 나머지는 `interval_merge`로 묶인다. 피해 횟수와 판정 프레임은
  오디오 병합과 무관하게 그대로 유지한다.

### 6.3 현행 임시 키트 매핑

출시 전 교체할 개발용 HSR SFX 키트에서 전체 믹스를 에너지 온셋으로 나누고 앞뒤 무음·14ms 페이드·
유효 RMS 정규화를 적용한다. 원본 WAV 전체는 저장소에 두지 않고 실제로 쓰는 스테레오 44.1kHz OGG만 넣는다.
아군은 캐릭터마다 여성 HSR 캐릭터 한 명을 고정한다. 대사가 섞인 `cast`만 `Voice` 버스로 보내고,

적은 이름에 `no voice`가 명시된 원본 구간만 써 사람 목소리를 넣지 않는다.

`ActionQueuePanel`은 `ActionScheduler.ForecastOrderCached`의 읽기 전용 결과를 사용한다. 예약·참가 유닛·AV·턴 수·추월 몫·속도·활성/소환 여부·일반행동 이름이 같으면 예측을 재사용한다. 입력 변경은 즉시 다시 계산하고 라운드 종료 시 참조를 걷는다. 기존 `ForecastOrder`는 독립 사본을 반환하는 API로 유지한다. `core_forecast_safety`의 1·4배속 및 `ui_overhaul`을 실제 Unity에서 통과했다.
