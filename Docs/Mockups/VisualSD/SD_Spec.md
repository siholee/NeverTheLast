# SD 캐릭터 규격·검수 조건

최종 갱신: **2026-11-05**. SD 3~6차 지시서(`SD_Pose_v3~v6_Brief.md`)와 Root 검수 기록(`Logs/SDPoseV*_*/root_review_pm.md`)의 기준 및 사용자 확정 적 제작 예외를 모은 문서다. 회차별 지시서와 충돌하면 이 문서가 우선한다.

역할: 사용자 지시 → **Codex가 이 문서대로 제작·등록·검증** → **Root(Claude)가 최종 검수**(§8). Codex의 자체 PASS는 최종 승인이 아니다.

## 1. 작업 전 필수: 키트 먼저

포즈를 정하기 전에 반드시 읽는다.

- `Assets/Docs/Design/Characters/{id}.md`
- `Assets/Resources/Data/20_codes.yaml`의 해당 코드(N·SP·U·P)

각 행동마다 **대상**(적 단일/전체·아군·자신), **접촉/비접촉**, **종류**(베기·찌르기·타격·사격·주문·치유·보호막·버프·소환)를 한 줄씩 적는다.

| 규칙 | 내용 |
| --- | --- |
| WINDUP·STRIKE 기준 | 게임은 모든 행동에 같은 WINDUP→STRIKE를 쓴다. **가장 자주 하는 행동(보통 일반행동 N)**에 맞춘다 |
| 공격 없는 일반행동 | 치유·보호막·버프·도발·자원 축적이면 **공격 자세 금지**. 축복·손짓·소품 동작으로 만든다(예: 토트·이시스·만사 무사·셰익스피어·아스톨포) |
| 콘셉트와 키트 충돌 | 사용자 콘셉트와 키트가 어긋나면 **키트를 따르고 보고서에 차이를 적는다**. 사용자가 콘셉트를 택하면 둘을 함께 만족하는 해석을 찾는다(예: 아그니 "불을 다루는 법사" + 접촉 일반행동 → 손바닥 장법) |
| 무기·소품 추가 | 원화에 무기가 없으면 키트 행동에 맞는 소품을 더해도 된다. 추가했으면 보고서에 적는다 |
| 기존 SD와 구분 | 같은 계열(사격·손짓 주문·베기 등)의 기존 SD와 **무기 모양·자세·실루엣이 겹치지 않게** 한다(§6 참조표) |

## 2. 이미지 규격

- 아군 등신 목표 2.68(합격 2.60~2.76)

| 항목 | 값 |
| --- | --- |
| 파일 | `{ID}_SD_{IDLE\|WINDUP\|STRIKE\|HIT\|DOWN}.png`, 1024×1280, 8bit RGBA, 네 모서리 alpha 0 |
| 등신 | 약 2.5등신(허용 2.3~2.8). 2.9 이상은 HOLD 사유 |
| 발 기준선 | **5장 모두 alpha≥129 최하단 y = 1220**(DOWN 포함). 무기 끝·옷자락이 1220 아래로 내려가면 안 된다. 맞출 때는 이미지 전체를 **정수 픽셀 이동**(LockBits 행 복사)만 한다. 재샘플링 금지 |
| 가로 범위 | alpha≥129 x 범위가 30..994 안 |
| 머리 크기 | 두개부 ROI(귀·장발·모자·후드·장식 제외)의 **√(폭×높이)**가 같은 캐릭터 IDLE 대비 **±3%**. 폭 하나만으로 판정하지 않는다 |
| 방향 | 아군 5장은 **오른쪽**, 적 5장은 **왼쪽**을 향한다. 카메라 응시 금지. 얼굴이 드러나는 캐릭터는 원화가 눈을 감았어도 반쯤 뜬 눈으로 바꾼다. 로마 군단 일반병의 눈 차폐는 아래 예외를 따른다 |
| 화풍 | 균일한 진한 남색 먹선 + 부드러운 회화 명암 + 따뜻한 저채도. 원소색 포인트는 실루엣 안 1~2곳(발광 없음). 장식·명암 밀도는 3~6차 승인본과 같게(너무 단순하면 HOLD) |
| 원화 일치 | 얼굴·머리색·눈색·핵심 의상·원소색은 `Standings/Allies/{ID}_STANDING.png`·`Portraits/Allies/{ID}_PORTRAIT.png`를 따른다. 원화 자세를 그대로 베끼지 않는다 |
| 금지 | 배경·그림자·VFX(빛·불꽃·궤적·마법진·참격·총구 화염)·**글자**(라틴·한자·한글·상형문자·국기 포함. 부적·책·악보·문장 무늬도 글자로 읽히면 안 된다)·**흰 외곽 번짐**(머리 바깥 흰 스티커 테두리)·곱슬 과다·유치한 벡터풍 |
| 생성 | 내장 image_gen(transparent background). IDLE을 먼저 확정하고 그 IDLE을 참조로 나머지 4장을 만든다. 포즈당 자체 검수 후 최대 2회 재생성 |
| 프롬프트 | 게임·작품·신화/실존 인물·캐릭터 이름을 쓰지 않고 시각 특징만 쓴다 |

### 적의 방향·익명 모브 예외(사용자 확정 · 2026-11-04)

- 적은 전투 상대인 화면 왼쪽을 향한다. 좌향 원본의 등록 방향과 SD 리그의 반전·접점 앵커가 일치해야 한다.
- 로마 군단 테마의 일반 등급 병과는 익명 모브다. 5포즈 모두 투구 안 눈 영역을 짙은 불투명 음영으로 완전히 가리고, 흰자·눈동자·눈꺼풀 선·발광 눈을 표시하지 않는다. 닫힌 눈을 그리는 것도 차폐를 대신하지 않는다.
- 같은 군단병의 중복 등장과 병과 사이 닮은 기본 형태를 허용한다. 익명 군단병끼리는 고유 인물 같은 얼굴이나 과도한 실루엣 차별화를 강제하지 않는다. 같은 캐릭터의 행동·피격·사망 포즈 구분은 유지한다.
- 이름 있는 지휘관·보스와 콜로세움 검투사는 익명화 대상에서 제외한다. 적 원화는 `60_enemies.yaml`의 실제 portrait/standing 키와 해석된 Resources 경로를 기준으로 삼는다.

### 흰 외곽 후처리(재생성보다 우선)

머리 바깥 흰 테두리가 남으면 다시 그리지 말고, 알파 경계 안쪽 6px 이내에서 **휘도 >185이고 채도 <0.18인 픽셀만 alpha 0**으로 지운다. 얼굴·옷·소품 내부는 건드리지 않는다. 처리 전/후 2배 확대 비교 시트를 남긴다.

## 3. 포즈 정의

| 포즈 | 표시 시간 | 내용 |
| --- | --- | --- |
| IDLE | 상시 | 기본 대기. 무기·소품을 든 그 캐릭터다운 자세 |
| WINDUP | 약 0.14초 | 행동 준비. **단색 실루엣으로 IDLE과 구분**되어야 한다(차이가 작으면 메모, 거의 같으면 HOLD) |
| STRIKE | 행동 정점 | 행동이 일어나는 순간. 무기·손이 적 쪽으로 뻗는다. 궤적·빛 없이 형태로만 |
| HIT | 약 0.42초 | 피격 반동. 뒤로 젖힘·움찔·막기. 머리 크기 ±3% 유지 |
| DOWN | 실제 사망 | 무릎·주저앉음·엎드림. 무너지는 형태로 |

- 시만 `sd.downFade: true`: DOWN 진입부터 0.6초 동안 알파 1→0.35, 이후 유지. 부활·전투 재시작 때 1로 복구하며 사망 판정·공통 퇴장 완료 시점은 유지한다. 🔸 검증 필요(2026-11-05): 다음 등록 회차 실제 Play에서 곡선·복구 확인.

- 전투 크기(몸 높이 약 250px)와 단색 실루엣에서 5장이 서로 구분되어야 한다. 등록 아군은 선택 `sd.crownY`(귀·모자·후드 여분·아호게·무기를 제외한 두개부 윗선)가 있으면 발~정수리로 표시 크기를 맞춘다: `height × 0.96299463 / (feetY − crownY)`. K는 호루스 제외 42명 IDLE 실루엣 표시 높이 중앙값을 보존한다(2026-11-05). 생략한 적·소환수·호루스는 기존 topY 기준이며, topY는 HeadBounds·HP바·가림 판정에 유지한다.
- 같은 캐릭터 5장은 의상·얼굴·무기·원소색 위치가 같다(장식 세부의 미세한 차이는 메모).

### 초월자 톤(세이·시·츠쿠요미만)

과장 없이 정숙·우아·절도 있게. 작고 정확한 한 동작, 머리카락·소매가 크게 휘날리지 않음, 차분한 표정, 팔로 얼굴을 가리지 않는 절제된 HIT, 단정하게 앉는 DOWN. 시는 칼집에 손 → 낮은 발도 준비 → 한 번 베고 정지(돌진·도약 없음).

### 4.2 게임 배치(현재 확정값, 1920×1080 기준 px × 주인 깊이 배율 ds)

| 종류 | 예 | 자리(주인 발 기준, 적 방향 +) | 크기 | 그리기 순서 |
| --- | --- | --- | --- | --- |
| 동반형 | 로키 펜리르 | 뒤 70, 화면 위 20 | ×0.62 | 주인 앞(+1). 로키 허리 아래·뒤 몸과 실제 겹침, 로키/옆 아군 얼굴·HP바는 가리지 않음(12차 Root 정정, 2026-11-05) |
| 표시 전용 동반 | 오리온 시리우스 | 앞 150, 화면 위 10(아래 보정 적용) | ×0.60 | 주인 앞(+1). Unit·행동 순서·판정에 넣지 않는다 |
| 피격 가능 동반 | 토트 서기관 | 앞 150, 화면 위 10(아래 보정 적용) | ×0.50 | 주인 앞(+1). 작은 체력판·대상 접점도 SD를 추적 |
| 다수형 | 우치 분신 | (+100,+6)·(−165,−28)·(−250,+24) | ×0.55 | 주인 앞(+1+i) |
| 다수형 | 이시스 수호령 | (+105,+4)·(−170,−26)·(−255,+22), 30px 부유 | ×0.45 | 아군 SD 전체 위, HUD·숫자 아래 |

- 다수형은 **소환술사별 고유 배치**를 갖는다. 주인과 같은 깊이에서 주인 둘레 좌우로 넓게 펼친다. 하단 띠·주인 다리 곁 밀집은 사용자가 기각했다.
- 가장자리: 몸 박스 끝이 화면 가장자리 140px 안이면 먼저 안쪽으로 당긴다. 그래도 간격이 모자라면 (+215,−24), 그것도 안 되면 (+215,+40)으로 옮긴다.
- 앞 배치인 시리우스·서기관은 140px·중앙선 제한과 허리선 상한을 적용한다. 위 칸 충돌 시 위 칸 동반체만 아래 0.35몸높이·0.9배로 보정한다. 복원한 뒤 동반체와도 밀집하면 주인 앞을 유지하며 alpha 몸 경계의 최소 가로 간격만 추가 확보한다. 펜리르는 정정된 뒤 배치를 그대로 사용한다(2026-11-05).
- 밀집 금지: 어떤 두 소환수도 **가로 간격 < 몸 폭 0.6배이면서 세로 간격 < 몸 높이 0.5배**인 경우가 없어야 한다.
- 침범 금지: 화면 중앙선·상대 SD·같은 열 다른 아군 얼굴 앵커·하단 카드 줄·화면 밖에 걸리면 안 된다. 적 진영은 좌우 반전.
- **소환사와 소환수는 피격 판정이 별개다.** 주인이 맞을 때 소환수가 함께 HIT하는 표시는 금지. 우치 분신의 "대신 맞기"는 키트 기능이라 유지.
- 카드 배지: 분신 ×n / 펜리르 / 시리우스 ◆5칸 / 수호령 ×n / 서기관. 문구는 소환수 프로필 데이터에서 읽는다.
- 모션은 **기존 타격 시각 창 안에 압축**한다(분신 0.24초, 펜리르 0.10초). 타격 시각·대상 추첨·사망 처리 순서는 바꾸지 않는다.

## 5. 게임 등록

1. 원본(`Docs/Mockups/VisualSD/sd_gen/style_c3_v*/`)은 수정하지 않는다. 크기 보정·후처리는 `registered/` 사본에만 한다.
2. 크기 보정: 발바닥 중심(alpha≥129 최하단의 가로 중심)을 고정점으로 균등 배율을 적용해 √(w·h) IDLE ±3%에 맞춘다. 1.00배로 이미 안이면 보정하지 않는다. 확대가 캔버스를 넘으면 **나머지 포즈를 축소**한다.
3. `Assets/Resources/Sprite/SD/`에 추가한다. 임포트 설정은 `SdTextureImportPolicy`와 같게 하고, GUID는 Unity가 만든다. 기존 meta·GUID는 바꾸지 않는다.
4. `Assets/Resources/Data/97_stage_figures.yaml`의 해당 스탠딩 항목에 `sd: { prefix, facing, feetY: 1220, faceX, topY, head, chest, hand }`를 실측해 넣는다. `sd.facing`은 SD 원본 방향이며 생략 시 기존 자산과 같은 `right`다. 좌향 적 SD는 `left`로 지정한다. 상위 `facing`은 대체 스탠딩 원본의 방향으로 유지한다. 임시 할당 줄의 `# 임시 SD: DONOR` 주석을 제거하고, 임시 할당표를 갱신한다.
5. **표시 모드**: 실제 게임(릴리스 빌드 포함)에서 기본 표시는 **Stage(SD)**여야 한다. `VisualModeState`가 릴리스에서 Card로 강제하면 SD가 보이지 않는다. 0.5.5 첫 빌드에서 실제로 이 문제가 있었다.
6. 판정·피해·타격 시각·타수·스케줄러·자원 판정은 미술 작업에서 바꾸지 않는다.

## 7. Codex 산출물(캐릭터당)

## 8. Root 최종 검수

### 8.1 절차

1. `reports/{ID}.md`와 키트 문서를 대조한다(행동 해석이 맞는가).
2. `sheets/{ID}_poses.png`·`_face.png`(필요하면 `_silhouette`·`_with_summon`)를 직접 본다. 결함이 의심되면 원본 PNG를 확대한다.
3. 발 기준선·머리 크기는 수치로 확인한다. Codex 실측을 그대로 믿지 않고, 의심되면 PowerShell System.Drawing으로 직접 잰다.
4. 등록 후에는 Unity 실제 선택 렌더러 시트와 실제 Play 1920×1080 화면을 본다. 소환수는 주인을 전열 가운데·후열 앞줄·후열 뒷줄에 각각 세운 화면을 본다.
5. 판정을 `Logs/SDPoseV{N}_{날짜}/root_review_pm.md`에 캐릭터별로 남긴다.

### 8.2 판정

| 판정 | 조건 |
| --- | --- |
| **PASS** | §1~§4의 필수 항목을 모두 충족. 경미한 차이(장식 세부, 짧은 WINDUP의 작은 실루엣 차이, 등록 때 크기 보정으로 해결되는 머리 편차)는 메모로 남긴다 |
| **HOLD** | 고치면 되는 결함: 머리 ±3% 밖(보정 불가), 2.9등신 이상, WINDUP이 IDLE과 거의 같음, 흰 외곽, 글자처럼 읽히는 무늬, 기존 SD와 실루엣 겹침, 소환수 사실 비율, 콘셉트·키트 충돌에 대한 사용자 결정 필요 |
| **FAIL** | 키트와 반대되는 행동(치유 캐릭터의 공격 자세 등), 원화와 다른 인물, 발 기준선 불일치, VFX·배경 포함, 카메라 응시, 선정적 표현 |

### 8.3 필수 확인표(캐릭터마다)

- [ ] 키트 행동과 WINDUP·STRIKE가 맞는다(공격 없는 키트에 공격 자세 없음)
- [ ] 5장 alpha≥129 최하단 y = 1220, 1024×1280 RGBA, 모서리 alpha 0
- [ ] 머리 √(w·h) IDLE ±3%(또는 등록 보정 계획 명시)
- [ ] 아군 우향·적 좌향, 원화 얼굴·머리색·눈색·의상·원소색 일치. 익명 로마 군단 일반병은 5포즈 모두 눈 완전 차폐
- [ ] 단색 실루엣으로 5포즈 구분
- [ ] VFX·배경·그림자·글자·흰 외곽 없음
- [ ] 곱슬 과다·유치한 벡터풍 없음, 장식·명암 밀도가 승인본 수준
- [ ] 기존 SD와 무기·자세가 겹치지 않음(§6). 익명 로마 군단병끼리의 닮은 형태·중복은 허용
- [ ] 소환수: SD 비율, 주인과 한 쌍, 배치 규칙(§4.2) 충족, 밀집·침범 0
- [ ] 등록 후: Unity 실제 Play에서 SD로 보임(릴리스 빌드 포함), WINDUP→STRIKE→IDLE·HIT 0.42초·실제 사망 DOWN

### 8.4 사용자 확인으로 넘길 항목

선정성 기준선 근처(노출·몸 곡선 강조), 곱슬 경계, 등신 경계(2.8~2.9), 콘셉트와 키트 충돌. Root가 임의로 확정하지 않는다.

### 8.5 범위

정지 화면·부품 PASS를 영상·성능·전체 게임 QA·상용 미술 승인으로 확대하지 않는다.
