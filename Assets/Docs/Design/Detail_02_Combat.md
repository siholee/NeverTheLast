## 1. 전장 구조

세븐나이츠식 **전열/후열** 구조다. 각 진영은 2열이고, **한 열에 4명**이 세로로 늘어선다.

```
   아군 후열   아군 전열        적 전열   적 후열
    (x=-2)     (x=-1)          (x=1)    (x=2)
      □          □      ⚔       □         □      y=1
      □          □              □         □      y=2
      □          □              □         □      y=3
      □          □              □         □      y=4

              대기석  □ □ □ □ □   (전투 미참여)
```

| 항목 | 값 | 코드 |
| --- | --- | --- |
| x 범위 | `[-2, 2]`, **`x = 0` 없음** | `GridManager.xMin/xMax` |
| y 범위 | `[1, 4]` | `GridManager.yMin/yMax` |
| 진영당 | **2열 × 4행 = 8칸** | |
| 전열 / 후열 | `x = ±1` / `x = ±2` | `GetFrontColumn()` / `GetRearColumn()` |
| 대기석 | **5칸** | `GridManager.benchSize` |

### 1.1 화면 배치 상수

| 상수 | 값 | 의미 |
| --- | --- | --- |
| `ColumnSpacing` | 13.2 | 같은 진영 두 열 사이. 돌진하는 카드가 옆 열을 스치지 않게 벌린다 |
| `BattleColumnMinGap` | 0.9 | 전투/기본 준비에서 같은 진영 인접 카드의 **실제 확대 폭** 사이에 보장하는 최소 틈 |
| `SlotSpacing` | 12.8 | 한 열 안 4명의 간격. 카드 + 아래 HUD의 세로 영역(12.2)보다 크다 |
| `CenterGap` | 7 | 양 진영 사이 추가 거리 |
| `BattleCenterGap` | 1 | 양 진영 전열 카드의 실제 폭 바깥에 남기는 중앙 틈 |
| `Cell.CardSize` | 칸(10.16) × 0.96 | 카드 한 변 |

### 1.2 배치 규칙

| 대상 | 규칙 |
| --- | --- |
| 아군 | 전열(−1) 우선, 가운데 행(y=2,3)부터 채운다 — `TryFindOpenAllyPosition` |
| 적 | `archetype` 7·8·9 → 전열(x=1), 그 외 → 후열(x=2). 각 열 최대 4 |

실제 출전 인원은 파티 상한(5명)에 묶인다. 대기석 유닛은 전투 판정과 UI 모두에서 빠진다.

## 2. 행동 순서 — 턴제 + 행동치(AV)

**시간 축은 턴이다.** 벽시계는 연출(투사체 비행 · 카드 모션)에만 쓴다. 지속시간 · 주기 · 내부 쿨다운 ·
제어 · 집중은 전부 턴으로 센다. 초는 전투 판정 어디에도 남아 있지 않다.

### 2.1 턴의 정의

> **턴 = 그 효과를 들고 있는 유닛이 행동하는 것.**

| 대상 | 누구의 턴으로 세는가 |
| --- | --- |
| 버프 · 디버프 · 지속피해 · 원소 부착 | 상태가 붙어 있는 유닛 |
| 주기형 특성 | 특성 보유자 (`PeriodicTurnPassive`) |
| **집중** | **시전자** — [Detail_03 §4.5](Detail_03_Character.md) |

진행 지점은 `Unit.BeginTurn()` 한 곳이다.

### 2.2 AV — 다음 행동자 결정

```
AV = 10000 / 속도          (속도 = 최종 Speed 스탯, 작을수록 먼저 행동)
```

AV가 가장 낮은 유닛이 0에 닿을 만큼만 전원의 AV를 한 번에 깎고, 그 유닛이 행동한 뒤 자기 AV를 채운다.
동점이면 속도가 빠른 쪽이 먼저다.

**추월 제한.** A는 B보다 이번 라운드에 `floor(A속도 ÷ B속도)`번까지만 더 턴을 열 수 있다.
속도 2배 미만이면 번갈아 행동한다. 행동을 앞당기는 효과(`AdvanceAction`)는 앞당긴 비율만큼 추월 몫을 준다.

### 2.3 우선순위 — 한 번에 하나만

| 순위 | `ActionKind` | 행동 | 턴 |
| ---: | --- | --- | :-: |
| 0 | `PriorityAdditional` | 우선 추가행동 — 특성이 부른 것(세이의 빅뱅) | 안 쓴다 |
| 2 | `Additional` | 추가행동 | 안 쓴다 |
| 3 | `Coordinated` | 협동행동 — 🔸 enum만 남아 있고 쓰는 코드가 없다 | 안 쓴다 |
| 4 | `Special` | 특정 트리거가 연 특수행동 | 안 쓴다 |
| 5 | `Ultimate` | 궁극기 | 안 쓴다 |
| 6 | `Normal` | 일반행동 또는 대체행동 | 쓴다 |

0과 2는 성질이 같고 둘 다 `OnAdditionalActivates`를 발행한다(`ActionScheduler.IsAdditional`).
같은 `(유닛 + 종류 + 키)`는 큐에 하나만 존재한다.

**궁극기는 턴을 쓰지 않는다.** 마나가 차는 즉시 줄을 서고, 발동해도 AV가 리셋되지 않는다.

### 2.4 라운드 제한

라운드는 **전역 80턴**으로 끝난다(`GameManager.roundTurnLimit`). 추가행동 · 특성 발동은 세지 않는다.

### 2.5 궁극기 자원 — 행동 · 피격

마나 획득 규칙과 수치는 [Detail_03 §3](Detail_03_Character.md)에 한 벌만 둔다.
전투 시간에 비례하던 옛 충전(`INT × 전투 초`)은 없어졌다 — `ActionScheduler.ActionValuePerSecond`는
통계 표기에만 남았다.

전투가 끝나도 남은 마나는 다음 스테이지로 이어지고, 테마 라운드가 바뀔 때만 0이 된다. 단,
`ultimateResourceType: Stack`인 사바흐는 공용 행동·피격·처치 마나를 받지 않고 특성 이벤트만으로 아즈라엘을 채우며,
전투 밖 복원에서는 0으로 돌아간다. `Passive`인 바스테트는 자원을 소모하거나 자동 시전하지 않는다. HUD는 충전된
초월기와 같은 테두리와 가득 찬 내부를 상시 표시하고, 초월기 코드는 라운드 시작부터 종료·사망까지 구독형으로 동작한다.

### 2.6 어떤 코드에도 재사용 대기 시간이 없다

일반행동은 AV가, 궁극기는 마나가 주기를 정한다. 코드 안쪽 내부 쿨다운은 `Combat.TurnCooldown` /
`TargetTurnCooldown`으로 **턴**을 잰다.

### 2.7 직접 공격 대상 교체와 선제 개입

직접 공격은 원래 대상 목록을 모두 고른 직후 `AttackTargetRouter.Prepare`로 해석한다. 먼저 바스테트 경호처럼
대상을 교체하고, 이어 `ResolvePreAttack()`이 최종 대상의 선제 개입을 **동기적으로 끝까지 기다린다.** 이 두 단계는
`Targeting.Announce`, 행동 VFX, `TakeDamage`보다 앞이므로 공지·피격 연출·마나·반격이 모두 최종 대상과 일치한다.
일반행동은 `BaseNormalCode`, 초월기는 `BaseUltimateCode.PrepareTargets`, 특수행동은 같은 라우터를 직접 사용한다.

```text
원래 대상 목록 확정
→ AttackTargetRouter.Prepare(공격자, 전체 원래 대상, 코드 종류, 피해 태그)
→ 경호 등 대상 교체
→ ResolvePreAttack(최종 대상의 선제 개입을 동기 해결)
→ 공격자가 사망·제어되었으면 원래 공격 취소
→ Targeting.Announce(최종 대상)
→ 시전 1회 + 최종 대상별 피격 VFX
→ TakeDamage
```

바스테트 P322는 이 단계에서 바스테트 한 자리만 경호자로 바꾼다. 지속피해(`Effect`)·특성 간접 피해
(`PassiveAttack`)·원소 반응·덧붙는 피해(`BonusDamage`)는 직접 공격이 아니므로 교체하지 않는다. 추가행동처럼
스케줄러의 행동으로 실행되는 공격은 직접 공격이다. 다중 대상 목록에 이미 견고/반격 경호자가 있으면 대상 수나
중복 피격을 늘리지 않기 위해 교체하지 않는다. 다단 공격에서 교체된 경호자가 사망하면 잠근 대상이 사라진 것이므로
남은 타수는 취소한다.

잔 P207은 경호 교체까지 끝난 최종 대상이 잔일 때, 원래 공격보다 먼저 `PriorityAdditional` 자식 행동으로 N7을
한 번 실행한다. 같은 부모 행동·공격 키·잔 조합은 중복 처리하지 않는다. 반격 피해는
`NormalAttack + AdditionalAttack + CounterAttack + ContactAttack`이며, 반격 정점 뒤 공격자가 사망하거나 제어되면
원래 공격을 공지·연출·피해 전에 취소한다. 바스테트 U122 추격은 반격 피해를 감지하되 원래 행동이 끝나거나 취소된 뒤
예약 순서대로 실행하며, 선제 처치로 대상이 죽으면 만들지 않는다.

## 3. 피해 계산

### 3.1 파이프라인

```
0) Unit.AnyDamageIncoming         (정적 이벤트 — 경감 · 보호막 전. 세이의 빅뱅이 여기서 센다)
1) OnBeforeDamageTaken            (자신, 공격자)
2) CalculateFinalDamage           경감 (아래 3.2)
3) OnTakingDamage → 보호막 흡수 → 체력 차감
4) 사망 방지 판정                   BaseEffect.TryPreventDeath
5) 피격 마나 +5                    (지속피해 · 덧붙는 피해 제외)
6) OnAfterDamageTaken / OnDamageDealt / Unit.AnyDamageDealt
7) 체력 0 이하 → Die()             파괴 연출 → 처치 마나 → 비활성화
```

### 3.2 공식

```
기본 피해   = 코드가 정한다 — 고정값 + 스탯 × 계수 (Code.StatDamage)
            대부분 공격력 계수. 극소수가 방어력 · 최대 체력 계수
치명타      = 확률 CritRate, 배율 1 + CritDamage
경감 스탯   = 방어력        (일반 피해)
            = 특수방어력    (지속피해 CodeType.Effect · 원소 반응 · SpecialDamage 태그)
            = 없음          (TrueDamage)
기준값 K    = 100 + 6 × (공격자 레벨 − 1)
경감 배율   = K / (K + 경감 스탯 × 방어배율)      경감 스탯 ≥ 0
            = 2 − K / (K − 경감 스탯 × 방어배율)  경감 스탯 < 0
최종 피해   = max(1, round(기본 피해 × 치명타 × 주는 피해 보정 × 경감 배율 × 받는 피해 보정))
```

| 요소 | 출처 |
| --- | --- |
| 경감 스탯 선택 | `DamageMitigation.TryGetDefenseStat` |
| K | `UnitStats.ArmorConstant(attackerLevel)` — 상수 `ArmorConstantBase` 100, `ArmorConstantPerLevel` 6 |
| 경감식 | `UnitStats.MitigationMultiplier` |
| 방어배율 | `DamageContext.DefenseStatMultiplier` × 대상의 `DefenseStatMultiplierModifier` 등 (방어 무시 · 약화) |
| 주는 / 받는 피해 보정 | `OutgoingDamageModifier` / `ReceivingDamageModifier` 누적곱 |

#### 왜 공격자 레벨의 K인가

무한 모드에서 레벨은 끝이 없고 모든 스탯은 선형으로 자란다. K를 100으로 묶으면 방어력만 커져 경감률이
100%로 수렴해 고레벨 전투가 끝나지 않는다. K를 표준 방어 성장과 같은 기울기로 키우면 **같은 레벨끼리의
경감률은 레벨과 무관하게 일정**하고, 레벨이 높은 공격자는 낮은 방어자를 더 잘 뚫는다(원신식).

| 방어력 / 레벨 비 | 같은 레벨 경감률 |
| --- | --- |
| 표준 성장(방어 +5/Lv) 방어자 | 약 45% |
| 세이 (85 + 6.5/Lv) | 약 46~52% |

### 3.3 덧붙는 피해

다른 피해에 반응해 따라붙는 피해(세이의 초월기 고정 피해)는 `DamageTag.BonusDamage`를 단다.
덧붙는 피해는 **다시 덧붙는 피해를 부르지 않고**, 피격 마나를 주지 않는다.

### 3.4 치명타

| 항목 | 값 |
| --- | --- |
| 확률 | `CritRate` 최종값, 0~1로 자른다 |
| 배율 | `1 + CritDamage` (기본 5% / 50%) |

### 3.5 효과 명중과 회피

해로운 상태를 적이 걸 때(`UnitStatusController.Add`) 명중을 굴린다.

```
명중 확률 = 기본 확률 × 2 × 특공 / (특공 + 특방)     0~1로 자른다
```

두 스탯이 같으면 기본 확률 그대로다. 빗나가면 카드 위에 `회피`가 뜬다(`CombatFeedback.PlayEvade`).
확률을 코드가 이미 굴린 상태(화상 등)는 `UnitStatus.SkipEffectHitRoll`로 이중 판정을 막는다.
**피해 자체를 피하는 회피는 없다.**

## 5. 제어

행동만 막는 제어(빙결 · 에어본 · 기절 · 속박)는 모두 `ControlStatuses.ApplyControl`을 지난다.
지속 턴은 **특수공격력 ÷ 특수방어력** 비율로 정한다.

| 제어 | 지속 턴 | 범위 |
| --- | --- | --- |
| 빙결 | `round(2 × 특공/특방)` | 1~3 |
| 에어본 | `round(1.5 × 특공/특방)` | 1~2 |
| 기절 | `round(특공/특방)` | 1~2 |
| 고정 기절 | 코드가 정한 턴 (`ApplyFixedStun`) | — |

- 재부여하면 남은 턴과 새 턴 중 긴 쪽을 남긴다.
- **제어 분쇄** — 같은 대상에게 반복되면 100% → 60% → 30% → 면역. 제어 없이 자기 턴 3번이면 초기화.
- 제어가 걸리면 `OnControlStarts`가 나가고, 그 유닛이 건 **집중이 해제된다**(공허 분쇄자의 대지 분쇄로 검증).

## 6. 피해 태그

`BaseClasses/DamageTags.cs`. 만 자리가 분류이며, 한 공격은 각 자리에서 하나씩 붙인다.

| 분류 | 태그 |
| --- | --- |
| 10000 대상 범위 | `SingleTarget` · `MultiTarget` · `AllTarget` |
| 20000 공격 종류 | `NormalAttack` · `UltAttack` · `SpecialAttack` · `AdditionalAttack` · `CounterAttack` · `PassiveAttack` · `ElementalReaction` |
| 30000 접촉 | `ContactAttack` · `NonContactAttack` |
| 40000 관통 · 변환 | `ShieldPenetration` · `TrueDamage`(경감 없음) · `SpecialDamage`(특수방어력 경감) · `BonusDamage`(덧붙는 피해) |

**지속피해는 태그 목록이 비어 있다.** 접촉 판정은 `ContactAttack`이 **있는지**를 묻는다.
카드 흔들림 연출도 `ContactAttack`에만 붙는다.

## 7. 상태(Status) 시스템

`UnitStatus` + `BaseEffect`. 같은 키 = 같은 상태이고, `StatusStackPolicy`가
Replace / ExtendDuration / Stack / ReplaceIfStronger / Ignore 중 하나를 고른다.

### 7.1 BaseEffect 훅

| 분류 | 훅 |
| --- | --- |
| 생명주기 | `OnApply` · `OnOwnerTurn` · `OnRemove` |
| 스탯 | `StatFlatModifier(stat)` · `StatPercentModifier(stat)` · `ManaRecoveryMultiplierModifier` |
| 피해 | `OutgoingDamageModifier` · `ReceivingDamageModifier(unit, ctx)` · `DefenseStatMultiplierModifier` · `OwnedDefenseStatMultiplierModifier` · `TryPreventDeath` |

| 지속피해 | `IsDamageOverTime` · `EstimateDamagePerTurn` |

공용 효과는 `Effects/Buffs/SharedModifierEffects.cs`에 있다 — `StatModifierEffect(stat, 값 또는 Func, percent)`,
`ReceivingDamageMultiplierEffect`, `OutgoingDamageMultiplierEffect`, `ArmorShredEffect`, `ManaEfficiencyEffect`.
한 줄짜리 무조건 보정을 새 이름으로 다시 선언하지 않는다.

지속피해의 틱 피해는 **시전자 공격력 × 계수**이고 특수방어력이 경감한다.

### 7.2 상태 부여

```csharp
target.AddStatus(BuffStatus.Create(

```

카드에 오라를 그리려면 효과가 `ICardAura`(Glow · Ring)를 구현한다.

## 10. 전투 연출 — 자유 원화 카드

모든 유닛은 **자유롭게 선 원화 + 하단 글라스**다(`Entities/View/UnitCardView.cs`).
2026-09의 하스스톤식 불투명 판·보석은 원화를 가려 되돌렸지만, 카드 단위 모션과 전투 이펙트 구조는 유지한다.

| 부분 | 내용 |
| --- | --- |
| 원화 실루엣 | 원화 전체를 칸 안에 맞추고 카드 크기의 컷코너 프레임·보조면은 두지 않는다. 피격 피드백도 별도 스프라이트를 만들지 않고 원화 자체의 색만 짧게 변조한다. 상태 오라는 카드 면이 아니라 발밑의 낮은 타원 표식으로 제한한다. `Portraits/**` 원화는 무압축 RGBA32·밉맵 없음·Bilinear·Clamp로 임포트해 투명 면의 압축 블록이 흰 머리카락 둘레에 점선을 만들지 않게 한다. 런타임 RGBA32 사본은 이 무압축 원본을 GPU 임시 표면에서 읽는다. 투명 이웃과 맞닿은 외곽 1px을 8방향으로 걷고 새 경계를 반 픽셀 부드럽게 만든다. 분리감은 발밑 `#415C73` 43%의 넓은 접지 그림자와 하단 스모크 전이가 맡는다 |
| 에너지 오브 | 원화 우상단 중심 `(75, 28)`의 48 × 48 공용 하드웨어다. 별도 월드 캔버스를 `배경 < 오브 < 원화 < 하단 HUD·글자`로 정렬해 원화가 오브의 왼쪽·아래를 자연스럽게 덮는다. 오브는 카드 폭 안에서 끝나 옆 카드 원화를 침범하지 않는다. 링은 진영과 무관한 밝은 실버블루 크롬 + 청회색 키라인이고, 0%도 옅은 투명 유리 웰과 크롬을 유지한다. 원소색은 앞/뒤 액체 2층에만 쓴다. 액체 마스크는 크롬보다 5.5 안쪽에 두고, 수면은 아래→위로 차며 뒤층만 수위 ±0.028·가로 ±0.72로 어긋난다. 글리프는 흰 단색 + 어두운 사본이다. 완충해도 외곽 하드웨어는 중성색을 유지하고 내부 글리프 밝기와 오브 안에 갇힌 호흡광만 켠다 |
| 고유 자원 | 유닛별로 명시한 HUD 자원만 오브 윗링 안쪽의 9.2 × 7.2 숫자 각인에 한 자리로 적는다. 세이는 `SeiBigBang.ResourceId`를 쓰며, 현재값이 0이거나 명시가 없으면 받침과 숫자를 함께 숨긴다 |
| 하단 글라스 | 카드 안쪽 `x=2.5..97.5`, `y=72.5..100`의 95 × 27.5 A안 글라스 한 장이며, 상태가 없으면 `y=91.2`까지 18.7 높이로 접는다. 원화 블러 사본과 `SpriteMask`는 제거한다. 무압축 원본은 GPU 임시 표면을 거쳐 원화별로 한 번만 읽고, 하단 30%의 알파를 감쇠한 런타임 스프라이트 사본을 캐시한다. 좌·우·하단 어느 변이든 불투명 픽셀이 경계에 연속으로 길게 닿으면 해당 변 전체를 원화 폭/높이 7%에서 알파 감쇠한다. 연속 접촉이 최소 24px에 못 미치는 짧은 발·꼬리는 변 절단으로 오인하지 않는다. 반투명 가장자리 RGB는 3px 안의 불투명 원화색으로 블리드한다. 패널은 진영 공통 `#26384A` 72% 스모크 한 면 + 1px 냉백색 림 72% + 0.45 높이 상단 스펙큘러 28% + 하단 내부 그림자 10%로 끝낸다 |
| 정보 2/3행 | 일반·소형 LOD 모두 1행은 이름 + `현재 / 최대` HP, 2행은 아군 청록/적 적색 HP 바 + 윗면의 금색 보호막 선이며, 상태가 있을 때만 3행 흑백 아이콘을 연다. HP 바는 2.3에서 1.55로 줄여 목업처럼 가늘게 하고 행동 게이지는 분리한 0.7 높이 무채색 보조선으로 둔다. 하단 묶음은 카드가 확대돼도 슬롯 폭의 98% 기준을 넘지 않게 균일 축소하고, 이름·HP 글자도 같은 기준으로 줄인다 |
| 상태 | `StatusIcons`가 전용 `IconPath` → 키 → ID → 효과/분류 순으로 고르고 `status_glyph_atlas.png`의 `#F7FBFF` 글리프를 쓴다. 이로움은 열린 원+↑, 해로움은 마름모+↓, 행동 불가는 이중 마름모이며, 받침은 `#172534` 10% 채움 + 냉백색 42% 윤곽으로 가볍게 둔다. 중첩은 짙은 청회색 원 위의 흰 숫자, 넘침은 `›`다. 화면상 카드 폭 260px 미만은 소형 LOD, 300px 이상은 일반 LOD다. 소형은 우선순위 상위 3개 + `›`만 남긴다 |

생성형 원본은 `Resources/UI/CardHud/`에서 `Resources.Load<Texture2D>` 후 런타임 `Sprite.Create`로 읽는다.
현행 사용 자산은 비분할 `energy_orb_glass_bright.png`와 원소 글리프이며, `status_glyph_atlas.png`는
6 × 6의 128px 셀이다. 하단 패널은 PNG가 아니라 `UIShapes.RoundedRect`로 만들고, 원화→글라스 전이는
불투명 내부색을 반투명 가장자리에 블리드한 뒤 런타임 사본의 하단과 긴 직선 절단으로 판정한 좌·우·하단 변을 감쇠한다. 사용 HUD 자산은 PNG 임포트 타입에 의존하지 않고 런타임에 `Sprite.Create`한다.

실제 배치된 카드 중심에는 청회색 접지 음영과 저대비 각인만 둔다(`BattlefieldBackdrop.SetBoard`). 양 진영 사이는

4~7%만 남겨 생성 원화와 흰 캐릭터의 명도를 누르지 않는다. 배경은 원화보다 채도·대비를 한 단계 낮춘다.

**전투 연출 포커스** — 평상시는 위 밝기를 그대로 유지하고, 착탄·궁극기처럼 이펙트가 열리는 짧은 구간에만
`BattlefieldBackdrop.PushFocus`가 하늘 원화·바닥·각인의 RGB에 청흑 배율을 직접 곱한다. 회색 알파 면으로 덮지 않으므로
밝은 부분도 함께 가라앉되 원본의 채도와 명암 경계는 남는다. 가장자리에는 짙은 남색 비네트를, 시전자·착탄점에는
낮은 방사형 스포트를 두어 카드 둘레가 중앙보다 덜 어둡다. 이 레이어는 카드 원화·카드 HUD·상단 바·행동 순서·피해
집계·VFX에는 곱해지지 않는다. 요청은 합산하지 않고 현재 가장 강한
곡선을 택하므로 연사·다중 착탄에서 화면이 깜빡이지 않는다. 페이드는 `Time.deltaTime`을 써 배속·히트스톱을 따르며,
전장 비표시·스테이지 재배치·카메라 비활성화 때 `ClearFocus`로 즉시 원복한다. 배경 전환 중인 현재·이전 원화와
테마 베일·바닥 각인·중앙선은 같은 RGB 배율을 받고, 비네트·섬광은 매 프레임 카메라 뷰포트보다 12% 크게 맞춘다.
방사형 스포트는 거리를 0~1로 정규화한 뒤 알파를 0까지 닫고, 런타임 마스크도 `FullRect`로 투명 페더를 보존한다.
따라서 16:9·21:9·4:3 및 편성별 카메라 이동에서도 저알파 끝이 사각형으로 잘리지 않는다.

**프레이밍** — 덱 구성 중에는 2열 × 4행 빈 칸을 모두 보여 주지만, 전투/기본 준비에서는 실제 점유 카드만 모은다.
전열이 비고 후열만 있으면 후열을 안쪽 표시 열로 당긴다. 같은 진영의 전열/후열 중심 간격은 양쪽 카드의
실제 확대 폭 절반씩과 최소 틈 0.9를 더해 정하므로 하단 패널이 겹치지 않는다. 전투의 1:2 같은 비대칭 편성은
빈 반대편 경계를 복제하지 않고 실제 점유 경계로 카메라를 잡는다. 좌측 행동 순서와 우측 피해 집계의 서로 다른
폭도 별도 안전 영역으로 계산한다. 1:1은 카드가 화면 높이 52%를 넘지 않게 상한을 두고, 1:2는 약 40~45%를 목표로 한다.
총 카드 수 1~3 / 4~5 / 6~7 / 8 이상은 각각 화면 배율 1.28 / 1.14 / 1.0 / 0.88을 쓰며,
`Cell`은 보스 강조 배율과 이 밀도 배율을 곱한다.
사망·등장으로 경계가 바뀌면 카메라는 0.30~0.34초 동안 부드럽게 따라가고, 마지막 파괴의 `HoldCamera` 동안에는
기존 프레임을 유지한다. 화면 고정 하늘 성채 원화는 카메라 자식의 cover 배치라 줌과 무관하게 화면을 계속 덮는다.

**피해 숫자** — `DamagePopup`은 Noto Sans KR 굵은 비이탤릭 숫자다. 보통 피해는 `#FFF4E4` 웜 아이보리 채움 + `#132033` 8방향 외곽(카드 폭 1.05%) + `#05101B` 아래·오른쪽 SDF 그림자 + 원소색 0.32% 안쪽 림, 치명타는 `#FFD65E` + `#5B2B10` 외곽·1.32배·`!`·짧은 대각 슬래시다. 피격점에서 얼굴 바깥쪽 40~47% 안전 슬롯에 만들고 0.55초 안의 연속 피해는 최대 4단으로 좌우 교대한다. 0.1초 동안 1.18→1.0으로 내려앉고, 머문 뒤 마지막 44%에만 위로 8% 떠오른다.

날아가는 카드는 정렬 순서 +600으로 다른 카드 위에 그린다. 애니메이션은 `LateUpdate`에서 돌고 `Tick`은 HUD만 갱신한다.
돌진·피격의 이동과 스케일 반동은 HUD도 따라가되, 몸체 기울기는 월드 캔버스와 이름·HP가 역회전해 화면 수평을 유지한다.

### 10.2 전역 연출 원칙

아군·적, 캐릭터·일반 적을 가리지 않고 아래 다섯 원칙을 새 연출과 기존 연출의 개수 작업에 함께 적용한다.

| 원칙 | 규격 |
| --- | --- |
| P1 방향성 | 시전점과 피격점의 회전·좌우 반전은 고정 각도나 진영 상수로 정하지 않는다. `VfxSpace.AimFrom(caster, target)`이 반환한 **시전자→대상 벡터**의 각도와 진행 방향을 쓴다. 대상이 위·아래 줄에 있으면 그 기울기까지 반영하며 적이 시전하면 자연스럽게 왼쪽을 향한다. |
| P2 다중 대상 | **시전자 카드에서 시전·휘두르기 한 번 → 대상 카드마다 피격 이펙트**만 연다. 대상 사이를 잇는 이동 궤적·중간 칼날·관통선은 만들지 않는다. `BuildTargetHitSequence`/`ResolveTargetHits`는 동시 또는 기술별 0.04~0.12초의 짧은 대상별 피격 순서만 계산하며 피해 횟수·대상·치명타 공유 같은 전투 계약은 바꾸지 않는다. |
| P3 전원 비투사체 기본 문법 | 검사·마법사·사수·짐승·적을 포함한 모든 직접 공격은 카드 돌진이나 탄도 비행을 기본으로 쓰지 않고 **시전자 카드의 시전/사격 이펙트 + 대상 카드의 피격 이펙트**로 구성한다. 짧은 제자리 반동·후퇴/부분 전진은 허용한다. 판정 콜백은 피격 정점에서만 실행하며 두 이펙트 모두 P1 방향을 따른다. |
| P4 전용 앞 레이어 | 전투 VFX의 `SpriteRenderer`·플립북·Handpaint·Hovl·파티클은 `CombatVfx` 정렬 레이어를 쓴다. 카드 원화·이웃 카드·카드 월드 HUD보다 앞이고 화면 고정 상단 바·모달 UI보다 뒤다. 카드 경계를 벗어난 원화도 자르지 않는다. |
| P5 표준 부품 조합 | 스킬마다 별도 원화를 만들지 않는다. `96_vfx.yaml`의 표준 부품을 `prepare`·`cast`·`hit`·`affected`·`screen` 슬롯에 배치하고 색·크기·방향·시간 오프셋만 조합한다. 다중 대상은 `simultaneous`·`sequence` 모드로 대상 위치의 피격만 열며 전투 코드의 대상·피해·판정 횟수는 바꾸지 않는다. |
| P6 후속 2단 구조 | 현행 적용 대상은 **시의 만종**이다. 멸참의 시전+피격을 먼저 끝까지 보여 주고, 3타는 같은 대상에 작은 만종, 6·9타는 적 진영 중앙에 큰 만종을 바로 잇는다. 만종용 새 시전 사이클은 없고 9타의 잔광도 같은 피격 단계다. |
| P7 의미가 읽히는 미리보기 | 비전투 상태 검수는 화면 상단에 `버프 부여`·`기절`처럼 한국어 라벨을 붙이고 한 종류씩 약 1초간 순차 재생한다. 시전·사격·화면 톤다운은 호출하지 않아 공격 장면으로 오해되지 않게 한다. |
| P9 단계 절제 | 공격기는 `시전 → 피격 → 실제 부가효과가 있을 때만 affected`, 버프기는 시전 하나와 시전자 외 대상의 affected만 쓴다. 보호막 생성처럼 별도 결과가 있어도 단순한 한 단계만 더한다. 시전자 몸 위 충격형 시전은 금지하며 카드 움직임이 시전 역할을 하면 별도 시전 이펙트를 겹치지 않는다. 단일 타격의 시전→첫 피격 정점은 승인된 시 약 **0.56초**·사바흐 약 **0.64초**를 기준으로 한다. 연사·다중 피격은 새 시전을 반복하지 않는 한 타격 단계로 보고, 시퀀스 안에서 승인 간격에 가장 가까운 대표 정점을 같은 ±30% 기준으로 검수한다. |
| P10 피격 위치 | 피격 이펙트의 중심은 대상 카드의 발밑·패널·빈 공간이 아니라 **얼굴~상체 초상화 박스 안**에 둔다. 시 6·9타 만종과 사바흐 아즈라엘의 중앙 벼락은 생존 적 진영 중심을 쓰되, 뒤따르는 수평 연기는 같은 중앙 X에서 점유된 각 적 행의 얼굴~상체 Y로 펼친다. 정점 프레임의 차분 무게중심으로 검수한다. |
| P11 사전 자체 검수 | 사용자용 영상 전에 스킬별로 ① `96_vfx` 단계 수 ② 피격 중심 ③ 시전이 피격처럼 보이지 않는지 ④ 시전→피격 간격 기준 ±30% ⑤ 방향·`CombatVfx` 앞 레이어 ⑥ 표시 1×와 실제 영상 길이 ±5%를 자동+육안 확인한다. 정점의 불투명 면적을 초상화 박스 면적으로 나눈 값은 시전 **15%**, 피격·지원 **35%**를 하한으로 하고, 평균 휘도 차 0.18 또는 진한 외곽선, 연속 0.12초, 공격 얼굴 가림 0.15초 이하(지원은 0)를 함께 확인한다. 카드 밖으로 뻗는 시전은 원화를 자르지 않는 넓은 측정 창을 쓰되 면적·외곽 비율의 분모는 같은 초상화 박스로 유지한다. 스킬별 정규화 실루엣 IoU가 **0.82** 이상이면 중복 경고를 남긴다. 하나라도 실패하면 수정·재촬영하며 결과를 `qa.md`에 남긴다. |
| P12 내부 VFX 분류 | 플레이어에게 노출하지 않는 `vfxClass`가 기본 시전을 고른다. `caster`는 팩 `Fire3` 작은 불꽃을 카드 중앙과 적 방향 끝에, `archer`는 `Muzzle1` 총구광을 쓴다. `saber`·`fighter`·`lancer`·`beast`는 짧은 카드 전진이 시전이며, `assassin`은 고유 발도를 우선한다. 캐릭터별 정체성은 속성색과 `hit` 부품으로 표현한다. |
| P13 포커스 조명 | 행동마다 시전자·현재 피격/지원 대상만 밝게 남기고 나머지를 단일 `BattlefieldBackdrop` 포커스 체계로 어둡게 한다. 슬롯 진행에 따라 시전자 단독→시전자+대상으로 중심을 옮기며 일반은 약, 추가·특수는 중간, 궁극기는 강으로 쓴다. 4× 이상은 강도·지속을 줄이고 연속 행동은 기존 요청을 이어 받아 깜빡임·이중 암전을 막는다. 정의는 `screen.focus.normal/special/ultimate`로 둔다. |
| P14 범용 지원 피격 | 지원기는 고유 `cast` 뒤 `hit.support.buff/cleanse/heal/shield` 중 실제 결과에 맞는 한 부품을 대상마다 연다. 강화는 `Impact1`을 역재생해 머리 위로 모으고, 보호막은 은회색 `Ball1` 구체를 몸통에서 짧게 회전시킨다. 강화의 현재 크기는 카드 기준 `0.96×0.84`이며, 요청된 머리 폭 약 75%까지 축소됐다고 보지 않는다. 정화는 역재생 `Smoke5`, 치유는 녹백 `Impact1`을 쓴다. 네 부품은 끝점에서 카드 하단 HUD로 빛점을 보내 상태 아이콘·HP·보호막 표시를 1.0→1.35→1.0으로 팝하고 링 플래시를 연다. 색은 시전자 시전색으로 재착색하되 보호막은 은회색, 피그말리온 날카로운 가시는 장미색으로 고정한다. 상태 자동 재생과 스킬 명시 슬롯은 중복하지 않는다. |
| P15 방향성 피격 앵커 | 방향성 피격 시트는 그림 중심이 아니라 `impactAnchorX/Y`의 실제 충돌 끝점을 대상 초상화 중심에 맞춘다. `incomingImpact`는 충돌점에서 공격자 쪽으로 몸체를 뻗어 적 공격의 몸체가 카드 오른쪽, 아군 공격의 몸체가 카드 왼쪽에 남는다. 좌우·상하 각도는 `AimFrom`으로 계산하고 총구처럼 이동 방향을 직접 그리는 시트는 회전 뒤 중복 반전하지 않는다. |
| P16 조합의 인과 | 연속 부품은 앞 부품의 접촉·낙하 앵커에서 다음 부품이 발생해야 하며, 같은 부품을 의도 없이 중복 재생하지 않는다. Smoke는 하단 중앙, Lightning은 낙하 끝, Fire는 밑동, Impact/Explosion은 폭심, Slash/Claw는 충돌 끝을 기준으로 기록한다. 강화는 크기보다 외곽 대비·잔광·리듬으로 구분한다. |
| P17 검수 산출 | 스킬마다 `timeline.json`·0.05초 연속 `strip.png`·앵커/초상화/부품 박스를 표시한 `anchors.png`·`visibility.json`·960×540 `visible_at_scale.png`를 남긴다. 부품 중복, 앵커 오차 ±10%, 가시성, 사망 연출 전 재배치 시작 여부를 자동 판정한다. |
| P18 가시성 | 5유닛 1× 화면의 밝은·어두운 배경 모두에서 시전 면적 15%, 피격·지원 면적 35%, 대비 0.18 또는 진한 외곽선, 연속 0.12초를 만족한다. 짧은 연발 부품은 전환 프레임을 압축하고 `peakHoldSeconds`로 정점만 유지해 펄스끼리 겹치지 않으면서 실제 캡처 지속 기준을 지킨다. 지원 피격은 얼굴 중앙을 비우고 둘레·발밑·가장자리로 면적을 확보한다. |

P4 이전에는 전투 VFX와 카드가 모두 `Default` 정렬 레이어에 있었고, 호출 경로마다 정렬 순서만 더했다. 월드 캔버스,
카드 자식, 독립 프리팹이 섞이면서 같은 숫자 계약을 공유하지 않아 이웃 카드나 카드 HUD가 VFX를 덮었다. 원인은 제거된
`SpriteMask`나 `RectMask`가 아니라 **서로 다른 렌더러를 같은 정렬 레이어에 둔 구조**였다. `VfxSpace.ResolveSortingLayer`와
`NewSprite`가 전용 레이어를 강제하고, `HandpaintFx`·`SkillFx`·`FlipbookFx`·`HovlFx`·`VfxParticles` 등 직접 렌더러를
만드는 경로도 같은 규칙으로 정규화한다.

P5의 데이터 키는 SFX 큐와 같은 논리 이름(`shi.destruction_slash`, `sabah.azrael` 등)을 사용한다. 각 슬롯은
`partId`, 몸체/코어 색 재정의, `scale`, `direction`(`casterToTarget`·`stroke`·`radial`·`fixed`),
`angleOffset`, `timeOffset`, `peakFrame`, 선택 `useCasterColor`를 가진다. `VfxDefinitionCatalog`가 부품과 스킬 정의를 읽고
`VfxComposer`가 P1 방향·P4 정렬·Handpaint 합성 규격을 적용한다. `hit`의 `triggersImpact` 정점만 전투 코드가
넘긴 콜백을 열어 한 대상당 정확히 한 번 판정한다. 상태 부여는 `UnitStatusController.Add`가 성공한 직후
`StatusAffectedVfx`를 호출한다. 상태의 `AffectedVfxPartId` 또는 `statusBindings`가 있으면 그 부품을 쓰고,
없으면 강화/보호막/회복·해로운 효과/둔화/표식·제어·지속피해 분류의 기본 `affected` 부품을 고른다. 해로운 상태 제거는
`hit.support.cleanse`, 실효 회복은 `hit.support.heal`을 재생한다. 강화는 머리 위 역재생 별형 충격, 보호막은 몸통의 은회색 구체를 쓰고,
끝에서 카드 하단 상태 아이콘·HP·보호막 게이지로 빛점이 내려가 실제 UI 변화를 강조한다. 지원 연출은 얼굴을 불투명하게 덮지 않는다.
폭발·연기·충격 시트는 유익 `affected`에 쓰지 않는다. 이는 기존 상태 아이콘과 `ICardAura`를 대체하지 않는 단발 부여 연출이다.

### 10.3 이펙트 모듈 (`Effects/Vfx/`)

| 파일 | 역할 |
| --- | --- |
| `VfxSpace` | 절차적 스프라이트와 가산 재질. `WorldPoint`는 `Cell.CardCenter`, `AimFrom`은 시전자→대상 각도·반전, `BuildTargetHitSequence`/`ResolveTargetHits`는 궤적 없이 짧은 대상별 피격 순서와 콜백만 맡는다. `ResolveSortingLayer`는 모든 전투 렌더러를 `CombatVfx` 앞 레이어로 정규화한다 |
| `SpriteFx` / `VfxTiming` | 한 장짜리 확대·회전·페이드와 배속 보정. 8배속에서도 짧은 코어·외곽은 최소 2프레임, 투사체 비행은 최소 3프레임을 남긴다 |

#### 10.3.1 플립북 합성 기준

- 몸체는 알파 블렌드, 밝은 코어만 휘도 임계 가산으로 분리한다. 큰 문장·결정 벽의 몸체 정점 알파는 **0.60~0.85**를 넘기지 않고, `fade-in → 정점 → fade-out` 곡선과 UV 소프트 마스크로 가장자리를 닫는다.
- 인접 프레임 교차 합성과 위치·회전·크기 이징을 기본으로 한다. 16칸 시트라도 연속 보간해 끊김을 줄이며, 대형 정점은 2048급 단일 원화를 겹쳐 확대 흐림을 보완한다. 32장 전체 재생성은 실루엣 변화가 큰 기술에만 쓴다.
- 발밑에는 원근 타원형 가산 빛 웅덩이와 낮은 접지 그림자를 함께 둔다. 연출 반사광은 주변 카드 원화에만 짧게 더하며 얼굴의 흰색이 날아가지 않게 저채도 틴트와 상한 알파를 쓴다.
- `BattlefieldBackdrop.CurrentBackgroundLuminance`로 현재 배경 명도를 읽는다. 밝은 판에서는 몸체의 흑갈색을 들어 올리고 금·호박·백색 코어 비중을 높이며, 어두운 판에서는 몸체 알파와 가산광을 함께 낮춰 과발광을 막는다.
- 세이의 16프레임/교차합성/고해상도 정점 혼합 비교에서는 프레임 수만 늘린 것보다 **교차합성 + 형태 이징 + 고해상도 정점**이 윤곽 선명도와 장면 접지를 함께 개선했다. 따라서 이를 기본값으로 삼고 피해 콜백 프레임은 기존 인덱스를 유지한다.
- 발도는 `Presets/DrawSlashFx`의 파라미터형 직선 프리셋을 쓴다. 색·길이·굵기·각도·지속·카드 상대 오프셋을 주입할 수 있으며, 비가산 몸체와 가산 코어를 좌하단→우상단 한쪽 끝부터 와이프하고 같은 방향의 이동 선두광·짧은 잔상을 겹친다. `mirror: true`는 적 카드용 우하단→좌상단 좌우 반전이다.
- 손그림 팩 시트는 원본 패키지 폴더를 수정하지 않고 실제 사용하는 시트만 `Resources/VfxTex/Handpaint/`에 복사한다. `HandpaintFx`는 구매 팩의 프리팹에서 읽은 행×열·권장 FPS를 보존하되 카드 중심 피벗과 카드 상대 크기·회전·mirror를 적용한다. 전 캐릭터는 기본 화풍에서 이 경로를 쓰며, 이전 연출은 Legacy 비교·회귀용으로 남긴다. 몸체 알파의 0.035 컷오프와 0.055 소프트 구간은 밝은 판에서 시트 셀의 옅은 사각 안개만 걷고, 휘도 코어·접지·장면 반사광은 기존 합성 규칙을 유지한다. `Fire3_Yellow`는 밑동 앵커를 카드 중앙과 적 방향 끝에 맞춘 caster 공용 2점 시전, `Smoke3_Purple`은 낙하·할퀴기 접촉점 하단에서 중앙→좌우로 한 번 퍼지는 수평 피격에 쓴다.
- 히미코 기본 일반행동은 caster 공용 `Fire3_Yellow` 시전광 한 번과 대상 얼굴~상체 중심의 `Explosion2_Red` 피격 한 번, 성공한 맹화 `affected` 한 번만 쓴다. 3중첩은 세 번째 표식 부여광을 생략하고 일반 피격과 같은 크기의 Red Explosion을 적갈색 대비로 바꿔 한 번 연 뒤 받는 피해 증가 `affected` 한 번으로 끝낸다. 표식 제거→받는 피해 증가 상태→폭발 연출 예약→고정 피해 순서는 그대로 둔다. 피그말리온은 적갈 `Fire3_Yellow` 두 점 뒤 대상 얼굴~상체에 `Explosion2_Red` 화염 피격 한 번만 열고 판정도 한 번 유지한다. 두 캐릭터의 이전 `RadiantVolleyFx`/`ClawRakeFx` 경로는 Legacy로 보존한다.
- 방향성 시트의 `impactAnchor`는 그림 중심이 아니라 Lightning 낙하 끝, Smoke 하단 중앙, Fire 밑동, Slash/Claw 타격점, Explosion 폭심을 뜻한다. 런타임은 반전·회전된 앵커를 역산해 대상 초상화 중심에 맞춘다. 사망 시에는 퇴장 연출 완료 전 시각 재배치를 보류하고, 처치 재행동은 `WaitForFieldLayoutSettled` 뒤 시전해 빈 자리나 이동 중 카드에 먼저 피격이 뜨지 않게 한다.
- P17 검수는 각 스킬의 부품 타임라인·0.05초 스트립·앵커 오버레이·원크기 정점을 남긴다. P18 면적·대비·0.12초 지속·얼굴 가림은 밝은 하늘 성채와 어두운 시험 배경에서 모두 잰다. 행동 포커스의 전역 명도 변화는 대비 픽셀에서 제외하고, 각 부품은 행동 전 효과 없는 프레임과 비교한다.
- 공허 괴수 중타격과 활 발동/착탄은 `Resources/VfxTex/Gen/Enemy2/`의 4×4 시트와 고해상도 정점을 함께 쓴다. 어두운 몸체는 알파 합성, 좁은 금백·백열 코어만 휘도 가산하며, 밝은 판에서는 대표색을 들어 올리고 어두운 판에서는 코어 알파를 억제한다.
- 사바흐의 `ShadowPuddle`·`SoulCleaveArc` 합성은 Legacy 비교용으로만 남는다. 기본 아즈라엘은 손그림 보라/검정 몸체와 좁은 전격 코어를 겹치되 대상 사이 궤적은 만들지 않는다. 각 대상의 단일 피격 정점에서만 판정하고 후속 폭발은 열지 않는다.
- Legacy 찬드라 성역은 `Resources/VfxTex/Maple/Chandra/{MoonWaveRing,MoonSanctuaryDome}`을 몸체 알파와 휘도 코어로 이중 합성한다. 소마는 **1.12초 역수렴 → 0.56초 봉합 → 0.52초 안정**, 창야는 **1.20초 역수렴 → 0.58초 봉합 → 0.56초 안정**으로 재생한다. 바깥 월륜·광선·파편과 중앙 봉합은 하나의 이징 진행률을 공유하며 밖으로 폭발하지 않는다. 창야는 소마보다 장식층과 잔광이 한 단계 많고, 이어지는 **0.54초** 적중은 섬광·십자·눈금 고리·입자 흩날림으로 구성한다. 이 문단의 배경 톤 다운도 Legacy 비교 경로에서만 유지한다.

카드 원화 위의 큰 가산 원판은 금지한다. 앞쪽 레이어는 작은 심광·테두리·짧은 스윕만 쓴다.
피격 카드는 별도 면광 없이 원화 자체만 짧게 웜 틴트해 전용 착탄광과 겹쳐도 사각 받침을 만들지 않는다.
넓은 룬·빛기둥·먼지는 카드 뒤 또는 발밑에 둔다. 모든 비행/프리팹 오브젝트에는 라운드 재시작과
시전자 비활성화에 대비한 파괴 안전시간을 둔다.

포커스 딤을 쓰는 착탄에서는 넓은 황토/엄버 받침을 두지 않는다. 암편 외곽과 비행 방향을 잡는 청회색 알파만
낮게 남기고, 착탄 섬광·충격 고리·금빛 광맥은 가산으로 연다. 등장처럼 딤이 없는 작은 연출의 먼지도 청회색으로
짧게 꺼서 밝은 바닥에 갈색 얼룩이 남지 않게 한다.

일반 연출은 **주인공 요소 1개 + 보조 요소 최대 2개**로 제한한다. 다만 창세의 노래·빅뱅은 화면 단위 대형 기술로,
원화 뒤 4×4 결정 문장 + 상승 광입자 + 대상별 플립북 Hit을 한 묶음으로 허용한다. 얼굴·눈·머리 실루엣은 계속 금지 구역이며,
전면 가산광은 작은 심부에만 쓴다. 보호막은 발밑의 호박 결정 Hit을 주인공으로 삼고 좌우 소형 Flash만 보조한다.
빅뱅은 시전자 카드 위 대형 금빛 시전광을 한 번만 열고 `pickTarget()`이 **0.075초** 간격으로 고른 일곱 위치에
백금 심광과 금빛 결정 파편을 바로 파쇄한다. 각 선택은 **0.242초** 뒤 독립 피해를 만들며 탄도·산개·귀환·원형 발사대는
쓰지 않는다. 이전 추적 가시와 `RadiantVolleyImpact_4x4` 착탄은 Legacy 비교 경로에만 남긴다.
창세의 결정 흡수는 `Hit 26`과 짧은 글린트 두 가닥만 쓴다.

#### 10.2.4 접촉 공격 타임라인
