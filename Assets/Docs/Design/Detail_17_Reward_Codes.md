## 2. 보상 코드 규칙

### 2.1 장착

| 항목 | 규칙 |
| --- | --- |
| 받는 쪽 | 보상 · 구매 시 아군 1명을 지정한다. 벤치 · 쓰러진 유닛도 받을 수 있다(소환수 제외, `RewardCodeFlow.Party`) |
| 슬롯 | **유닛당 활성 보상 코드 7칸 + 개수 제한 없는 개인 코드 보관함**(`Unit.RewardCodeSlotCount`). 고유 특성 · 일반행동 · 초월기는 칸을 쓰지 않는다 |
| 슬롯이 찰 때 | **초과분은 보관함으로 들어간다.** 기존 활성 코드를 지우거나 교체 대상으로 고르지 않는다 |
| 중복 | 보상/구매는 같은 유닛의 활성·보관을 모두 검사해 중복 획득을 막는다. 드래그로 같은 코드를 보관할 수 있지만 동시 활성화는 금지한다. 다른 유닛끼리는 활성 코드가 겹쳐도 된다. **상위를 이미 가진 유닛은 그 하위를 받지 않는다**(`Unit.CanReceiveRewardCode`) |
| 필드 효과 | "필드에 있으면"류는 보유자가 **필드에 서 있을 때만**(`Unit.IsOnField`) 켜진다. 여러 명이 들면 **높은 하나만** 적용한다(`RewardAura.Best`, 계열 키가 같은 오라끼리). 한 보유자의 코드 종료는 다른 활성 보유자의 공유 오라를 제거하지 않는다. 마지막 활성 보유자가 종료되면 제거한다. 죽는 중인 보유자는 오라에서 제외하며, 홀리 인챈트의 치명타 캐시는 사망 알림에서 즉시 갱신하여 자기 턴 이전의 추가행동·초월기에도 사라진 오라가 남지 않는다 |
| 수명 | 런 영구. 쓰러져도 남는다. 빈 칸을 포함한 활성 7칸은 `UnitSaveData.activeRewardCodeSlots`, 보관 순서는 `storedRewardCodeIds`에 저장한다(저장 v17, v12/v13/v14/v15/v16 자동 이관) — §7 |
| 장착 코드 위치 | **활성 코드만** `Unit.PassiveCodes`에 붙는 일반 `PassiveCode`다. 보관 코드는 스탯·상태·오라·정산 효과를 내지 않는다. 라운드 시작에 `CastPassiveCode`가 켜고, 라운드 종료에 `StopCode`가 상태 · 구독을 걷는다 |

**준비 중 무료 Drag & Drop.** Tab 창에서 활성 칸 → 보관함은 비활성화, 보관함 → 활성 칸은 활성화다.
점유된 활성 칸으로 옮기면 밀려난 코드는 출발 위치로 돌아가며 양쪽이 교환된다. 왼쪽 아군 초상화로 끌면 그 아군의
보관함으로 이동한다. 벤치·쓰러진 아군도 교환 대상이다. 출발 위치 변경·중복 활성·상하위 동시 활성·준비 밖 드롭은
양쪽 상태를 바꾸지 않는다. 전투 중에는 확인만 가능하다. `Combat.RewardCodeInventory`가 두 유닛의 결과를 먼저 검증한다.

**7칸은 활성 효과 예산이다.** 추가 코드 보유는 허용하지만 동시에 효과를 내는 수는 늘지 않는다. 보관과 무료 교환은
다음 적 편성에 맞춘 빌드 조정을 쉽게 만든다. 상점 가격·구매 2회·보상 티어 확률·코드 계수는 유지한다.
장비·중량·숙련은 복원하지 않는다. 아이템은 공용 보급, 보상 코드만 유닛별 보관함에 둔다.
장기 런에서 생존·경제·성장 코드를 전투별로 바꿀 수 있는 가치 증가는 별도 밸런스 시뮬레이션 대상이며 승률 검증을 완료했다고 보지 않는다.

### 2.3 상위 코드

- 하위 코드는 `SupersededByCodeId`로 상위를 가리킨다. 사다리의 원본은 `20_codes.yaml`의 `supersededBy`이고
  `RewardCodeCatalog`(`UpperOf` · `IsUpperOf` · `LowersOf` · `SealTargetOf`)가 조회한다. `Unit.CastPassiveCode`는 상위를 가진 하위의 발동을 재운다.
- **같은 유닛이 상위를 받으면 활성 하위는 보관하고 그 칸을 그대로 쓴다.** 상위를 받는 것은 칸을 더 쓰지 않는 강화다(`Unit.TryGrantRewardCode`가 하위를 보관하고 같은 자리에 상위를 넣는다).
- 옛 제도와 달리 **하위 없이도 상위를 받을 수 있다.** 무작위 보상에서 선행 조건을 걸면 상위가 사실상 나오지 않는다.
- 보상 화면은 파티 중 누군가 하위를 활성화하고 있으면 상위 카드에 `▲ 상위: ○○`을 표시한다.
- **T1 깡 스탯과 T2 퍼센트 스탯은 사다리가 아니다.** 합연산과 곱연산은 서로 다른 항이라 함께 들 때 각자 일한다.
  T2를 받아도 T1은 사라지지 않는다. 다만 **청동 승급의 인장**으로만 T1을 대응하는 T2로 바꿀 수 있다(아래 표).

### 2.4 승급의 인장

**인장은 올릴 수 있는 최대 티어로 나뉜다.** 한 번에 한 단계만 올리며, 높은 인장은 낮은 인장의 일을 모두 한다.
상위 코드가 없거나, 상위의 티어가 인장의 한계를 넘으면 쓸 수 없다.

| 인장 | 아이템 티어 | 최대 승급 | 쓰는 곳 |
| --- | ---: | ---: | --- |
| 청동 승급의 인장 | T2 | → T2 | T1 깡 스탯 → 대응 T2 |
| 은 승급의 인장 | T3 | → T3 | 소환술사 → 소환사 · 결전의 포효 → 결전의 일격 · 연격 → 연환격 · 되받아치기 → 응징 · 기수 → 도발의 문장 |
| 금 승급의 인장 | T4 | → T4 | 재기의 바람 → 기사회생 · 투사 → 하루종일도 할 수 있어 · 치유의 손길 → 의신의 가호 · 역병의 저주 → 죽음의 계약 · 원소 촉매 → 원소술사 · 축적의 촉진 → 겹겹이 쌓인 운명 |
| 별빛 승급의 인장 | T5 | → T5 | 기사회생 → 완벽한 재기 · 천살성 → 당연한 운명 · 원소술사 → 대해의 판결 |

인장은 활성·보관 코드에 모두 쓸 수 있다. 재료 코드를 변환하는 승급이므로 하위는 사라지고 상위가 **같은 활성 칸 또는 보관 위치**에 들어간다 — `Unit.TryReplaceRewardCode`.
같은 코드가 여러 장이면 활성·보관 위치와 축전기 저장량을 보고 한 장을 선택한다. 선택지는 8장씩 페이지로 나누고 취득층도 표시하며, 선택한 인스턴스의 GUID·저장량·취득 스테이지를 보존한다. 게임 API도 승급 사다리 및 조화의 문장 허용 목록을 검증한다.
인장은 인벤토리에서 준비 페이즈에만 쓴다 — 아군 → 올릴 코드 → (조화의 문장이면) 바꿀 T2 순으로 고른다(`RewardCodeFlow.StartSeal`, `GameManager.UseSeal`).
이미 대응 T2를 가진 유닛의 T1은 올릴 수 없고, 인장의 최대 티어를 넘는 상위도 못 올린다.

## 3. 코드 태그

**유닛의 `archetypeTags`와 같은 키를 쓴다.** 코드 카드의 태그 칩이 유닛 카드의 태그 칩과 같은 아이콘이므로
"이 태그를 가진 유닛에게 주면 된다"가 그림으로 읽힌다. 한 코드에 태그는 1~2개.

| 키 | 표시 | 코드에서의 뜻 | 신규 |
| --- | --- | --- | :-: |
| `Universal` | **범용** | 누구에게 줘도 손해가 없다. 기본 스탯 · 생존 | ✔ |
| `Economy` | **경제** | 전투 밖 자원(골드 · EXP)을 늘린다 | ✔ |
| `Burst` | 방출 | 마나 효율 · 궁극기 피해. 방출 유닛(초월기가 핵심인 유닛)이 잘 받는다 | |
| `Precision` | 정밀 | 치명타 · 처형 · 단일 피해 조건 | |
| `FollowUp` | 연속 | 추가행동 | |
| `Swift` | 신속 | 속도 · 행동 빈도 | |
| `Support` | 지원 | 필드 오라 · 아군에게 주는 효과 | |
| `Control` | 제어 | 행동불능 대상 | |
| `Healing` | 치유 | 회복 | |
| `Shielding` | 방어 | 보호막 | |
| `Infusion` | 부여 | 원소 부착 · 원소 반응 | |
| `Sturdy` | 견고 | 방어 · 전열 · 대상 지정 | |
| `Counter` | 반격 | 반격 피해 | |
| `Summon` | 소환 | 소환수(피그말리온 포함) | |
| `Domination` | 지배 | 지속피해 · 해로운 상태 · 특수공격력 | |
| `Indomitable` | 불굴 | 체력을 자원으로 쓰거나 위기에서 강해진다 | |
| `Growth` | **성장** | 런 내내 쌓이는 **영구 중첩**을 늘린다 — [Detail_03 §3.1](Detail_03_Character.md) | ✔ (유닛 태그도 신설) |

키와 표시 이름의 원본은 `UnitTagCatalog`다(`Universal` · `Economy` · `Growth`를 이 체계에서 더했다). 코드의 태그는
`20_codes.yaml`의 `codeTags`에 적는다.

### 3.1 공격 형태

`Code.AttackForm`과 DamageTag의 50000번대는 베기·찌르기·사격·타격·주문이다. 접촉 여부와 소환 피해 표지는 별개다.
지속/반응/덧붙는 피해를 직접 공격 형태로 세지 않는다. `requiresAttackForm` 후보 제한은 실제 파티의 공격 선언을 조회한다.
상세 판정은 [02 전투](Detail_02_Combat.md)와 `Combat/AttackForms.cs`를 따른다.

### 4.6 소환·발상 연계

발상은 유닛별 중립 표식이다. 상한 없이 획득하되 코드의 효과량에 상한을 둔다. 정화·강화 해제로 제거되지 않고 전투 종료에 초기화한다. 궁극기 자원·영구 성장·축전량이 아니다. 실제 소환수의 소유·생성·사망은 `Summons` 경로를 쓰며 소유 개수에 피그말리온 자신은 포함하지 않는다. 필드 소환수 수·보호 장비에는 소환수 간주 아군도 포함한다. 개전 시 이미 생성된 소환도 한 번만 관찰한다. 동일 수혜자가 같은 코드를 중복 보유하지 않는 기존 규칙과 활성7칸을 따른다.

## 5. 보상 풀과 상점

### 5.1 보상 카드 한 장의 생성

`RewardManager.GenerateRewards(count, round, killedEnemyIds)`가 선택지를 만든다. 카드 장수는 기본 3장, 25스테이지마다 +1, 최대 6장이다.
분류 비율과 태그 · 상위 가중치의 원본은 `90_rewards.yaml`(`rewardCategoryWeights` · `codeTagWeights` · `upperCodeWeight`)이다.

```
카드 한 장마다
1. 라운드 티어 확률로 티어를 굴린다                         (Detail_13 §2, 현행 그대로)
2. 분류를 굴린다:  코드 55 · 소모품 30 · 적 드랍(식량 등) 15
3. 그 분류 · 그 티어의 후보 중에서 가중치로 고른다
     코드  — 태그 가중치: 파티 유닛 태그와 겹침 ×2 · 범용 ×1 · 그 밖 ×0.5, 상위 가중치 ×1.5
     소모품 — 써서 달라지는 것만(다친 아군이 없으면 치료 제외, 쓰러진 아군이 없으면 부활 제외)
     드랍  — 이번 전투에서 처치한 적의 드랍표 + 공용 드랍
4. 후보가 없으면 같은 티어의 다른 분류(무작위 순) → 가까운 티어(전 분류) 순으로 물러난다
선택지가 다 차면
5. 코드가 한 장도 없고 코드 후보가 남아 있으면, 무작위 한 장을 가까운 티어의 코드로 바꾼다
```

| 분류 | 후보 |
| --- | --- |
| 코드 | 구현된 보상 코드(`RewardCodeFactory.IsImplemented`) 중 아래 후보 조건을 통과한 것 |
| 소모품 | `90_rewards.yaml`의 즉시 소모품(치료 · 부활 · 사탕 · 운명의 주사위 · 경험의 서 · 휴식의 향로 · 경험의 서 상권) + `40_items.yaml`에서 `rewardPool: true`인 비약 · 승급의 인장 · 넥타르 |
| 적 드랍 | `commonDropItemIds`(식량) + 처치한 적의 `drops`. 식량 · 귀중품 |

| 규칙 | 값 |
| --- | --- |
| 코드 보장 | 한 번의 보상 선택지 중 **최소 1장은 코드** (5단계) |
| 같은 선택지 안 중복 | 금지 (뽑힌 카드는 모든 분류의 풀에서 지운다) |
| 줄 곳이 없는 코드 | 파티 전원이 이미 가진 코드(또는 그 상위)는 후보에서 뺀다(`Unit.CanReceiveRewardCode`) |
| 대상이 없는 코드 | 공격 형태 코드는 그 형태 공격 보유자가, 성장 코드는 `Growth` 유닛이 파티에 있을 때만 후보 |
| 상위 코드 | 파티 누군가 하위를 갖고 있으면 가중치 ×1.5 |
| 리롤 | 보상 화면의 **다시 굴리기** 버튼이 리롤 티켓 1장을 쓰고 같은 장수로 선택지를 새로 만든다(`RewardManager.RerollRewards`). 티켓이 없으면 버튼이 숨는다. 처치 기록은 그대로 쓴다 — §6.2 운명의 주사위 |

> 태그 가중치가 시뮬레이션 우주의 "운명의 길" 역할을 한다. 파티 태그가 빌드 방향을 끌어당기지만
> 겹치지 않는 코드도 0.5로 남겨 빌드를 갈아탈 여지를 둔다.

**실측(하네스 `r12_core`, 라운드 5 · 3장 · 300세트):** 카드 분류 비율이 코드 약 62% · 소모품 약 29% · 드랍 약 7%였다. 굴린 비율(55 · 30 · 15)보다 코드가
높은 데에는 **최소 1장 코드 보장**도 작용한다. 모든 분류에 같은 티어 후보가 충분하다고 가정해도 3장 세트의 보장만으로 코드의 기대 비중은
`0.55 + 0.45³ / 3 = 약 58.0%`다. 드랍이 낮아지는 추가 원인은 후보가 없는 분류에서 다른 분류로 물러나는 규칙이다
(현재 드랍 식량은 T1~T2에만 있어, T3 이상을 굴리면 드랍이 물러난다).
모든 세트에 코드가 1장 이상 들어갔다. 티어별 후보 수가 적은 분류의 비율은 밸런싱 때 다시 본다.

### 5.2 상점 고정 재고

생존·정화 보완 코드와 §4.6 소환·발상 연계 코드를 고정 판매한다. 발명의 순간·과학 승리·옳은 마음은 상점 전용이며, 나머지 소환 연계 코드는 보상 추첨에서도 얻는다.

  보상으로 얻는 쪽이 늘 이득이어야 보상 선택이 의미 있다.

저장량은 유닛의 공통 영구 중첩이 아니라 **코드 한 장의 인스턴스**에 속한다. 활성·보관 전환, 아군 간 교환, 동일 코드끼리 교환, 런 저장·복원에서도 인스턴스 ID와 값이 함께 움직인다. 한 유닛이 같은 코드를 활성·보관에 각각 가지고 있어도 저장량은 독립적이다. 수치 원본은 `20_codes.yaml`의 `capacitorStat/PerCharge/Cap`이다.

판매는 상점 판매 탭에서 한 장씩 한다. `기본 판매가 × 취득 스테이지 × (1 + 저장량/상한)`이며 기본 판매가는 상점 코드의 기본 구매가 25%, 그 밖에는 `20 × 2^(티어−1)`이다. 완충 가격은 빈 코드의 2배다. 취득 시세를 고정해 후반 스테이지·무료 교환으로 판매가를 늘리는 경로를 막는다. 판매는 구매 횟수를 쓰지 않으며 **귀중품 전부 팔기**는 코드를 팔지 않는다.

개별 코드 저장은 v14에서 도입했다. 현재 형식 **v17**도 기존 활성/보관 ID 배열과 `activeRewardCodeInstances`, `storedRewardCodeInstances`의 `codeId/instanceId/charge/acquiredStage`, `nectarStats`를 보존한다. v12·v13은 코드에 0충전 새 식별자를 부여해 복원한다. v14→v15는 10라운드 테마 진행을 8라운드로 옮기며 코드 인스턴스·축전량·넥타르를 변경하지 않는다. v15→v16은 기본 슬롯의 표시 테마/위치를 보존하여 추가 휴식·고정보스가 있는 누적 진행 인덱스로 이관한다. v16→v17은 런 생명력만 폐지하고 코드 인스턴스와 취득 당시 시세는 바꾸지 않는다. 전투 전후 스냅샷도 같은 DTO를 쓴다.

### 지원 연계 정화의 공통 판정

서풍/굳건한 보루는 정화할 해당 디버프가 있어야 사용권을 소모한다. 서풍은 체력이 가득 찬 아군도 치유가 도달하면 적용하며, 회복량0인 무효 호출은 제외한다. 소유자의 TurnCount를 기준으로 다음 자기 턴 시작에 다시 사용할 수 있다. 추가·우선 추가·특수·초월 행동과 수혜자의 턴은 재사용을 초기화하지 않는다. 첫 정화가 발생한 실제 스케줄러 행동의 광역 대상은 함께 정화하되 대상별1회이며, 같은 턴의 다른 행동에는 적용하지 않는다. 스케줄러 밖의 직접 지원 호출은 단일 지원1회다. 두 코드의 제한은 독립이고 자기 자신도 아군에 포함한다. 적·벤치·사망 대상이나 다른 시전자 지원은 제외한다. 원소 부착은 디버프 상태가 아니므로 지우지 않는다. 제어 정화는 기절/빙결/에어본/속박 상태와 별도 행동불능 타이머를 함께 해제하며 비제어 정화는 제어를 남긴다. 두 코드는 상위 사다리 없이 기존 활성/보관/저장 규칙을 따른다. 의신의 가호(810)는 별개 코드다.

### 11.1 비밀과 지속피해

**비밀**은 적별 공유 중립 표식이며 최대50중첩이다. 정화·강화 해제로 지워지지 않으며 디버프 수에 포함하지 않는다. 전투 종료 시 사라진다.

- 장례식/은밀하게 위대하게는 살아서 필드에 있는 보유자의 아군이 적에게 지속피해를 성공적으로 부여하거나 기간을 갱신할 때 각각1/3중첩을 더한다. 동일 생성 계열은 파티 최고 하나만 적용한다. 실패·저항·단순 기간 경과는 획득하지 않는다.
- 피해망상은 아군이 적에게 실제 지속피해를 한 번 줄 때1중첩을 더한다. 자연·즉시 정산·독안 파열에 모두 적용한다. 0피해·분담 피해·처치된 대상은 제외한다. 여러 보유자가 있어도 한 타격에1회다. 해당 타격의 피해 계산이 끝난 뒤 추가하므로 새 중첩은 다음 타격부터 적용한다.
- 발푸르기스의 밤은 적 비밀1중첩당 아군 지속피해를2% 증가시킨다(최대+100%). 부여 당시가 아니라 실제 타격 시 평가하고, 원 시전자 보정·즉시 정산에도 한 번만 곱한다. 동일 오라 중복 보유로 곱하지 않는다.
- 의심암귀는 비밀1중첩당 적 공격력0.6%를 감소시킨다(최대30%). 특공에는 영향이 없다. 오라 보유자 사망·퇴장·코드 정지 시 캐시도 갱신한다.
- 하이볼티지는 적이 감전을 가진 동안 가하는 피해15%를 감소시킨다. 별도 디버프를 추가하지 않으며 감전 정화 즉시 끝난다. 동일 오라는 중복되지 않는다. 이후 소환된 적에게도 적용한다.
- 막말내뱉기는 보유자가 원 시전자인 지속피해에만 특방20% 무시를 적용한다. 직접 공격·일반 방어력에는 적용하지 않는다. 악몽의 +1턴은 죽음의 계약과 합쳐 +2턴이며 재부여마다 기간을 계속 늘리지는 않는다.
- 남의 고통은 나의 즐거움은 아군의 적 대상 실제 지속피해마다 보유자 마나2를 회복한다. 소유자 일반 차례 사이 최대5회이며 충전 효율을 따른다. 마나가 이미 가득 찼거나 실제로 늘지 않으면 횟수를 쓰지 않는다. 고유 중첩형 자원은 회복하지 않는다.

### 11.3 심장 제세동기

치명상 시 실제 사망 이벤트 전에 최대 체력30%로 복귀하고 **활성 인스턴스 한 장**을 소비한다. 보관함의 같은 코드는 그대로 남지만 자동 장착하지 않는다. 다른 코드의 상태·재사용 대기시간은 초기화하지 않는다. 복귀는 치유·처치·소환 사망·축전 충전 이벤트를 발생시키지 않는다. 소비된 인스턴스는 전투 후·런 저장/복원에도 돌아오지 않는다.

필드의 아스톨포 특성이 켜져 있으면25% 확률로 소비를 막는다. 여러 아스톨포가 있어도 판정은 한 번이다. 보존된 코드는 이후 치명상에서도 다시 발동할 수 있다. 비약 보존 규칙은 유지하며 일반 코드 제거·판매·인장 소비는 보존하지 않는다. 이 코드는 다른 런 영구 코드의 일회 소비 예외다.

## 12. 추가행동·정밀 보상

`FollowUpRewardCodes.cs`가 담당한다. 정밀은 보유자별 중립 표식 `reward_precision`, 상한20이며 전투 종료·사망의 상태 정리에서 초기화한다. 정화·강화 해제로 지우지 않으며 런 저장에 누적하지 않는다. 정밀(755)과 준비된 자(833)만 중첩을 생성한다. 승리의 찬가(658)·서사시환(913)은 스스로 정밀을 생성하지 않는다.

- 추가행동 완료는 `Additional`/`PriorityAdditional`만 센다. 비공격 추가행동도 정밀·에너지 바를 받으며 일반·특수·초월·취소된 예약은 제외한다.
- 서사시환 공격력은 실제 행동자의 추가행동 중에만 최종 공격력에 비례해 적용한다. 일반행동·특수행동이나 행동 종료 후 스탯에 남지 않는다. 치피는 실제 추가공격 태그에 적용하며 단일 여부는 별도 태그로 가린다. 소환자와 실제 행동자가 다르면 공격력 조건은 행동자 기준이다.
- 등대는 자기 추가행동 실행·완료 콜백에서 얻는 마나에만 기존 마나 효율과 곱해 적용한다. 기본적으로 마나를 생성하지 않으며 피격·다른 유닛의 행동·고유 중첩 자원은 제외한다.

- 정밀·준비된 자·에너지 바는 상점 전용. 나머지는 보상 추첨과 상점 양쪽에 등록한다. 상위 획득은 기존 활성/보관/슬롯·인장 규칙을 따른다.

### 13.1 공격 판정

단일은 `SingleTarget`이며 `AllTarget`/`MultiTarget`·지속피해·반응·분담·덧붙는 피해를 제외한다. 유언·사산 검은 여기에 `NormalAttack` 태그를 요구한다. 일반공격 태그를 함께 가진 반격/추가공격은 피해 효과를 받지만, 추가행동 자체가 일반행동 완료 마나를 만들지는 않는다. 시의 특수 멸참은 특수 공격이므로 유언·사산 검을 발동하지 않는다.

초월자의 시선은 실제 단일 일반공격을 명중시킨 일반행동 완료의 기본 마나에만 적용한다. 피격·처치·추가행동·특수행동의 마나와 상시형/고유 중첩 자원은 늘리지 않는다. 궁극의 각성은 실제 소비 마나를 추적하며, 무효 대상 취소·마나 미소비·강인도 격파로 환급하지 않는다. 한 초월기로 여러 적을 처치해도 한 번만 반환한다.

분배는 하나의 총량을 대상 수로 나눈 피해다. 현행 만종6/9타·월식 정산이 `DamageContext.IsDistributed`를 설정한다. 대상이 하나만 남아도 분배 기술이며, 일반 광역·바운스·나누는 치유에는 적용하지 않는다. 시의 만종3타는 단일 후속이므로 제외한다.

### 13.2 간파

간파는 적별 공유 중립 표식이다. 여러 정찰대 보유자가 부여한 중첩을 합하며, 정화·강화 해제로 제거하지 않는다. 3중첩은 즉시 소모하고 마지막 부여자 공격력120%의 고정 피해를 한 번 준다. 동시에 단일 공격으로 받는 피해+15%의 **간파: 노출**을 대상 일반행동2회 동안 부여한다. 노출은 별도 디버프로 공통 효과 명중/저항을 거치고 정화할 수 있으며, 갱신·비중첩이다. 폭발 고정 피해가 다시 간파를 쌓거나 노출의 단일 공격 배율을 받지는 않는다.

표식은 부여자가 사라져도 해당 적에게 남으며, 전투 종료 때 제거한다. 아군 정밀의 중첩·상한·서사시환 사다리는 유지한다.

### 13.3 소모·경제·저장

생명선과 은 식기는 실제 활성 코드 인스턴스를 소모하므로 다음 전투에도 자동 복구되지 않는다. 아스톨포의25% 소모 보존을 공통 경로로 적용한다. 보존됐다면 이후 유효한 새 피격/제어에도 다시 발동할 수 있고, 같은 콜백의 재귀 소모는 막는다. 생명선이 활성인 동안 공격력400% 보호막 능력은 우수한 방어의 개전 보호막 후보에도 포함되며, 생명선 소모 후에는 제외된다. 생명선은 이미 쓰러진 아군을 살리지 않으며 은 식기는 비제어 디버프를 지우지 않으며, 제어가 부여될 때 이미 발생한 집중 중단을 되돌리지 않는다.

약탈자의 영혼은 시 특성 멸참·천살성·당연한 운명의 명시적 처형 피해와 실제 사망을 함께 확인한다. 일반 처치·소환수 처치·강인도 가상 처치는 골드 중첩을 주지 않는다. 기존 골드 정산의 가산 전투 보너스로 합산한다.

저장은 현행v17 활성7칸·보관·인스턴스 GUID 구조를 유지한다. 새 보상 ID를 Factory에 연결하며 저장 DTO와 기존 ID는 바꾸지 않는다. 수치의 장기 밸런스는 🔸 조정 필요.

### 14.1 연계와 발동 단위

특수행동은 `Special`이고 Additional/PriorityAdditional과 구분한다. 수리야의 일반 피해 판정 특수행동도 Special 보상을 받으며, 아그니의 집중 포격은 실제 Additional이라 특수행동 피해 증가를 받지 않는다. 시의 독립 특수행동은 황금의 아이·반신·금강저·신성한 피·영광스러운 아침·망루의 대상이지만 묶음 개시나 연계 인원 보상은 만들지 않는다.

`SpecialAction.Batch`는 실제 예약한 참여자와 개시자를 고정한다. 죽음·제어로 나중에 취소된 예약도 원래 연계 인원에 포함하며 최대6명까지만 계수화한다. 묶음 도중 다시 여는 요청은 새 묶음을 만들지 않는다. 개시자 피해 강화와 방어 무시는 그 개시자 자신의 해당 묶음 특수행동에만 적용한다. 뭉치면 살고 흩어지면 죽는다는 같은 묶음 참여자인 보유자의 특수행동에만 적용한다.

푸짐한 보급은 남은 예약이 모두 해결되고 실제 완료가1회 이상 있었을 때 살아 있는 필드 참여자만 치유한다. 전투 종료 Reset·전부 취소는 회복하지 않는다. 신성한 피의 저항은 아군별1회이며 갱신으로 횟수가 합쳐지지 않고, 공통 효과 명중을 통과한 첫 해로운 상태를 확정 저항한다. 일반적인 효과 회피로 빗나간 부여에는 소비하지 않는다. 보호막은 공통 AddShield 규칙을 따른다. 재사용 대기는 보유자의 TurnCount로 세며 추가·특수행동으로 경과하지 않는다.

### 14.2 원소 부착 공격

원소 공명은 피해 컨텍스트의 명시적 부착 시도 `AppliesElement`를 확인한다. 고유 원소가 있다는 이유로 모든 공격을 강화하지 않는다. 실제 부착 판정은 타격 후 공통 명중·반응 경로를 그대로 쓰므로 명중 실패나 치명타로 대상이 쓰러져 부착하지 못해도 그 본타는 강화된다. 수리야의 준비 사격에는 적용하지 않고 종언탄에는 적용한다. 잔은 원소가 없는 일반행동을 제외하고 얼음을 붙이는 반격에 적용한다. 이시스 수호병의 공격은 기존 소환자 명의와 부착 판정을 유지한다. 반응·지속피해·분담·보상 덧붙임 피해는 제외한다.

원소의 여운·순환 회로는 실제 성공한 적대 부착 이벤트만 센다. 광역·바운스·같은 원소 갱신도 보유자 턴 재사용 대기를 공유한다. 순환 회로와 빠른 집결은 마나 자원만 회복하고 고유 중첩을 생성하지 않는다. 개전 두 코드는 전투별 사용 표식을 남겨 재시전·교환으로 개전 보상을 복제하지 않는다.
