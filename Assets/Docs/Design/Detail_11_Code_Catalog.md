## 1. 읽는 법

### 1.1 분류는 서로 다른 네임스페이스다

`CodeFactory`는 passive / normal / ultimate를 **각각 따로** 조회한다.
그래서 **ID 숫자가 같아도 분류가 다르면 완전히 다른 코드**다.

예를 들어 오리온의 P·N·U는 모두 80이지만 셋 다 다른 클래스로 생성된다.
`164`는 패시브에서는 콜로세움 '챔피언의 여유', 궁극기에서는 레기온 '일제 투창'이다.

### 1.2 위력과 피해

```
피해 = 위력 × 시전자 스탯 × 0.2
```

'STR 기반 위력 80'은 주스탯 대신 STR을 쓴다는 뜻이다.
보호막도 같은 식으로 산출한다(`SkillDamage(위력, 스탯)`).

**위력은 두 형식 중 하나다.**

| 형식 | 표기 | 쓰는 곳 |
| --- | --- | --- |
| 고정 | `위력 80` | 대부분의 코드 |
| **고정값 + 스탯 비례** | `위력 50 + STR×0.2` | 로마 테마 전체 |

```
위력 = 고정값 + 시전자 스탯 × 계수      (Code.PowerStatCoefficient)
```

두 번째 형식은 **저점을 고정값으로 보장하고 고점을 억제한다.**
위력 자체가 스탯에 비례하면 최종 피해는 스탯의 제곱에 가깝게 자라므로,
계수를 작게(0.2~0.6) 잡으면 후반 폭주 없이 초반 화력만 확보된다.
`위력 DEX×0.6`처럼 고정값이 0인 형태는 순수 비례형이라 초반이 약한 대신 성장 폭이 크다.

### 1.3 표기

| 표기 | 뜻 |
| --- | --- |
| `<고유 패시브>` | 캐릭터당 1개. 코드 용량을 쓰지 않는다. 등급은 **보라색 `Unique`**로, 은·금 사다리 밖이라 대체하지도 대체당하지도 않는다 |
| `<전수 불가능>` | 서포터 카드로 넘겨줄 수 없다. **모든 고유 패시브가 여기 해당한다** |
| `<강화 등급>` | 금색 코드. 같은 계열의 일반(은색) 등급을 대체하며, 둘을 함께 들면 일반 쪽이 발동하지 않는다 |
| `<장비 전용>` | 장비가 부여한다. 코드 용량을 쓰지 않고 장비를 벗으면 걷힌다 |
| `<적 전용>` | 적만 보유한다 |
| `<보스 전용>` | 그 유닛이 보스로 등장할 때만 붙는다 |
| `#물리` `#특수` `#접촉` `#비접촉` `#베기` `#찌르기` | 피해 태그 |
| 보유자 `—` | 현재 어떤 유닛도 참조하지 않는 사문 코드 |

### 1.4 신규 코드 등록

1. `20_codes.yaml`의 올바른 분류에 고유 ID와 표시 설명을 등록한다.
2. 코드 클래스를 만들고 `CodeFactory`의 같은 분류에 연결한다.
3. `10_units.yaml`(아군) 또는 `60_enemies.yaml`(적)의 `codes`·`levelPassives`에 연결한다.
4. 이 문서를 갱신한다. 절차 전문은 [Detail_12 §6](Detail_12_Code_Weapon_Catalog.md)을 본다.

### 1.5 ID 배치 규칙

**ID는 계열이 정한다.** 슬롯마다 네임스페이스가 다르므로 배치도 슬롯별로 본다.

| 구간 | 무엇이 들어가는가 | 규칙 |
| --- | --- | --- |
| 1~199 | 아군 일반·궁극기 / 공용 해금 패시브 | **아군 일반·궁극기는 소유 유닛 ID와 같은 번호**(화령 블록이 180~199를 쓰면서 1~179에서 넓어졌다). 패시브 쪽 1~179는 여러 유닛이 나눠 쓰는 공용 해금 |
| 180~199 | 데이터가 가리키지 않는 패시브 | 참조가 끊긴 사문 코드와, YAML 대신 **코드에서 직접 부르는** 것(팔랑크스 183)을 모아 둔다 |
| 200~399 | 아군 고유 패시브 | **소유 유닛 ID + 200**. 화령 블록(180~199)이 380~399를 채워 구간이 꽉 찼다 |
| 400~499 | 장비 전용 패시브 | `codeGrants`가 실어 나른다. 코드 용량을 쓰지 않는다 |
| 500~599 | 소환수 일반·궁극기 | 칸을 차지하지 않는 종속 유닛의 코드. 플라이어 500, 펜리르 501, 분신 502 |
| 900~999 | 사문 일반·궁극기 | 패시브의 180~199에 대응한다 |
| 1000~1099 | 적 공용 | 병종 공용 성장 패시브·일반행동 |
| 1100~1199 | 콜로세움 | |
| 1200~1299 | 로마 군단 | |
| 1300~1399 | 메히코 | |
| 1400~1499 | 아스완 · 범용 사도 | 아스완 1400~1411, 테마에 묶이지 않는 **범용 거인·씨앗** 1420~1436 |
| 1500~1599 | **공허 계열** | 병종마다 10칸씩 — 프리즘 1500 · 괴조 1510 · 멧돼지 1520 · 늑대 1530 · 사슴 1540 · 기사 1550 · 사수 1560 · 선봉대 1570 · 분쇄자 1580 · 용 1590. 궁극기는 원소 변형 8개가 그 10칸을 채운다 |
| 1600~1699 | 노르드 | 광전사 1600 · 볼바 1610 · 토르 1620 · 발키리 1630 |
| 1700~1799 | **일본 천공 전선** | 공용 1700 · 등불나방 1710 · 고치 1720 · 나비 1730 · 포식자 1740 · 종말의 포식자 1750 · 천공의 포식자 1760 · 결정 1770. 세 슬롯이 같은 10칸을 나눠 쓴다 |
| 1800~1899 | **일본 해안 전선** | 공용 1800 · 돌격대장 1810 · 선봉대장 1820 · 사냥꾼 1830 · 공포 1840 · 집정관 1850. 세 슬롯이 같은 10칸을 나눠 쓴다 |

**아군 코드는 유닛 ID만 알면 찾을 수 있다.** 오리온(22)의 일반행동과 궁극기는 둘 다 22,
고유 패시브는 222다. 세 슬롯이 서로 다른 네임스페이스라 같은 숫자를 겹쳐 쓸 수 있다.

> **적 코드는 `CodeFactory`가 구간으로 한꺼번에 받는다.**
> `>= 1200 and <= 1211 => new LegionNormal(context, (LegionNormalStyle)(codeId - 1200))`처럼
> **ID 간격이 그대로 색인**이다. 그래서 적 계열은 블록 안에서 간격까지 유지한 채 옮겼다.
> 새 적 코드를 계열 중간에 끼워 넣으면 그 뒤가 전부 밀리니, 반드시 계열 끝에 붙인다.

로마 3인(아그리파·옥타비아·카이사르)은 레기온 적과 구현을 공유하지만 코드는 아군 규칙을
따른다. `CodeFactory`에 제 몫의 분기가 있고, 거기서 `LegionNormalStyle.Agrippa` 같은
이름으로 스타일을 직접 건넨다 — 예전처럼 적 구간의 ID 간격에 얹혀 있지 않다.

캐릭터 ID의 소속별 블록은 [Detail_03 §7.4](Detail_03_Character.md)를 본다.

302·303은 프레이아(244)와 같은 **치유형 일반행동**이라 적 타겟팅 흐름을 쓰지 않는다.
307·308은 한 클래스의 두 모드다. 예약으로 들어오는 강화형은 같은 인스턴스가 한 번만
강화 모드로 도는 방식이라 큐에 코드가 두 벌 올라가지 않는다.

**출혈은 계열 공용 상태다.** `Effects.Negative.BleedStatus`(상태 5930, 키 `bleed`)가 하나만 있고
**턴당 최대 체력 비율만 부여자가 정한다** — 사령의 발톱 1%, 공허 계열 3%. 예전에는 아스완과
공허의 괴조가 이름만 같고 상태 ID가 달라, "출혈을 부여하면"을 조건으로 거는 코드가 어느 쪽을
봐야 할지 알 수 없었다. 재부여는 지속시간만 늘리므로 먼저 걸린 쪽의 비율이 남는다.
`BleedStatus.Applied` 이벤트가 부여 순간을 알리며, 공허의 늑대 `피 냄새`(1530)가 이를 구독한다.

**출혈의 명중 판정은 부여하는 코드가 정한다.** 사령의 발톱은 시전자의 `LUK+DEX`와 대상의
`CON`을 겨루고(`AswanCombat.BleedHitChance`), 공허 계열은 시전자의 `LUK%`를 그대로 쓴다.
화상·제어가 `CON` vs `CON`인 것과는 다르다.
상태 ID는 5930이며, 콜로세움의 '열상'(6261)과는 별개다 — 저쪽은 시전자 공격력 비례,
이쪽은 대상 최대 체력의 1%다.
