## 1. UI 화면 구성

### 1.0 화이트 아카이브 구조 개편 (2026-09-19)

- 로비는 좌측 대형 캐릭터 스탠딩, 우측 여정 선택 카드로 나눈다. 이어하기가 있으면 첫 행동으로 강조한다.
- 편성은 좌측 쇼케이스 / 우측 로스터 / 하단 출전 파티, 준비는 중앙 전장 / 상단 통합 정보 / 하단 행동 바로 역할을 나눈다.
- 전장은 불투명한 사각 카드 대신 캐릭터 원화와 얕은 이름 받침, 체력·행동·궁극기 표시를 사용한다.
- 넓은 관리 화면은 안전 영역 내 95% 작업 공간으로 확장한다. 단순 확인 창은 작은 모달을 유지한다.
- `UISafeArea`로 로비·모달·HUD·준비바의 기기 안전 영역을 반영한다. 배경은 전체 화면이다.
- 가로 양방향 회전을 사용한다. 전장 포인터는 마우스와 기본 터치를 통합하며, UI 위 드롭·취소 터치는 원위치로 돌린다.
- 툴팁은 마우스 호버와 터치 길게 누르기(0.55초)를 지원한다. 긴 내용은 임의로 잘라 버리지 않는다.
- 마우스 호버 툴팁은 우상단 원형 게이지가 0.85초 동안 차면 그 자리에 고정된다. 고정 전에는
  레이캐스트를 받지 않고, 고정 뒤에만 패널 안으로 포인터가 들어갈 수 있다. 캐릭터 툴팁의 전투 성향
  `[아이콘 | 태그]` 칩에 마우스를 올리면 설명을 보조 툴팁으로 띄운다.
- 전투 성향 아이콘은 `Sprite/UI/UnitTags/`의 무채색 흰색 알파 마스크다. 선택 화면에서는 액센트,
  다른 UI에서는 해당 문맥의 색을 `Image.color`로 입힌다.
- 한글 UI는 `Maplestory Light SDF`를 기본으로 쓰며 Bold 스타일은 별도 Bold SDF에 연결한다. 누락 글리프는 `NotoSansKR-Regular SDF`로 폴백하고, UGUI와 월드 TMP의 Distance Field 재질은 분리한다.
- 빠른 마우스 드래그는 Input System의 실제 누름·놓음 이벤트 좌표를 기록한다. 이전 프레임 좌표나 이동량으로 시작점을 추정하지 않는다.
- 에디터 `Tools/NeverTheLast/UI Review`: `Ctrl+Shift+F5`는 사용자 저장이 격리된 새 여정,
  `Ctrl+Alt+F12`는 `Logs/UIReview/` 화면 캡처다. 16:9·19.5:9·4:3 Game View 프리셋도 제공한다.
- 🔸 실제 모바일 기기의 터치·노치·성능 검증은 별도 필요하다. 에디터 화면비 점검이 이를 대체하지 않는다.

**2026-09-19 직접 검증:** Unity Play Mode에서 1920×1080 및 1440×1080 화면을 확인했다.
수르트·사바흐 추천 편성, 기술 보기, 준비/배치 전환, 상점 탭, 훈련→결과→전투를 조작했다.
사바흐는 보상 선택 후 1-2 진입, 최종 통합본의 수르트는 실제 자리 교환·복원과 1-1 승리/결과 화면까지 확인했다.
테스트 여정은 `DebugMode.BeginSession()`으로 사용자 저장에서 분리했다. 이는 장기 밸런스 검증이나 실기기 QA 결과가 아니다.

| 일시정지 메뉴의 나가기 셋 차이를 모름 | 이름에 결과를 적고 버튼 오른쪽에 한 줄 설명 | `PauseMenuScreen` |

**ESC는 가장 위의 창부터 닫는다.** `ModalScreen.TryEscapeTop`이 떠 있는 모달 중 정렬 순서가 가장 높은 것에
ESC를 넘긴다. 배경으로 닫히는 창(상점 · 스킬 · 메뉴 · 자료실)은 ESC로도 닫히고, 확인 창은 취소, 훈련은
돌아가기다. 진행을 막는 창(보상 · 사건 · 전투 결과)은 받지 않으므로 ESC가 평소처럼 메뉴를 연다.
TAB 캐릭터 창이 떠 있으면 그 아래 층 창은 건드리지 않는다(§1.5-A). 창이 없고 덱 구성 모드가 켜져 있으면 모드를 끈다.

### 1.1-C 준비 페이즈 바

안전 영역 가로폭의 95%, 높이 172px(1080p 기준), 하단 24px의 커맨드 바다.
상태·육성 자원을 상단 한 줄에, 여섯 행동을 하단 한 줄에 배치한다. 전투 시작은 가장 넓은 틸색 버튼이다.

| 줄 | 내용 |
| --- | --- |
| 머리 | `PREPARATION / COMMAND` 눈썹 · `작전 준비` 제목 · **상태 칩**(준비 행동 1회 남음 / 준비 행동 완료 / 보스전 · 훈련 불가 / 중량 초과) · 안내문 · 훈련 체력 · 컨디션 · 스킬 Pt · 트레이닝 노트(걸려 있을 때) · 강화제 |
| 커맨드 독 | `ACTION · 준비 행동 1회` [훈련][휴식] ｜ `UTILITY · 관리` [상점][스킬] ｜ `FORMATION · 편성` [덱 구성] ｜ 제목·`STAGE R-S`·화살표를 따로 조판한 큰 [전투 시작] CTA |

버튼마다 이름 아래 상태 한 줄이 붙는다 — 훈련 `체력 N`, 휴식 `체력 +50`, 상점 `구매 N회 남음`,
스킬 `습득 가능 N`(민트) 또는 `Pt N`, 덱 구성 `배치 바꾸기` / 켜지면 [완료] `모드 끄기`, 전투 시작 `R-S`(보스면 `· 보스`).
꺼진 이유가 버튼 위에 있으므로 윗줄 문장을 읽지 않아도 된다.

### 1.1-D 전투 결과 화면 (BattleResultScreen)

모든 전투(사건 안 전투 포함)가 끝나면 뜬다. **확인(Enter · Space · 클릭)을 눌러야 다음으로 넘어간다.**
ESC로는 넘어가지 않는다 — 결과를 못 보고 지나치는 일을 막는 화면이다.

창보다 먼저 전장 위에 **판정 띠**가 1.4초 뜬다 — 글라스 띠에 `VICTORY 전투 승리` / `DEFEAT 전투 패배` /
`RUN TERMINATED 런 종료`. 누르거나 Enter · Space로 건너뛴다. 예전에는 마지막 적이 쓰러진 프레임에 창이 덮여
이긴 순간이 보이지 않았다.

| 자리 | 내용 |
| --- | --- |
| 판정 띠 | `MISSION COMPLETE` 작전 성공(민트) / `MISSION FAILED` 작전 실패(적색) / `RUN TERMINATED` 런 종료. 이유 한 줄(적 전멸 · 턴 초과 · 아군 전멸) · 스테이지 `R-S`와 테마 |
| 칸 넷 | 목숨(줄었으면 `18 → 14` 적색 강조, 차이와 남은 적 수) · 골드(처치 + 승리 보수) · 경험치 · 처치(토큰 획득) |
| 딜 그래프 | 출전한 아군을 딜량 순으로 한 줄씩 — 초상화 · 이름 · 막대(1등 기준 길이, 1등만 금색) · 딜량과 비중(%). 쓰러진 사람은 어둡게 + `전투 불능`. 머리에 합계와 `전원 생존` / `전투 불능 N명` |
| 버튼 | 승리 `보상 선택` · 패배 `다음 스테이지` · 런 종료 `메인 메뉴로` |
| 전투 로그 | `전투 로그` 버튼(또는 L)이 **전투 로그 창**(`CombatLogScreen`)을 연다. 아래 참고 |

값은 `GameManager`가 모은다 — 전투 시작 때 목숨 · 골드 · 누적 처치와 출전 파티를 적어 두고(`CaptureBattleStart`),
끝나면 **필드 복원 전에** 쓰러진 사람을 센 뒤(`BeginBattleResult`), 보수 지급이 끝나고 차이를 채운다(`FinishBattleResult`).
전투 불능이 된 아군은 전투 뒤 필드 복원으로 **전투 시작 때의 체력으로 돌아온다**(§4.5).

딜량은 `Combat.DamageMeter`가 센다. `Unit.AnyDamageDealt`에서 **방어막과 체력에서 실제로 깎인 양**만 받고,
소환수의 피해는 소환자 몫, 아군이 아군에게 준 피해는 제외한다. 전투 중에는 우측 **딜 그래프**
(`HUD/DamageMeterPanel`, 행동 순서와 마주 보는 자리)가 같은 값을 0.2초마다 다시 그린다.
사건 전투도 `CaptureBattleStart`를 거쳐 지난 판의 값이 남지 않는다.

**전투 로그 창** — 자동 전투라 플레이어가 고칠 수 있는 것은 편성뿐인데, 왜 졌는지 모르면 무엇을 고칠지도 모른다.
위쪽 **원인 요약**이 먼저 답한다: 끝난 이유 · 쓰러진 아군(턴 · 누구의 공격) · 아군에게 가장 많이 넣은 적(비중) ·
가장 많이 맞은 아군. 아래에 전체 기록이 턴 순서로 흐르고 탭으로 거른다 — **주요**(기본: 쓰러짐 · 궁극기 ·
최대 체력 30% 이상 한 방 · 시작/종료) · 전체 · 행동 · 피해 · 쓰러짐/반응/상태. 줄 색은 주인공 진영(아군 민트 · 적 적색).
기록은 `Combat.CombatLog`가 기존 전역 이벤트(`ActionScheduler.AnyActionStarted` · `Unit.AnyDamageDealt` ·
`AnyUnitDied` · `AnyElementalReaction` · `AnyHitNullified` · `AnyEvaded` · `AnyNegativeStatusGranted`)를
듣기만 해서 모은다. 한 판 3,000줄이 상한이고 넘치면 앞부분부터 버린다(원인은 대개 끝에 있다).
로그 창이 떠 있는 동안 Enter는 결과 화면을 넘기지 않는다. ESC · 바깥 클릭으로 닫는다.

목숨이 0이 되면 같은 화면이 런 종료를 알리고 메인 메뉴로 보낸다. 예전에는 아무 화면 없이 멈췄다.
자동 검증 도구(`DebugMode.SuiteRunning`)가 도는 동안에는 화면 없이 곧바로 넘어간다.

### 1.1-E 설정 창

왼쪽 레일에 탭 셋, 오른쪽에 줄마다 [이름 + 한 줄 설명 | 조작]. 선택지가 많으면 `‹ 값 ›` 스테퍼, 2~3개면 한 줄 세그먼트.

| 탭 | 항목 | 값 | 적용 |
| --- | --- | --- | --- |
| 화면 | 표시 방식 | 테두리 없는 전체 화면 · 전체 화면(윈도우에서만 독점) · 창 모드 | **[적용]** 뒤 12초 안에 [유지]를 안 누르거나 설정 창을 닫으면 되돌린다 |
| | 해상도 | 모니터 목록(1280×720 이상, 주사율 중복 제거) + 흔한 창 크기 | 위와 같음 |
| | 수직 동기화 | 끔 · 켬 | 즉시 |
| | 프레임 제한 | 30 · 60 · 120 · 144 · 240 · 제한 없음 (수직 동기화가 켜져 있으면 꺼짐) | 즉시 |
| 인터페이스 | 글자 크기 | ×1 · ×1.15 · ×1.3 (§1.3) | 즉시, 숨은 화면까지 |
| | HUD 크기 | ×0.9 · ×1 · ×1.15 — 상단 바 · 행동 순서 · 준비 바 · 툴팁 캔버스만. 전장 카메라가 비워 두는 픽셀(§1.9)도 같이 커진다 | 즉시 |
| 소리 | 음악 · 효과음 | 0~100 | 즉시 |

값은 `SettingsManager`가 PlayerPrefs에 둔다. 매니저는 첫 씬 로드 직후 스스로 생기며(`RuntimeInitializeOnLoadMethod`),
저장된 화면 설정이 있으면 그때 적용한다(에디터에서는 적용하지 않는다). [유지] 전 시험 적용값은 저장하지 않아 강제 종료 뒤에도 마지막 확정값을 복원한다. 플레이어 설정의 창 크기 조절(`resizableWindow`)을 켰다 —
창 크기가 바뀌면 전장 카메라가 다시 맞춘다. HUD 크기 1.15를 넘기면 1080p에서 상단 자원 띠와 우상단 바가 겹치므로 상한으로 둔다.

### 1.5-A ESC 메뉴와 TAB 창의 분리

두 창은 **따로 열리고 따로 닫힌다.**

| | ESC 메뉴 | TAB 캐릭터 창 |
| --- | --- | --- |
| 여는 입력 | ESC · 우상단 ≡ (같은 입력, `UIManager.HandleEscape`) | TAB · 우상단 인벤 버튼 |
| 닫는 입력 | ESC · ≡ · 계속하기 · 바깥 클릭 | TAB · × · 바깥 클릭 |
| 내용 | 설정 · 자료실 · 저장/불러오기 · 나가기 | 장비 · 캐릭터 시트 · 코드 |

**ESC가 위다.** 캐릭터 창이 떠 있을 때 ESC를 누르면 캐릭터 창을 닫지 않고 **그 위에** 메뉴가 뜬다.
메뉴를 닫으면 캐릭터 창이 그대로 남아 있다. 메뉴가 떠 있는 동안 TAB은 무시한다.
ESC는 메뉴 묶음 안에서 가장 위의 것 하나만 닫는다(설정 → 자료실 → 메뉴).

캔버스 층은 `UITheme.Layer*` 상수 한 곳에서 정한다.

| 층 | 정렬 |
| --- | --- |
| 진행 모달(보상 · 상점 · 캐릭터 선택 …) | 70~80 |
| TAB 캐릭터 창 | 120 |
| ESC 메뉴 | 130 |
| 자료실 | 133 |
| 설정 | 136 |
| 확인 창 | 140 |

**나가기 세 갈래** — 메뉴 안에서 `나가기` 머리글 아래 따로 묶는다. 이름에 결과를 적고, 버튼 오른쪽에 한 줄 설명을 붙인다.
예전 이름(저장 후 나가기 · 나가기 · 바탕화면으로 나가기)은 무엇이 저장되고 어디로 가는지 갈리지 않았다(QA).

| 버튼 | 설명 줄 | 저장 | 도착 |
| --- | --- | --- | --- |
| 저장하고 메인 메뉴로 | 이어하기로 여기서 계속 | 저장한다 (`CanSaveNow`일 때만 켜짐) | 메인 메뉴 |
| 저장 없이 메인 메뉴로 | 마지막 저장 이후는 사라짐 | 하지 않는다 | 메인 메뉴 |
| 게임 종료 | 저장하지 않고 끔 | 하지 않는다 | 게임 종료 |

셋 다 확인 창을 거친다. `게임 종료`가 몰래 저장하지 않는 것은 의도다 — "그냥 끄기"를 고른
사람의 저장본을 덮어쓰면 안 된다. 저장이 필요하면 `저장` 또는 `저장하고 메인 메뉴로`를 먼저 쓴다.

### 1.5 TAB 화면 — 캐릭터 창 (CodexScreen)

발더스 게이트 3 인벤토리 화면을 레퍼런스로 삼는다. **지금 파티의 상태만 다룬다** — 런과 무관한
참고 자료(전체 캐릭터·코드·장비·적, 추천 조합)는 §1.5-B 자료실이 맡는다.

```
┌───────────────────────────────────────────────────────────┐
│  캐릭터명                              중량            ✕   │
├──────────┬──────────────────────────────┬─────────────────┤
│ 파티 목록 │ [장비][캐릭터 시트][코드]     │  선택 항목 상세  │
│          ├──────────────────────────────┤                 │
│  캐릭터1  │ STR  DEX  CON  INT  LUK      │  아이템 설명     │
│  캐릭터2  │  14   24★  13   10   22◆     │  또는           │
│  캐릭터3  │──────────────────────────────│  캐릭터 요약     │
│          │  소유 아이템 격자 / 시트      │                 │
└──────────┴──────────────────────────────┴─────────────────┘
```

**항상 열 수 있다** — `BattleHud.Update`가 매 프레임 TAB을 검사하며, 캔버스 정렬 순서가 120이라
보상·사건 같은 모달(80)보다 위에 뜬다. 어느 페이즈에서든 아이템 보유자와 장착을 지정할 수 있다.
단 ESC 메뉴(130)보다는 아래다 — §1.5-A.

**장비 인형의 빈 칸.** 아무것도 없는 칸(장착 슬롯 · 보관함)은 **안쪽이 투명하고 짙은 테두리(2px)만** 둘렀다 —
밝은 테마에서 15% 농도의 옅은 선이던 예전 빈 칸은 채워진 칸과 잘 갈리지 않았다. **양손 무기**(둔기 · 장창 · 대검 등)를
주무기로 들면 보조 슬롯은 쓸 수 없으므로 테두리 빈 칸이 아니라 **회색 면**으로 꺼 두고 `양손`이라 적으며,
무엇도 놓이지 않는다(드롭 대상을 달지 않는다).
경험치 막대와 인형 사이에는 **16px 여백**(`DollTopGap`)을 두고, 초상화는 좌우 슬롯 줄의 한가운데에 선다.

**장비 끌기는 그림이 따라온다.** 끌고 있는 동안 커서를 따르는 것은 이름 상자가 아니라 **장비 그림 자체**다
(`UIDragSource.Icon`, 64px, 살짝 투명). 그림이 없는 물건만 이름표로 물러난다.

**주스탯 스트립** — 레퍼런스의 `근접 +N / 명중 보너스 / 피해` 줄 자리에 **5주스탯**을 놓는다.
주스탯은 ★, 부스탯은 ◆로 표시하고 민트로 강조한다. 소유 아이템 격자 바로 위에 항상 보인다.

**캐릭터 시트 탭** — 네 구획을 순서대로 쌓는다.

| 순서 | 내용 |
| --- | --- |
| 1. 기초 스탯 | STR / DEX / CON / INT / LUK |
| 2. 상세 스탯 | 체력, 방어력, 내구, 위력 100 기준 피해, 치명타(확률·배율), 행동 속도, 마나 효율 |
| 3. 육성 | 육성 Lv, 중량 `현재 / 한도`, 보유 코드 수 |
| 4. 상태 | 지금 걸려 있는 상태를 전투 카드와 **같은 아이콘**으로. 없으면 구획 자체가 빠진다 |

**코드는 별도 탭이다.** 고유 패시브·일반행동·특수행동·궁극기와 해금·전수·장비 코드를 한 목록에 놓고
등급(은·금·보라)으로 이름에 색을 준다. **코드 용량 한도는 폐지됐으므로 `보유 / 최대` 표기는 없다.**

**이름 아래에 한 줄 소개가 붙는다.** `20_codes.yaml`의 `description`을 `CodeCatalog`가 읽어,
`<고유 패시브>` 같은 꼬리표와 `#물리` 같은 피해 태그를 걷어 낸 문장을 최대 두 줄로 싣는다.
마우스를 올리면 전문 · 등급 · 꼬리표가 툴팁으로 뜬다. 코드가 많으면 칸 안에서 스크롤된다.

코드 인스턴스는 제 ID를 모르므로 `CodeFactory`가 만들 때 `Code.CatalogId`를 새긴다(슬롯별 네임스페이스라
조회는 슬롯과 함께). 팩토리를 거치지 않은 코드는 클래스 이름(`codeName`)으로 찾되, 한 클래스를
여러 항목이 나눠 쓰면 찾지 않는다. 표에서 빠진 코드는 빈칸 대신 `설명 없음 — 슬롯 #ID`가 찍힌다.

### 1.5-A2 미해금 캐릭터 표시

해금 조건이 남아 있는 캐릭터는 **선택 화면에 미해금 타일로 뜨고 조건 한 줄을 달고 있다.**
예전에는 라부아지에 한 명만 하드코딩돼 있었는데, 0.4.8에서 데이터 기반으로 일반화했다.

| 요소 | 위치 |
| --- | --- |
| 조건 문구 | `10_units.yaml`의 `unlockCondition` — 이 칸이 비어 있지 않은 유닛만 잠금 표시 대상이다 |
| 판정 | `CharacterSelectionManager.IsPendingUnlock` — 조건이 있고, 스타팅 해금도 육성 기록도 없을 때 참 |
| 표시 | `CharacterSelectScreen` — 타일 이름은 `미해금 · 이름`, 초상화는 어둡게, 본문은 조건 한 줄만 |

**코드에 캐릭터 이름을 적지 않는다.** 새 캐릭터에 해금 경로가 생기면 `unlockCondition` 한 줄을
더하는 것만으로 화면이 따라온다.

누적 수치로 열리는 조건은 계정 저장이 세고 있다 — `unlockAfterSummonCount`(소환),
`unlockAfterSingleTargetHits`(단일 피해), `unlockAfterShieldGrants`(방어막).
단일 피해는 한 전투에서만 수백 번 일어나므로 타격마다 저장하지 않고 메모리에 모았다가
라운드가 끝날 때 `SaveSystem.FlushUnlockCounters`가 한 번에 기록한다.

### 1.5-B 자료실 (WikiScreen)

ESC 메뉴의 `자료실`로 연다. 메뉴 위(정렬 133)에 뜨고, 메뉴가 이미 시간을 멈춰 두었으므로 따로 멈추지 않는다.
ESC는 **설정 → 자료실 → 메뉴** 순으로 한 겹씩 닫는다. 메뉴가 떠 있는 동안 TAB은 무시한다.

```
┌────────────────────────────────────────────────────────────┐
│ [캐릭터][코드][장비][적][용어]                  [검색____]  │
├──────────────┬─────────────────────────────────────────────┤
│ 그룹 머리     │  이름                                [초상화] │
│  항목   부제  │  한 줄 소개                                   │
│  항목   부제  │  ── 구획 ──                                  │
│  …  (스크롤) │  본문 (스크롤)                                │
└──────────────┴─────────────────────────────────────────────┘
```

| 갈래 | 목록(그룹) | 본문 | 원본 |
| --- | --- | --- | --- |
| 캐릭터 | 진영(유닛 ID 20칸 블록) | 기본 정보, Lv.1 스탯과 레벨당 성장, 고유·일반·특수·궁극 코드, 해금 패시브(Lv순), **추천 조합** | `10_units` · `20_codes` · `30_synergies` |
| 코드 | 공용 해금 · 공용 특수 · 고유 · 장비 부여 (ID 500 미만 패시브) | 효과, 꼬리표, 고유 주인 · 레벨로 배우는 캐릭터 · 부여 장비 | `20_codes` |
| 장비 | 부위, 귀중품은 맨 끝 (`enemyOnly` 제외) | 제원(툴팁과 같은 줄), 전용 캐릭터, 부여 코드 설명, 떨구는 적 | `40_items` · `60_enemies` |
| 적 | 적 테마(`80_stages`의 이름), 보스 → 정예 → 일반 | 기본 정보, 스탯, 코드, 전리품 | `60_enemies` · `80_stages` |
| 용어 | 기본 규칙 · **육성** · **원소 반응** · 역할군 · 조합 유형 | 규칙 문장 / 육성 문장 / 반응 한 건씩과 전체 표 / 역할군·조합 유형 설명과 해당 캐릭터 | 코드 상수 · `ElementalReaction.AllReactions()` · `30_synergies` |

**추천 조합은 TAB에서 자료실 캐릭터 본문으로 옮겼다.** 아래 구성은 그대로다.
기획 원본은 [Detail_15](Detail_15_Party_Synergy.md)다.

| 순서 | 내용 |
| --- | --- |
| 1. 역할 | 역할군 ID를 한국어 이름으로 풀어 나열 |
| 2. 기여 | 전투·육성 기여를 ●○ 눈금 5칸으로. 권장 열(전열/후열) 병기 |
| 3. 강점 | `provides[].text` 를 줄바꿈 되는 문단으로 |
| 4. 주의 | `caution`. 붉은색 |
| 5. 편성 | **메인 가능**이면 고점·대체 두 벌을 아키타입 이름과 함께. **서포트 전용**이면 이 캐릭터를 부르는 메인 목록 |

**아직 손에 넣지 못한 이름은 흐리게 찍는다**(`SynergyCatalog.IsAvailable`).

**육성**은 집중 훈련 · 체력과 실패 · 컨디션 · 서포트 카드 · 우정도와 우정 훈련 · 힌트와 전수
여섯 항목이다. 수치는 `TrainingManager`의 상수를 직접 읽어 찍으므로 상수를 고치면 화면도 따라간다.
기획 원본은 [Detail_04](Detail_04_Training.md)다.

**원소 반응**은 `ElementalReaction.AllReactions()`가 돌려주는 28쌍을 그대로 쓴다. 화면에 표를 다시
적지 않으므로 반응이 늘거나 이름이 바뀌면 자료실이 저절로 따라간다. 목록에는 반응 이름마다 한 항목이
서고(확산은 여섯 쌍이 한 항목), 맨 앞 `반응이란` 항목이 부착 · 세기 · 우선순위와 전체 표를 보여 준다.
기획 원본은 [Detail_16](Detail_16_Elements.md)다.
Support 유형은 언제나 편성 가능하므로 항상 밝게 나오고, Starter·Locked는 해금·육성 기록을 본다.
"지금 짤 수 있는 조합"과 "다 모으면 되는 조합"이 같은 화면에서 갈린다.
자료실 캐릭터 목록도 같은 판정으로 아직 못 얻은 캐릭터를 흐리게 `미해금`으로 찍는다 — 스포일러를 가리지는 않는다.

**데이터에 없는 문장은 '용어 › 기본 규칙' 여덟 항목뿐이다**(`WikiScreen.Rules`). 공식의 원본은
[Detail_02](Detail_02_Combat.md) · [Detail_03](Detail_03_Character.md)이며, 공식이 바뀌면 이 문장도 함께 고친다.

### 1.6 캐릭터 선택 화면

전체 화면형 편성 작업 공간이다. 좌측 약 40%는 **스탠딩 쇼케이스**와 역할·기술 설명,
우측 약 60%는 STEP 01/02 안내와 **5열 초상화 로스터**를 배치한다.
카드는 120px 상한이나 세 줄 맞춤 없이 가용 폭을 채우며, 이후 후보는 세로 스크롤한다. 하단에는 메인을 구별한
**5인 파티 레일**과 큰 다음/여정 시작 버튼을 고정한다. 추천 편성·시작 자격·기술 조회 규칙은 유지한다.

2026-09-21: 파티 레일을 108px로 줄이고, 메인 단계에서 비어 있던 추천 영역을 로스터에 돌려준다.
목록 안쪽에는 커서 테두리 및 스크롤 막대용 패딩을 둔다. 소개·태그·기술 보기 버튼은 서로 겹치지 않는

창 너비나 글자 배율이 바뀌면 본문 전체 높이를 다시 잰다.

**2026-09-21 직접 검증:** 저장 격리 Play Mode에서 1920×1080·1440×1080의 메인/서포터 화면,
첫 행 선택 테두리, 세이의 네 태그·긴 소개, 기술/요약 전환과 창 너비 변경, 추천 네 명 편성,
로스터 마지막 행까지 스크롤을 확인했다. Console 오류는 0건이었다.

칸 크기는 `SquareGridSizer`가 격자 영역의 실제 픽셀 크기에서 매번 다시 계산한다.
캔버스 스케일은 첫 프레임에 확정되지 않고 창 크기에 따라 또 바뀌므로 한 번만 재면 어긋난다.

```
│ 대형 스탠딩   │ STEP 01/02 · 선택 안내               │

│ 요약 / 기술   │ 추천 편성 · 다음 단계 안내             │
├──────────────┴──────────────────────────────────────┤
│ [메인] [서포트] [서포트] [서포트] [서포트]  [다음 →]  │
└─────────────────────────────────────────────────────┘
```

**미리보기 설명 — 요약.** 전투 성향 태그 → 한 줄 소개(`10_units.yaml`의 `tagline`) → 원소·주/부 스탯을 싣는다.
중복 운용 설명·입문 추천 문구/배지·스타터 등 편성 자격 문구는 표시하지 않는다. 미해금 캐릭터의 해금 조건만 남긴다.

**미리보기 설명 — 기술.** `기술 보기` 버튼(Q · 패드 Y)으로 전환한다. 초상화를 걷고 이름을 위로 올린 뒤,
남은 자리에 **고유 패시브 · 일반행동 · (특수행동) · 궁극기**를 `20_codes.yaml` 설명과 꼬리표로 싣고
끝에 해금 패시브를 `Lv.N 이름`으로만 나열한다(설명은 자료실). 넘치면 칸 안에서 스크롤된다.
코드 조판은 자료실과 같은 `CodeText.AppendBlock`이다. 전환 상태는 커서를 옮겨도 유지된다 —
여러 캐릭터의 기술을 견줘 보는 용도다.

**키보드 · 패드 조작** (`UINavInput`, 입력은 `UIManager.Update` → `CharacterSelectScreen.Tick`)

| 동작 | 키보드 | 패드 |
| --- | --- | --- |
| 커서 이동 | WASD · 방향키 | 십자키 · 왼쪽 스틱 |
| 타일 고르기/해제 · 버튼 누르기 | Space · Enter | A (South) |
| 요약 ↔ 기술 | Q | Y (North) |
| 메인 다시 고르기 | Backspace | B (East) |
| 다음 · 여정 시작 | (버튼 줄에서 결정) | Start |

커서(흰 테두리)는 격자와 아래 버튼 줄을 오간다. 맨 아랫줄에서 더 내리면 버튼 줄의 `다음`/`여정 시작`에
서고, 위로 올리면 격자로 돌아간다. 방향은 누르고 있으면 0.35초 뒤부터 반복된다. 마우스를 올린 타일로도
커서가 따라온다. **ESC는 쓰지 않는다** — 어느 화면에서든 인게임 메뉴가 받는다. 메뉴나 TAB 창이 떠 있으면
(`UIManager.IsOverlayOpen`) 입력을 읽지 않는다. 마우스로 누른 버튼이 EventSystem에 '선택'으로 남으면
Space·A가 그 버튼까지 눌러 두 번 처리되므로, 화면이 떠 있는 동안 선택을 매 프레임 비운다.

**서포터 추천.** 2단계에 들어서면 고른 메인의 추천 조합(`30_synergies.yaml` `recommendations`)으로
추천 서포터 넷을 정한다. **고점 조합(`best`)에서 지금 격자에 오른 사람을 먼저** 담고, 빈자리는
최초 로스터만 쓰는 대체 조합(`basic`)으로 채운다 — 해금이 덜 된 계정에서도 네 자리가 비지 않는다.
추천 타일에는 `★ 추천 N` 띠가 붙고, 요약 줄에 이름·조합명·이유의 첫 문장이 뜬다.
`★ 추천 편성`은 서포터 칸을 추천 넷으로 통째로 바꾼다. 메인은 건드리지 않는다.
무한 모드는 메인이 없으므로 추천도 없다.

**메인별 추천 편성.** 입문 추천 표시는 제거하되 서포터 자동 편성 기능은 유지한다. 수르트는 아그리파·프레이아·세이·스카디,
사바흐는 스카디·니콜·세이·프레이아가 추천 서포터로 표시되며 `★ 추천 편성`으로 한 번에 채울 수 있다.

**모드별 흐름**

| 모드 | 단계 |
| --- | --- |
| 육성 | 1단계 **메인 1명** → `다음` → 2단계 **서포터 카드 4명** → `여정 시작` |
| 무한 | 메인 단계 없이 **서포터 카드 5장**을 바로 고르고 `여정 시작` |

- 1단계 후보는 `canStartAsMain` 또는 해금된 캐릭터, 2단계 후보는 `canStartAsSupport`만 보여준다
- 메인 단계에서 다른 타일을 누르면 기존 선택을 갈아 끼운다(항상 1명)
- 이미 고른 타일을 다시 누르면 해제된다
- `뒤로`는 2단계에서만 보이며 누르면 편성을 비우고 1단계로 돌아간다

### 1.7 사건(VN) 진행 조작

| 버튼 | 동작 |
| --- | --- |
| `계속 ▸` | 대사 한 줄 진행 |
| `자동` | 켜면 일정 시간마다 스스로 다음 대사로 넘어간다. 다시 누르면 해제 |
| `건너뛰기 ▶▶` | 남은 대사를 전부 건너뛰고 선택지로(없으면 사건 종료로) 간다 |

자동 대기 시간 = `1.2초 + 글자 수 × 0.045초` (상한 6초).
긴 대사일수록 오래 머물러 읽을 시간이 남는다.

**선택지·결과 화면에서는 자동이 꺼지고 세 버튼이 모두 숨는다.** 선택은 플레이어가 해야 한다.

> 화면은 MonoBehaviour가 아니므로 타이머는 `UIManager.Update()`가 매 프레임 넘겨 준다.

### 1.8 전장 초상화 크기 정규화

초상화 원본 해상도가 제각각이다 — 아군 1254px, 적 512px, 일부 1024px.
`Cell`의 스프라이트 렌더러 배율을 고정해 두면 **아군은 칸을 넘치고 적은 칸의 절반만 채운다.**

`Cell.SetPortrait`가 긴 변을 `PortraitFitSize`(9.6, 칸 테두리 10.16보다 약간 안쪽)에 맞춰
균일 배율로 줄인다. 해상도와 무관하게 항상 칸에 꼭 맞고 비율도 유지된다.
드래그 미리보기도 같은 배율을 따른다.

### 1.9 전장 카메라 프레이밍

배치 상수를 바꿀 때마다 씬의 카메라를 손으로 옮기면 금방 어긋난다.
`GridManager.FrameCamera()`가 **실제로 만들어진 셀 좌표에서 경계를 구해** 그 중심에 카메라를 두고
`orthographicSize`를 잡는다. 전열/후열 간격이나 대기석 위치를 바꿔도 프레이밍이 따라온다.

**경계는 카드가 실제로 덮는 영역이다.** 칸 중심에서 위로 카드 반 변 + 궁극기 게이지(`UnitCardView.HudAbove`),
아래로 카드 반 변 + 체력 · 행동 · 상태 아이콘 줄(`HudBelow`, 카드 한 변의 32%)까지 넣는다. 보스 단독 편성은
가장 큰 카드 배율(`Cell.FeatureScale`)로 잰다. 가로로는 소환수 소형 카드가 걸치는 폭까지 넣는다.

**HUD는 픽셀로 비운다.** 예전에는 "전장 높이의 7% · 16%"처럼 전장에 비례해 여유를 줬는데, HUD는 전장과 무관한
고정 픽셀이라 인원이 늘어 전장이 커질수록 어긋났다 — 5대5에서 맨 아래 카드의 체력·상태 줄이 잘리고,
맨 위 적 카드가 상단 체력 띠 아래로 들어간 원인이다. 이제 아래 픽셀(1080p 기준)을 CanvasScaler와 같은 식
(`√(W/1920 × H/1080)`)으로 화면 비율로 바꿔 비우고, 남은 영역의 가운데에 전장을 둔다.

| 여유 | px | 이유 |
| --- | ---: | --- |
| `TopHudPixels` | 172 | 통합 상단 HUD · 엘리트 체력 띠 |
| `BottomHudPixelsPreparation` | 210 | 준비 커맨드 바(24 + 172) + 14 |
| `BottomHudPixelsBattle` | 28 | 전투 중에는 가장자리 여백만 |
| `SideHudPixels` | 240 | 228px 행동서열 패널 + 전장과의 12px 안전 간격 |

위 값에는 설정의 HUD 크기 배율이 곱해진다. 창 크기나 HUD 크기가 바뀌면 다시 맞춘다.

| 간격 | 값 | 이유 |
| --- | ---: | --- |
| `ColumnSpacing` | 13.2 | 카드(8.94) 사이에 소환수 소형 카드(3.75)가 들어갈 틈 |
| `SlotSpacing` | 12.8 | 카드 한 장의 세로 영역(게이지 포함 12.2)보다 커야 위아래 카드가 겹치지 않는다 |
| `BenchSpacing` | 11.6 | 대기석 카드는 HUD가 없다 |
| `BenchOffsetY` | 14.5 | 최하단 카드의 상태 아이콘 줄을 비킨다 |

**기본 준비/전투에서는 빈 슬롯과 대기석을 숨기고 실제 배치된 유닛을 프레이밍한다.**
덱 구성 모드일 때만 전체 슬롯과 대기석을 펼친다. 전투 시작 시 양 진영 경계를 보관해
사망할 때마다 카메라가 줌인하지 않으며, 화면비가 바뀌면 같은 경계로 다시 계산한다.

> 🔸 **씬에 저장된 범위가 구조를 깨뜨릴 수 있다.**
> `CalculateFieldCellPosition`은 |x|=1을 전열, 그 외를 후열로 보므로 x가 ±2를 넘으면
> 여러 x가 같은 좌표로 계산되어 셀이 겹쳐 쌓인다. 실제로 씬에 구 레이아웃 값
> (`xMin -3 / xMax 3 / yMax 3 / benchSize 9`)이 남아 x=−3과 −2가 포개져 있었다.
> `EnforceLayoutBounds()`가 진영당 2열 × 4행, 대기석 5칸으로 바로잡고 경고를 남긴다.

## 1.10 공격 연출 — 무기 분류별 유형

**공격 하나가 어떤 모양으로 보일지는 `Effects.AttackVisuals`가 혼자 정한다.**
피해 태그의 5만 번대(무기 분류)가 최우선이고, 태그가 없으면 **손에 든 무기**를 본다.
장비가 비어 있으면 `startingProficiencies`로 물러난다(적 유닛은 장비 없이 서기 때문이다).

| 유형 | 결정 조건 | 화면 |
| --- | --- | --- |
| **베기** `Slash` | `Slash` 태그, 또는 장검·대검·단검 | 대상 카드 위를 비스듬히 긋는 선 + 파편 |
| **찌르기** `Thrust` | `Pierce` 태그, 또는 장창·단창 | 공격 방향을 따라 들어왔다 빠지는 창 + 앞으로 뻗는 파편 |
| **타격** `Impact` | 물리인데 무기 분류가 없음(둔기·맨손·투척) | 방향 없는 충격 고리 두 겹 + 사방 파편 |
| **화살** `Arrow` | `Arrow` 태그, 또는 활·석궁 | 깃 달린 투사체가 포물선으로 날아감 |
| **마법·특수** `Bolt` | `Physical`이 없는 모든 공격 | 원소색 마름모가 직선으로 날아감 |

**근접이냐 투사체냐는 무기가 정한다.** 일반행동의 기본 태그가 비접촉이라 접촉 태그만 보면
검사도 창병도 빈손으로 빛을 쏘게 된다. 베기·찌르기는 언제나 대상 위에서 터지고,
화살·마법은 언제나 날아간다. 타격만 둘 다 된다 — 둔기를 들었거나 접촉 태그가 있으면 내려치고,
맨손 비접촉이면 **덩어리가 돌면서 날아가(`Thrown`)** 고리로 터진다.

> 예전에는 `SfxManager`가 "검 숙련이면 베기, 로마·메히코면 베기"라는 두 줄짜리 예외만 갖고
> 나머지를 전부 같은 빛덩이로 쐈다. 창병도 둔기병도 구분되지 않았다.

**색은 시전자의 원소색이다.** 카드의 궁극기 링과 같은 표(`ElementalProjectiles`)를 쓰므로
날아가는 색만 봐도 누가 쏜 것인지 읽힌다. 궁극기는 파스텔, **물리는 원소색을 30%만 강철로 물려**
마법과 갈라 둔다. 원소가 없는 유닛(None)의 물리는 그냥 강철색이다.

**투사체는 아트 에셋이 아니라 코드로 그린다.** `ProjectileShapes`가 마름모·잔광·고리·파편
스프라이트를 만들어 캐시하고, `CardProjectile`이 그것을 조립해 쏜다. 파티클을 뿌리는 대신
**또렷한 실루엣 하나**를 짧고 세게 쓰는 쪽이다.

**궤적은 두 가지만 쓴다.**

| 궤적 | 대상 | 계산 |
| --- | --- | --- |
| **직선형** `Linear` | 마법·특수 투사체, 접촉(근접) 물리 | `Lerp(start, end, t)` |
| **곡선형** `ParabolicArc` | 화살·투척 등 **원거리 물리** | `Lerp` + `4h·t(1−t)`, 최고 높이 5 |

선택은 `ProjectileFlight.PathFor(피해 태그)`가 한다 — `Physical`이면서 `ContactAttack`이 아니면 곡선형,
그 외에는 직선형이다. 접촉 물리를 뺀 이유는 붙어서 때리는 연출에 포물선을 씌우면
이펙트가 솟았다 내려와 타격감이 어긋나기 때문이다.

> 🔸 **나머지 경로 타입(Spiral·Wave·Bezier·MultiPoint·DelayedDrop)은 구현만 남기고 쓰지 않는다.**
> 이 게임은 XY 평면을 정사영으로 비추는데, 그 경로들은 오프셋을 **경로에 수직인 z축**으로 준다.
> Wave는 전량이 z라 화면에서 아무 변화가 없었고, Spiral은 절반만 y라 나선이 아니라 위아래 진동으로 보였다.
> 곡선형은 y를 직접 올리므로 2D에서 그대로 보인다.

**파일 위치** — `Scripts/Effects/`
(`AttackVisuals` 판정 · `MeleeVfx`의 찌르기/타격 · `CombatVfx`의 베기/에어본 · `CombatFeedback` 타격 반응)
`Scripts/Effects/Projectiles/`
(`CardProjectile` · `ProjectileShapes` · `ProjectilePathType` · `ProjectilePathData` · `ProjectileFlight`)
`HS_ProjectileCustomMover`는 이 프로젝트가 작성한 코드인데 벤더 폴더(`Hovl Studio/`)에 있었다.
에셋을 다시 임포트하면 덮어써질 자리라 Scripts로 옮겼다.

## 1.11 타격 피드백

전투가 자동으로 굴러가므로 **무엇이 얼마나 아팠는지**를 체력 바의 변화만으로 읽게 두면 놓친다.
피해가 정산된 자리(`Unit.DefaultTakeDamageEvent`)에서 `Effects.CombatFeedback`이 세 가지를 함께 친다.
하나만으로는 약하고, 셋이 같은 프레임에 겹쳐야 '맞았다'가 된다.

| 반응 | 내용 |
| --- | --- |
| **숫자** | 붕괴: 스타레일식(`DamagePopup`). 크게(1.75배) **찍혀 0.1초에 제 크기로 내려앉고**, 머물다 위로 떠오르며 마지막 3할에서 사라진다. **굵은 기울임체 + 어두운 외곽선**. 체력에 들어간 피해는 **원소색**, 방어막이 대신 받으면 방어막색, 회복은 `+N` 초록, 회피는 '회피', 횟수제 무적이 막으면 방어막색 '무효', 치명타는 **금색 + 1.32배**. 같은 카드에 0.55초 안에 또 뜨면 위로 한 단씩(최대 4단) 올리고 좌우로 번갈아 벌려 겹치지 않는다 |
| **카드** | 하얗게 번쩍이며 뒤로 밀리고, **물리 타격이면 떤다**(`UnitCardView.PlayHitReaction`). 마법은 떨지 않고 번쩍이기만 한다 |
| **화면** | 큰 한 방에만 아주 짧게 흔들린다(`CameraShake`) |
| **시간** | 치명타 · 궁극기 · 한 방이 큰 공격에서만 **30~50ms** 멈춘다(`HitStop`) |

**전투 자원은 카드 이름표에 붙는다**(`Combat.CombatResourceLabels`). 이름이 등록된 자원은 전부 띄우고
0이면 숨긴다 — 천공 전선의 `무적 N` · `발동까지 N` · `포만 N`, 해안 전선의 `구간 N/6`. 켜짐만 알리면 되는 자원은 숫자 없이 이름만 띄운다 — 해안의 `갑주` · `준비`. 이름이 없는 자원(가우디의 스택 등)은
예전처럼 첫 하나만 `◆현재/최대`로 띄운다. 소환체는 무적과 카운트다운을 **함께** 보여야 우선순위를 읽을 수 있어서다.

> 🔸 **숫자는 대상을 따라가고, 대상을 잃으면 화면 좌표에 못 박는다.**
> 생성 시점의 월드 좌표를 붙들고 있으면 허공에 숫자가 남는다 — 유닛이 쓰러지면 칸이 비고,
> 빈 칸이 지워지며 남은 카드가 가운데로 다시 모이고 카메라까지 다시 잡히기 때문이다.
> 실제로 전장 빈 자리에 433이 떠 있었다. 마지막 일격의 숫자를 지우지 않으려고
> **즉시 종료가 아니라 그때의 화면 좌표에 고정**하는 쪽을 택했다.

**멈춤(hit-stop)은 자격을 좁게 준다.** 잔매마다 서면 전투가 끊긴 것으로만 보인다.
치명타이거나, 궁극기이거나, 한 번에 최대 체력의 **55%** 이상을 깎았을 때만 선다.
멈춤 사이 최소 간격은 **0.12초**이고 길이는 **실시간**으로 재므로 8배속에서도 같은 길이다.
배속이 `Time.timeScale`이라(§1.2) 멈춤은 그 값을 기억했다가 되돌리며,
되돌릴 때 <b>우리가 넣어 둔 값이 그대로 남아 있을 때만</b> 손댄다.

**세기는 절대 피해량이 아니라 "최대 체력의 몇 할을 한 번에 잃었는가"로 잰다.** 같은 50이라도
레벨에 따라 뜻이 달라지기 때문이다. **22%**를 한 번에 깎으면 최대 세기가 되고, 숫자 크기도
같은 값을 따라 커진다. 지속피해는 때린 사람이 없으므로 떨림을 **35%**로 줄이고 화면은 흔들지 않는다.

**때리는 쪽도 움직인다.** 맞는 카드만 흔들리면 누가 쳤는지가 화면에서 사라진다.
일반행동은 **뒤로 뺐다가 앞으로 찍는 순간 발사**한다(`UnitCardView.OnCast` → `PlayAttackReaction`).
시전이 시작되면 카드가 **시전 시간(`CastingDelay`) 동안 뒤로 빠져 자세를 잡고**(0.5칸), 투사체·베기가 나가는
프레임에 앞으로 찍는다(근접 1.15, 원거리 0.8). 예전에는 시전 시작에 곧바로 찍고 0.5초 뒤에야 발사해
카드가 움직인 뒤 한참 있다가 투사체가 나가는 간격이 생겼다. 반동 신호를 내지 않는 공격(마법 일반행동)은
시전 시간이 끝난 직후 스스로 찍고, 시전자가 쓰러지거나 제어당하면 찍지 않고 자세만 푼다.
같은 발사의 중복 신호는 0.12초 안이면 무시한다 — 진행 중인 찍기가 되감겨 카드가 한 번 더 튀기 때문이다.
궁극기는 예전처럼 시작 즉시 찍는다.

> 🔸 **카메라 흔들림은 프레이밍과 싸우지 않는다.** 카메라 위치의 주인은 `GridManager.FrameCamera()`다.
> `CameraShake`는 매 프레임 **직전에 넣은 흔들림을 먼저 빼고** 기준 위치를 다시 읽으므로,
> 전투 중 빈 칸이 지워져 프레이밍이 다시 잡혀도 카메라가 옛 자리로 끌려가지 않는다.

**연출 점검** — Editor에서 `Tools/Combat VFX/Export Preview` (Ctrl+Alt+V)가 베기·찌르기·타격·에어본을
한 장의 PNG(`Temp/CombatVfxPreview.png`)로 굽는다. 플레이 모드에 들어가지 않고 모양만 확인할 때 쓴다.

## 1.12 전장 배경 — 테마 환경광

완전한 검정 배경은 카드 대비에 가장 유리하지만 **어디서 싸우는지**가 사라진다.
로마 군단도 공허 얼음도 같은 검은 방에서 싸우는 것처럼 보인다.

`Effects.BattlefieldBackdrop`이 카메라에 붙어 세 겹을 깐다. 모두 명도가 낮아 카드를 덮지 않는다.

| 겹 | 내용 |
| --- | --- |
| 하늘 | 위는 거의 검고 아래로 갈수록 테마 색이 밴다(최대 알파 0.30) |
| 바닥 | 아주 옅은 사선 빗금. 평면이 바닥으로 읽히게 하는 결이다(0.13) |
| 광원 | 전장 가운데의 넓고 부드러운 빛 웅덩이(0.18) |

색은 테마마다 `80_stages.yaml`의 `ambientColor`(#RRGGBB)가 정한다. 비워 두면 무채색 기본값이다.
아래쪽이 밝아지는 만큼 적 실루엣도 배경에서 떨어져 나온다.

> 🔸 **배경은 가장 아래 정렬 레이어에 둔다.** `sortingOrder`만 낮추면 카드가 다른 정렬 레이어를
> 쓸 때 배경이 카드를 덮는다. 카메라의 자식이라 프레이밍이 다시 잡혀도 따라온다.

### 1.2 전투 HUD

| 컴포넌트 | 표시 |
| --- | --- |
| `HUD/TopStatusBar.cs` | 생명력, 스테이지/라운드, 페이즈 타이머(원형 게이지 + 숫자) |
| `HUD/PartyPanel.cs` | 파티 유닛 상태 |
| `HUD/ActionQueuePanel.cs` | **행동 순서 큐** — 다음에 누가 움직이는지 |
| `HUD/BattleHud.cs` | 전투 화면 총괄 |

> 전투가 자동인 만큼, **"다음에 누가 움직이는가"를 항상 노출**하는 것이 관전 경험의 핵심이다.

**텍스트 대비 기준선은 4.5:1이다.** 가라앉은 면(`SurfaceSunken`) 위에서 실제 렌더링으로 다시 확인한다.

| 색 | 쓰임 | 성격 |
| --- | --- | --- |
| `TextPrimary` | 이름·값 | 거의 검정인 잉크색. 가장 먼저 읽힌다 |
| `TextSecondary` | 본문·부연 | 짙은 청회색. 본문은 충분히 읽히되 제목과 경쟁하지 않는다 |
| `TextMuted` | 캡션·잠김 사유 | 중간 청회색. 작은 글자도 백색 면에 묻히지 않는다 |
| `TextDisabled` | 꺼진 버튼 글자 | 옅은 청회색. 읽히되 누를 수 없음이 먼저 보인다 |

밝은 바탕에서는 흰색 알파만으로 구획을 만들지 않는다. `FaintFill` · `SubtleFill` · `Track`의 잉크색
알파 토큰으로 슬롯과 게이지를 나누며, 상태 설명 · 구매 불가 사유는 2560×1440과 1920×1080 실제
화면에서 읽히는지 함께 확인한다.

**타이포(1080p 기준)** — Display 38 · Title 27 · Heading 21 · Body 18 · Caption 15 · Micro 13.
예전(34/24/19/16/13/11)보다 한 단계 크다. `UIBuild.Text`가 만드는 글자는 전부 **자동 맞춤**이다
(`UIScaledText`) — 최대는 기준 × 글자 크기 설정, 최소는 기준의 82%(하한 11). 칸에 자리가 있으면 커지고,
좁은 칸에서는 예전 크기 근처까지만 줄어 넘치지 않는다. 설정에서 글자 크기(×1 · ×1.15 · ×1.3)를 바꾸면
숨어 있는 화면의 글자까지 즉시 다시 잰다. 캔버스 전체를 키우지 않는 이유 — 캐릭터 창처럼 기준 해상도로
칸 폭을 계산하는 화면이 있어, 캔버스를 키우면 칸이 화면 밖으로 밀린다.

**버튼 상태** — 켜진 보조 버튼은 잉크색 1px 헤어라인, 꺼진 버튼은 회청색 면으로 가라앉고 테두리가 사라지며 글자가
`TextDisabled`가 된다(`UIButtonStyle`). 예전에는 ColorTint의 회색 곱만 써서, 원래 회색인 보조 버튼은 꺼져도
거의 같아 보였다. 화면 코드가 켜져 있는 동안 바꾼 면·글자색은 기억했다가 다시 켜질 때 돌려준다.

**스크롤 영역**(`UIBuild.ScrollArea`)에는 오른쪽 5px 스크롤 막대가 붙는다. 내용이 짧으면 숨는다.
안의 항목에는 **EventTrigger를 붙이지 않는다** — 휠 · 드래그까지 먹어 항목 위에서 목록이 굴러가지 않는다
(캐릭터 선택창의 초상화 위 휠이 이렇게 막혔다). `UIBuild.OnClick`과 호버는 클릭 · 진입만 받는
`UIPointerEvents`를 쓴다.

**포인터 종류는 `UIPointerKind`로 묻는다.** 새 입력 시스템의 UI 모듈은 마우스에도 양수 `pointerId`(장치 ID)를
준다. `pointerId >= 0`을 터치로 보던 예전 판정은 마우스를 터치로 읽어 TAB 창의 장비 끌기가 시작하자마자 끊겼고
마우스 호버 툴팁도 뜨지 않았다. 누르면 뜨는 떠 있는 카드(TAB 창 장비 상세)는 바깥을 누르면 닫힌다
(`UIDismissOnOutsideClick`).

**글라스 면**(`UIBuild.Glass`) — 상단 바 · 자원 띠 · 행동 순서 · 보스 체력 띠 · 딜 그래프 · 카드 이름표 · 판정 띠는
애플 리퀴드 글라스풍이다. 반투명 백색 판 + 흰 헤어라인 테두리 + 윗부분 반사광 한 겹. UGUI에 배경 흐림이 없어
굴절은 흉내 내지 않고, 판을 낮은 불투명도로 두어 뒤의 전장이 비치게 한다.

**준비 바는 떠 있는 동안 0.25초마다 값을 다시 읽는다**(`PreparationScreen.Tick`). 스킬 Pt · 습득 가능 수를
바꾸는 경로(스킬 창 · 훈련 결과 · 보상 · 사건)가 여럿이라 각자 알리게 하지 않는다.

**빈 목록은 비워 두지 않는다.** 카드 자리가 통째로 비는 화면(스킬 힌트가 없는 스킬 화면 등)은
도형으로 그린 빈 상태 판과 **행동 유도 버튼**을 세운다. 버튼을 누를 수 없는 상황이면
버튼을 끄는 데서 그치지 않고 **왜 못 누르는지**를 함께 적는다 — 꺼진 버튼만 남기면 고장으로 읽힌다.

### 1.4 셀 UI 규칙

**카드 HUD는 8배속에서 읽혀야 한다.** 자동 전투라 플레이어가 할 수 있는 일은 보는 것뿐인데,
그 화면이 가장 빠를 때 읽히지 않으면 아무것도 읽히지 않는 것과 같다.

| 자리 | 규칙 |
| --- | --- |
| **궁극기 게이지** | 우상단 원형. 아래에서 위로 차오르고, 안에 **⌃⌃ 표식**이 흐리게 깔린다 — 원소색 원반 하나만으로는 "원소 표시"인지 "충전량"인지 갈리지 않기 때문이다. 다 차면 표식이 또렷해지며 맥동하고 테두리가 금색으로 넘어간다 |
| **상태 아이콘** | 어두운 원형 받침 위에 그림, 최대 6칸. **그림 · 방향 · 색이 같으면**(같은 Key 포함) 한 칸에 모으고 수를 오른쪽 아래에 적는다(1이면 적지 않는다). 순서는 행동 불가 → 해로움 → 기타 → 이로움. 넘치면 마지막 칸이 남은 칸 수를 흰 숫자로 적는다 |
| **이름표** | 한 줄. **이름과, 있으면 전투 자원(고유 패시브 스택 등)만** 적는다. 체력 수치는 적지 않는다 — 바가 말한다 |
| **체력 바** | 체력 오른쪽에 **방어막이 하늘색**(`UITheme.Shield`, 블루 아카이브식)으로 이어 붙는다. 예전 회백색은 어두운 트랙과 구분되지 않았다. 윗부분에 옅은 반사광 띠가 얹힌다 |
| **호버** | 카드에 마우스를 올리면 **원소 · 숙련(아군) · 주/부 스탯 · 한 줄 소개**(`UnitInfoText`)로 누구인지 먼저 소개하고, 그 아래 상태를 **이름 · 중첩 · 남은 턴 · 설명**으로 풀어 적는다. 체력은 적지 않는다. 아이콘은 모여 있으므로 무엇이 모였는지는 여기서 본다 |
| **상태 색** | 이로움 초록 · 해로움 적색 · **행동 불가 보라**(`UITheme.Control`) |

> 중첩은 같은 상태를 여러 개 들고 있는 것으로 구현돼 있어(`StatusStackPolicy.Stack`),
> 목록을 그대로 늘어놓으면 화상 5중첩 하나가 다섯 칸을 전부 먹었다.

> 행동 불가를 적색에 섞어 두면 "그냥 나쁜 것"으로만 읽힌다. 지금 못 움직이는 유닛이
> 다른 디버프 사이에서 색 하나로 먼저 튀어나와야 한다.

중첩 수 글자는 `UIShapes.Digit`이 3×5 격자를 블록으로 찍어 만든다. TextMeshPro를 쓰지 않는
이유는 이 캔버스가 월드 스페이스라서다 — `TextMeshProUGUI`는 여기서 아예 그려지지 않고(§1.2의
카드 이름표가 겪은 문제), 카드마다 월드 텍스트를 몇 개씩 세우는 것은 두 자리 숫자 하나에 과하다.

| 규칙 | 내용 |
| --- | --- |
| 책임 분리 | `Unit.cs`는 게임 로직, `Cell.cs`는 UI 표시 |
| 필드 전용 | 대기석 유닛은 UI를 표시하지 않는다 |
| HP 바 | 체력 100% = scale 9, 위치 이동으로 감소 표현 |
| **z값 통일** | 모든 바의 z = 0 |
| 깊이 제어 | z축이 아닌 **`SpriteRenderer.sortingOrder`** 사용 |

```csharp
// HP 바 스케일 계산
float targetScale = hpRatio * 9.0f;
float xOffset = (9.0f - targetScale) * -0.5f;

// 렌더 순서
currHpRenderer.sortingOrder = maxHpRenderer.sortingOrder + 1;
```

> **교훈** — 2D에서는 z축 위치보다 `sortingOrder`가 안정적이다.
> 과거 HP 바에 임의 z값(-0.1f)을 쓴 결과, 드래그 앤 드롭의 z 좌표계와 충돌해 위치가 왜곡됐다.

## 1.13 엘리트·보스 단독 연출

**판정이 둘이다.** 상단 체력 띠와 카드 확대는 조건이 다르다. 띠는 화면 위쪽의 빈 자리를 쓰지만
커진 카드는 옆 칸을 침범하므로, 잡졸이 함께 선 판에서 카드를 키우면 서로 가린다.

| | 상단 체력 띠 | 카드 확대 |
| --- | --- | --- |
| 판정 | `FeatureEnemies.BannerTargets()` | `FeatureEnemies.SoloStageTargets()` |
| 조건 | **엘리트가 하나라도 있으면** | 살아 있는 적이 1~2기이고 **전원이** 엘리트·보스 |
| 인원 | 최대 2 (`MaxCount`). 셋 이상이면 보스 먼저, 그다음 최대 체력 순 | 1~2 |
| 효과 | 상단 중앙에 이름·체력·상태 | `Cell.FeatureCardScale` = **1.5배** |
| 적용 시점 | 매 프레임 (`BattleHud.Update`) | 편성 배치 직후 (`RoundManager.ApplyFeaturePresentation`) |

호위를 달고 나오는 중간 보스는 **띠는 뜨지만 카드는 그대로**다. 라그나르가 광전사 둘과
볼바 둘을 데리고 서는 4슬롯이 그 경우다.

**배율은 칸에 붙어 있으므로 편성을 깔 때마다 먼저 모든 칸을 1배로 되돌린다**(`GridManager.ResetFeatureScales`).
예전에는 되돌리지 않아, 엘리트 단독 판을 한 번 치른 칸이 이후 그 자리에 서는 잡졸까지 크게 그렸다
(메히코의 독수리 전사 하나만 커지고, 판이 지날수록 커진 칸이 늘었다).

**카드 확대는 칸 안에서 일어난다.** `Cell.SetFeatureScale`이 카드와 초상화에 같은 배율을 먹인다.
초상화는 카드와 별개의 렌더러라 배율을 직접 다시 먹여야 하므로, 스케일을 바꾸면
`SetPortrait`를 다시 태운다. 옆 칸이 비어 있을 때만 켜지므로 커진 카드가 다른 유닛을 가리지 않는다.

### 상단 중앙 체력 띠 (`FeatureEnemyBanner`)

자원 표시줄 아래에 붙는다. 한 명이면 폭 560을 다 쓰고, 둘이면 가운데 틈을 두고 반씩 나눈다.
칸 하나에 이름과 체력 바, 현재/최대 수치, 상태 아이콘 여섯 개까지 들어간다.

카드 위의 작은 바는 **잡졸 다섯을 한눈에 훑기 위한 것**이라, 한 마리를 오래 때리는 판에서는
정보가 너무 멀리 있다. 2인조에서 좌우로 나누면 둘 중 누구를 먼저 깎고 있는지가
화면 한가운데에서 읽힌다. 방어막은 체력 바 위에 겹쳐 그려 껍질이 남았는지를 함께 보여 준다.

### 2.1 단일 진입점 원칙

`RunManager.AdvanceToNextStage()` — 보상/사건/육성 어느 흐름에서 오든 여기를 통과한다.

```
if (육성 모드) {
    if (Stage >= MaxTrainingStage || !TryLoadNextRound())  → CompleteTrainingRun()
    else                                                    → 세이브 + 다음 스테이지
```

### 4.4 저장/삭제 시점

| 시점 | 동작 |
| --- | --- |
| 스테이지 전진 | `SaveCurrentRun()` |
| 전투 시작 직전 | `SaveCurrentRun()` |
| 사건 발생 기록 | `MarkEventTriggered()` → 즉시 저장 |
| 앱 일시정지 / 종료 | `OnApplicationPause` / `OnApplicationQuit` — `CanSaveNow`일 때만 |
| 인게임 메뉴 `저장` · `저장하고 메인 메뉴로` | `SaveCurrentRun()` — `CanSaveNow`일 때만(아니면 버튼이 꺼진다) |
| 런 시작 | `SaveSystem.DeleteSave()` — 기존 진행 폐기 |
| 게임 오버 / 런 완료 | `SaveSystem.DeleteSave()` |

**`RunManager.CanSaveNow`** — 준비 · 육성 · 사건 페이즈에서만 참이다. 전투 중에 저장하면 쓰러진 아군이
`BuildHeroSaveData`에서 빠지고, 보상 선택 중에 저장하면 경험치를 받은 채 같은 전투로 되돌아가며,
캐릭터 선택 중에는 파티가 비어 있다. 그때는 전투 직전 자동 저장을 그대로 두고 덮어쓰지 않는다.

인게임 메뉴의 `불러오기`는 `GameStartIntent.Continue`로 Game 씬을 다시 연다. `저장 없이 메인 메뉴로`와 `게임 종료`는
저장하지 않는다 — 마지막 저장 이후의 진행을 버리는 출구이고, 메인 메뉴의 이어하기로 그 시점부터 잇는다(§1.5-A).

### 4.5 복원 순서

```
LoadSavedRun()
  1. 모드/생명력/킬 수 복원
  2. 인벤토리 복원 (토큰, 골드, 티켓, 아이템)
  3. 우정도 / 사건 이력 복원
  4. RoundManager.InitializeStage(stage)
  5. 기존 아군 전부 비활성화 → 저장된 아군 스폰 → RestoreRunState()
  6. RoundManager.LoadRound(stage)
  7. UI 갱신 → EnterNextStageAfterLoad() → 준비 행동 상태 복원
```

**구버전 세이브는 로드 시 폐기된다** (`RunSaveData.version`).

`SpriteResource`가 위 네 분류 폴더를 먼저 뒤지고 이전 평면 루트를 마지막으로 본다. 따라서 YAML과
코드에는 분류 경로를 넣지 않고 기존 스프라이트 키를 그대로 유지한다. 아군·적이 같은 원화를 공유하는
경우에는 파일을 `Allies`에 한 번만 두고 양쪽에서 같은 키로 불러온다.

> **초상화·스탠딩은 `Resources.Load`를 직접 부르지 않는다. 반드시 `SpriteResource`를 거친다.**
> 데이터가 들고 있는 것은 키(`SEI_PORTRAIT`)이고 실제 파일은 분류 폴더 안에 있어서, 키를 그대로
> `Resources.Load`에 넘기면 **조용히 null이 돌아온다.** 분류 폴더로 옮기던 날 소환수 카드·행동
> 대기열·도감·육성 화면이 한꺼번에 빈 칸이 된 것이 이 때문이다.
> `SpriteResource`는 키와 해석이 끝난 전체 경로를 모두 받으므로 진입점을 하나로 둘 수 있다.
>
> `Unit.PortraitPath`는 **해석에 성공하면 전체 경로, 실패하면 키 그대로**를 담는다. 어느 쪽이든
> 그대로 `SpriteResource.LoadPortrait`에 넘기면 된다.
>
> 아이템 아이콘(`Sprite/Items/`)만은 분류가 없는 평면 폴더라 직접 로드해도 된다.

디버그 검증(F1 → 전체 검증)의 **스프라이트 연결** 단계가 유닛·적·아이템·소환수의 키를 전부 한 번씩
읽어 본다. 자산을 옮기거나 이름을 바꾸면 이 단계가 먼저 깨진다.
