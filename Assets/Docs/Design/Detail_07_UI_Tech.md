# 상세 기획서 07 — UI·연출·기술

최종 갱신: **2026-10-31**

현재 화면 구조와 유지 규약을 둔다. 이전 레이아웃·작업 보고서·검수 회차는 [보관소](../../../Docs/Archive/README.md)에 있다.
실제 화면과 수치는 `Managers/UI/`·`Entities/View/`·`Effects/Vfx/`를 기준으로 대조한다.

## 1. 화면 설계

게임은 에디터·개발·공개 빌드 모두 **Stage(SD 무대)**로 시작한다. 준비 단계의 8개 배치 슬롯·이동/교환과 전투 SD·소환수 표시·Stage HUD를 같은 모드로 사용한다. Card 모드는 검증과 개발 패널의 명시적 전환용으로 유지하며, 표시 모드는 저장하지 않는다.

원신 계열의 정보 계층·배치·정렬, 블루 아카이브의 밝고 청량한 분위기를 기본으로 한다.
홈은 명일방주의 캐릭터 스탠딩과 주요 진입점 구조를 참고한다. Apple 유리 재질은 가독성을 해치지 않는 범위에서 사용한다.
단순한 반투명 사각형의 반복이나 두꺼운 윤곽선으로 품질을 대체하지 않는다.

군청색을 기본 UI 색으로 통일하며 체력·피해·원소·상태 같은 의미 정보에만 별도 색을 쓴다.
패널·버튼·텍스트 그룹은 동일한 여백과 정렬 기준을 공유하고, 텍스트는 실제 글자의 시각 중심으로 수직 정렬한다.
선택을 나타내는 좌측 수직 `I` 장식선은 사용하지 않는다. 버튼의 hover·pressed·selected·disabled는 구분되어야 한다.
공통 구현은 `UITheme`·`UIBuild`·`UIIcons`·`CodeText`·공통 툴팁을 재사용한다.

| 화면 | 정보와 배치 |
| --- | --- |
| 홈 | 비율을 유지한 스탠딩, 새 여정·이어하기·자료실·설정. 장식보다 주요 진입점 우선 |
| 편성 | 해금 캐릭터의 역할·원소·코드와 추천 조합, 1~5명 선택·중복 금지 |
| 준비·전투 상단 | 진행 위치·생명·골드·단계·예고·배속과 별도 일시정지. 식량은 표시하지 않음 |
| 스테이지 예고 | 아이콘은 현재/다가오는 슬롯을 구분하고 hover 툴팁으로 내용 예고 |
| 파티 TAB | ‘보상 코드’·‘고유 스킬’ 탭으로 구분. 선택 유닛의 스탯·활성 7칸·개인 보관함·공용 보급 |
| 상점 | 화면 대부분을 덮는 넓은 창. 라부아지에 스탠딩·탭·상품·구매/판매 상태. 코드 3장씩 페이지 |
| 휴식 | 히미코 스탠딩, 짧은/긴 휴식의 비용·회복·부활과 사용 가능 상태 |
| 보상 | 큰 선택지를 수평으로 배치. 무료 수령·대상 선택·리롤·만사 추가 구매를 구분 |
| 자료실 | 실제 게임 가이드. 항목·본문·선택 탭 모두 여백과 수직 중심을 맞춤 |
| 설정·ESC | 전투 속도·오디오·저장/나가기 등 필요한 조작. TAB 파티 창과 역할을 구분 |
| 전투 결과 | 승패·피해/지원·골드/EXP를 읽을 수 있게 단계별 표시 |
| 사건 | VN 대사·선택지·스탠딩, 편성·보상 흐름과 겹치지 않게 전환 |

상점·파티·보상처럼 뒤의 전장을 볼 필요가 없는 화면은 넓게 사용한다. 작은 창에 목록을 압축하지 않는다.
검증 기준 해상도는 사용자가 지정한 **1920×1080**이며 다른 해상도의 합격을 이 결과로 대신하지 않는다.

## 2. 전장 카드와 정보 HUD

아군과 적은 **동일한 적 카드 기본 구조**를 사용한다. 별도의 넓고 무거운 아군 프레임을 만들지 않는다.
원화의 얼굴·가슴·손과 실루엣을 살리고, 하단 정보판은 모든 자원·상태 아이콘이 컨테이너 안에 들어가도록 같은 여백을 준다.
유닛명은 상시 표시하지 않는다. 원화 hover 툴팁에 **이름·원소·한줄소개**를 표시한다.

초월기 자원은 캐릭터 위에 있는 **원소색 원형 게이지**로 보여 준다. 위치는 legacy/main의 원형 HUD 배치를 따른다.
원은 원화에 살짝 가려지는 크기이며 충전 퍼센트 텍스트는 제거한다. 마나형·스택형·상시형의 의미는 구분한다.
아이콘은 심플한 고딕 형태로 통일한다. 피격 수·고유 스택·강인도·보호막은 해당 개체의 실제 값을 읽는다.
일반 마나의 충전 숫자는 표시하지 않는다. 별도 고유 자원은 유닛별 표시 규칙을 사용하며 만종·텐션은 0도 표시하고, 프레이아의 치유 에너지·아누비스의 영혼은 각각 자신의 단위를 유지한다. 현행 수리야는 적에게 종언 표식을 쌓으므로 자신의 탄창·강화탄 배지를 표시하지 않는다. 공통 레이아웃 갱신은 이를 다른 자원으로 덮어쓰지 않는다.
메뉴·자료실이 타격 순간의 히트스톱 중 열려도 닫은 뒤에는 선택한 전투 배속을 복구한다. 별도로 일시정지한 상태는 유지한다. 로비 자료실의 문서 링크와 용어 상세 링크는 현재 열린 자료실 안에서 이동한다.

새 버프·디버프·원소 부착은 하단 상태 아이콘 외에 카드 위의 빈 공간에 잠깐 나타나는 **테두리 없는 텍스트**로 알린다.
맹독의 부여·갱신 글자는 일반 상태 알림 큐 대신 실제 거품 시작에 연결한다. 거품과 같은 `ElementPalette` 풀색으로 몸통 접점 가까이에 띄우며, 피해 숫자와 같은 떠오름·명암 규칙으로 읽힌다. 기존 착탄 뒤 장식 지연만 따르고 실제 상태 부여·피해·행동 시각은 유지한다.
저항·제거·재부여와 피해/치유 알림은 의미를 구분하고 한 번의 적용을 반복 팝업으로 부풀리지 않는다.
피해 숫자는 배경·원화 위에서도 읽히는 크기·명암·위치·짧은 동작을 가진다. 상태 안내와 겹치지 않는다.
실제 HP 수치와 본체 게이지는 즉시 갱신하고, 줄어든 구간만 짧게 남았다 따라 줄어든다. 치유·최대 체력 변경·카드 재연결 때 잔량을 초기화하며 일시정지 중에는 진행하지 않는다.
같은 적의 연속 피해 숫자는 세로 두 행을 먼저 사용해 직전 값과 새 값이 한 줄의 긴 숫자로 이어져 보이지 않게 한다.
숫자의 실제 글자 폭과 상승 경로를 예약하고 얼굴·체력판·원소 원·확장 행동 공지·보스 정보판을 피한다. 회복 숫자는 작은 `+수치` 하나로 표시하며 같은 뜻의 자막을 덧붙이지 않는다.

강인도는 적에게 생성된 경우에만 표시하며 파괴는 별도 피드백을 준다. 공통 격파 피해를 연출로 암시하지 않는다.
재보는 [18 재보](Detail_18_Treasury.md)의 아군 공용 SP형 표시를 따른다.

## 3. 행동 읽기와 배속

행동 순서에서 현재 행동 예고 → 실제 행동자/종류 → 시전 → 피격·지원 효과 → 숫자/상태 → 종료를 구분한다.
행동서열의 확장 슬롯은 **행동 종료까지 유지**한다. 짧은 고정 초 뒤 닫거나 빈 카드를 남기지 않는다.
실제 효과가 적용된 패시브만 알린다. 예약과 실행, 취소·사망·제어로 중단된 행동을 구분한다.
예약 삽입·AV 변경·사망 제거는 기존 슬롯을 재사용해 보간하며 실제 예고를 늦게 표시하지 않는다.

배속은 **1·2·3·4·5배**를 순환 선택하며 일시정지는 별도다. 0.5.3의 기본 1배는 0.5.2의 2배와 같은 실제 전투 속도다.
예고·시전·효과·결과도 같은 기준으로 가속하며, 정지 중 모션·자원·피해가 진행되지 않아야 한다.
게임 규칙의 턴/AV와 벽시계 연출을 분리한다. 자동전투의 논리 판정을 프레임 수로 정하지 않는다.

## 4. VFX·카드 모션

메이플스토리 신규 캐릭터 수준의 매끄러운 플립북과 타격감을 목표로 하되 UI와 같은 밝은 파스텔 분위기를 유지한다.
‘메이플 투명도 80%’는 해당 게임 설정에서 보이는 정도를 참조한 것이며 모든 레이어의 alpha를 기계적으로 동일하게 두는 지시가 아니다.
눈을 찌르는 전체 화면 섬광·빠른 깜박임·과한 bloom 대신 절제된 실루엣·국소 광·선명한 중심을 사용한다.
광과민성 검수는 [Xbox118](https://learn.microsoft.com/en-us/xbox/accessibility/xbox-accessibility-guidelines/118)·[WCAG2.3.1](https://www.w3.org/WAI/WCAG21/Understanding/three-flashes-or-below-threshold.html)을 참고해 임의의1초 구간의 반복 빈도·영역·휘도차·적색 전환·고대비 무늬를 함께 살핀다. 1·2배속뿐 아니라 고배속·동시 효과·화면 전환·짧은 미디어 반복 경계도 포함하며, 경고문만으로 검수를 대체하지 않는다. 전달용 모션 영상은 자동 반복 GIF 대신 구간 사이 정지 시간을 둔 MP4를 우선한다.
광과민성 위험이 없는 제품임을 미술 검수만으로 인증하지 않는다.

기본 직접 공격 문법은 **제자리 시전/사격 + 실제 대상의 피격 효과**다. 긴 투사체 비행·카드 왕복 돌진·대상을 잇는 선은 기본 문법에 넣지 않는다.
아탈란테는 구매팩 화살 묶음이 기존 피격 정점까지 짧게 비행하는 예외다. 일반은3줄, 추격은 큰 유도 화살1줄, 초월은 실제 수신자당5줄의 시각 묶음을 사용하며, 화살 수를 추가 피해나 별도 판정으로 해석하지 않는다.
짧은 반동·부분 전진·복귀로 무게를 주며 광역은 시전자 1회 뒤 대상별 효과로 표현한다.
같은 대상의 후속 타격은 이미 끝난 접점에서 이어지고 논리 콜백은 정해진 타격 정점에 한 번만 실행한다.
예외가 필요한 스킬은 실제 효과의 의미와 타이밍을 먼저 확인한다.
투사체·시전·착탄·상태를 포함한 모든 전투 VFX는 기본 필드·카드·카드 HUD보다 앞에 그린다. `CombatVfx`를 `CombatHud` 위에 정렬하고, 얼굴·배지·HUD 영역으로 VFX 형상을 잘라내지 않는다. 명중 정점은 원화를 잠시 덮을 수 있으며, 수명 종료 후 원화와 정보가 다시 드러나야 한다. 공격 몸체는 `ElementPalette`의 원소색, 밝은 심은 같은 원소색에서 백색으로 이어진다.
멸참과 아즈라엘도 같은 앞 레이어 규칙을 따른다. 기존 피격 정점에서 획을 완성하고, 아즈라엘은 예고 벼락과 실제 연기 피격을 구분한다. 이 표시를 위해 피해 횟수·판정 시각·후속 행동 대기를 변경하지 않는다.
아즈라엘의 접점 강세와 기존 횡연기에서 분리되는 고유 형태는 🔸 검증 필요다. 기능 검사의 통과를 미술 승인으로 취급하지 않는다.

수평 광역 타격은 `CombatSweepTiming`으로 대상들의 배치 열 중심부터 판정한다. 원화 피팅·이동 중 카드 좌표는 판정 순서를 바꾸지 않는다. 기존 대상별 판정 시간 범위와 콜백 횟수는 유지한다. 조합의 피격 시작 지연은 `CombatPresentationWait`의 상대 시간으로 진행해 절대 `Time.time`의 float 반올림에 따라 동시 타격 순서가 달라지지 않게 한다(2026-10-27).

공통 부품은 `96_vfx.yaml`·`VfxDefinitionCatalog`·`VfxComposer`·`CommonHandpaintFx`로 조합한다.
구매한 Handpaint 시트의 그리드·FPS·정점 시간을 보존하고 프레임 보간·alpha 본체/광 중심을 사용한다.
Hovl 소스팩과 기존 GUID는 보존하고 기본 런타임 연출은 현행 Handpaint 경로를 따른다. 아탈란테·네이트·네프티스의 `PurchasedArcherFx`는 Hovl AAA Projectiles Vol 1의 Hit 4 yellow arrow 명중·발사 핵심 셀, Flash 4 yellow arrow 전용 시전광과 Arrow 21 비행을 사용한다. `PurchasedVfxBaker`가 원본 재질·입자 모듈의 HDR 명도를 보존해 비행48셀·시전24셀은60fps/512px, 명중96셀은120Hz/384px의 실제 파티클 샘플로 렌더하고 런타임에 시전자 원소색을 적용한다. 명중은12×8 시트와120Hz 최소 샘플 기준을 전용 스타일로 사용하며, 기본 크기는2.45카드다. 다른 합성의 최소 샘플 기준은60Hz로 유지한다. 네이트 지원·촉진은 구매 Trail73 텍스처를 가는 유한 메시 조각에 재사용한다. 시전 결과 수신 결의 시차·실제 연결점·원소색 테두리·조각별 소멸은 시각만 소유하며 게임 효과를 지연하지 않는다. 시트는 고품질 압축으로 공유하며 구매 파생 시트는 공개 소스에서 제외한다. 비행 코드는 곡선 위치·접선 회전을 소유하고, 명중 시트는 반동 뒤 실제 몸통 접점을 추종한다. 전격 보조 꼬리는 복제본에서 제외한다. 시전은 캐릭터 몸체의 짧은 당김·방출과 손앞 화살 발사광을 연결하고, 발사 순간의 작은 핵심 섬광을 별도로 낸다. 몸체 동작은 시전 시작 뒤의 scaled 경과 시간으로 계산해 생성 전 프레임 시간을 포함하지 않으며, 칸·행동 대기·피해 콜백을 소유하지 않고 일시정지 때 멈춘다. 비행 바람은 구매 텍스처의 농담을 보존한다. 추격의 단발에도 갈라지는 바람결을 남기고, 광역의 여러 핵은 구슬처럼 읽히지 않는 길쭉한 빛줄기로 표시한다. 다른 팩의 붓획이나 수작업 화살 색면을 추가하지 않는다. 풀 화살 발사→착탄→맹독 버블의 순서를 유지하며, 맹독의 0.24초 연출 지연은 실제 상태 부여·피해 판정을 늦추지 않는다.
아탈란테 명중은 `PurchasedImpactBlend`의 전용 단일 패스로 인접 셀을 premultiplied RGBA 보간하고, 구매 노이즈의 정지된 농담에 따라 본체가 부분적으로 풀린 뒤 원본 파편을 재생한다. 초기2셀 뒤의2~95셀을 사용하며 이 장식 수명이 판정이나 행동 대기를 소유하지 않는다. `ContinuousBodyBlend` 기본값은 false여서 다른 공통 합성과 시전·비행은 기존 경로를 유지한다. 2배 초과의 이 공통 구매 명중광은 hit-stop의 순간 배율이 아닌 복구 배율을 기준으로 강도를 낮추며,1·2배속의 정점과 논리 판정은 유지한다. 맹독은 `PoisonBubblesFx`가 기존 원화를 시차로 차오르게 하고 상승·압축·립/물방울 파열을 연결하며, 부여5개·틱3개는 시각 거품 수다. 자연 틱의 파열은 실제 추격 명중의 밝은 본체 퇴장과 연결해 기포별 원래 시차를 유지한다. 이 시각 대기는 취소·누락/회수와 scaled 2.5초 제한으로 해제하며 피해·상태·행동 대기를 소유하지 않는다. 네이트 일반은 번개 화살1줄, 초월은 번개 아군에게 교차하는 지원 결, 촉진은 피해 없는 대상 결로 표시한다. 네프티스는 일반 씨앗1개·초월 대상당3개의 잎눈 투사와 독안 개화를 구분하고, 독안 개화가 승인된 맹독 거품이나 아탈란테 추격의 대기를 다시 시작하지 않는다. 다른 대상의 상태로 읽히지 않게 파편의 위치·크기·분포를 정하되 카드/얼굴/HUD 합성 마스크로 형상을 자르지 않는다.
색·크기·방향·anchor·타이밍으로 구분하고 스킬마다 별도 절차적 그림을 무분별하게 추가하지 않는다.
카드 등장·hover·클릭·드래그·피격·사망·전장 드랍·소환과 공격 모션을 모두 검수 범위에 포함한다.
상태/원소 알림은 실제 적용 성공 뒤에만 나오며 보호막·치유·해제·충전·소비를 서로 다른 의미로 표현한다.
보호막 수혜는 공통 `StatusAffectedVfx.PlayShield`와 `PurchasedSupportThreadsFx.Kind.Ward`를 재사용한다. 실제 양수 보호막 증가 뒤에 호출하며, 이미 수신자를 관리하는 기존 옵저버와 중복 발행하지 않는다. 공통 UI 보호막색의 다면 판막이 몸통에서 아래부터 조립되고 부분별로 소멸한다. 이 경로는 보호막 수치·지속시간·피해 판정을 소유하지 않는다.
공통 피격 접점은 실제 대상 몸통의 짧은 정점과 파편으로 구성한다. 크기를 제한하거나 형상을 자르는 방식으로 원화를 피하지 않으며, 접점 장식은 피해 콜백이나 행동 대기를 추가하지 않는다.
별도 구매 화살 연출이 소유한 분산층을 제외하고, 다른 아군의 실제 직접 피해에는 공용 구매 불티·파편을 덧붙인다. 지속피해·반응·분담·추가 피해와 무피해 지원에는 타격을 추가하지 않으며, 연타 중첩과 동시 수는 장식 수명 기준으로 제한한다. 이 부품은 피해·상태·행동 시각을 소유하지 않는다.
적 지원기는 `enemy.support.heal/shield/rally/charge`로 구분하고, 실제 회복·보호막·강화 수신자에게 해당 공통 표시를 붙인다. 적의 지원기에 오르페우스 고유 연출을 빌려 쓰지 않는다.
네프티스·아탈란테·네이트·에레쉬키갈·니콜·아스톨포의 접점은 독·관통·전격·상처·전기장·뿔피리로 구분한다. 네이트의 강화와 에레쉬키갈의 치유는 실제 적용 성공에 따른 공통 지원 표시를 사용하고 공격 피격이나 치유를 중복 암시하지 않는다. 데이터는 `96_vfx.yaml`의 `contactMotif`와 `PortraitAccentFx`가 연결한다.

미술의 주 문법은 메이플스토리처럼 끝이 가늘어지는 곡선·분명한 셀 색면·국소의 밝은 심을 가진 한중일 서브컬처다. 관통 화살은 구매팩 원본을 우선 재사용하고, 지원의 상승광/결계와 독·전격·출혈은 공용16셀 원화와 인접 프레임 보간을 사용한다. 시전의 큰 장식은 실제 피격이 시작되면 거두어 수신자가 강조되게 한다. 이 장식은 피해 콜백이나 행동 완료 대기를 소유하지 않는다.
피격점은 원화의 투명 여백·무기 끝을 피한 몸통에 둔다. 원화 사본을 만들 때 불투명 연속 구간을 캐시하고, 자동 구분이 어려운 원화는 `portraitContacts`의 어깨 접점을 사용한다. 얼굴 영역 데이터는 접점을 고르는 기준이며, VFX 합성 마스크로 사용하지 않는다. 실제 원화 반동과 접점의 alpha를 확인하고, 이펙트 자체는 카드 앞에서 온전한 형상으로 표시한다.
동작의 연결성과 타격감 미술 기준은 **1·2배속**이다. 그보다 빠른 배속은 진행을 넘기는 용도로, 행동자·실제 수신자·피해/치유/상태 결과를 식별할 수 있게 한다. 콜백 없는 새 장식 시트는 고배속에서 셀을 건너뛸 수 있으며, 기존 판정 시트의 정점/대기는 보존한다. 일시정지에서는 배속에 따른 최소 셀 시간이 바뀌어도 프레임을 진행하지 않는다.
같은 실제 행동ID·수신자·피해 종류·치명/반격 구분의 직접 연타 숫자는 대상별 누계와 `N타 합계`로 갱신한다. 실제 피해 횟수와 콜백은 합치지 않는다. 지속피해·반응·추가 피해·분담 피해와 행동ID 없는 표시는 별도로 유지한다.

프레임 캡처의 정점 확인과 실제 시간 영상의 연결성을 각각 확인한다. 정지 프레임 PASS는 4배속·오디오·실기기 FPS 합격이 아니다.
미술 검수는 Root가 효과군 2~6부품 또는 캐릭터 1~3스킬처럼 **작은 범위**로 나누어 실제 화면과 모션을 순차 확인한다. Opus 5.5 검토는 생략한다.
Root가 결함을 소스/원본과 대조해 직접 보정하고 바뀐 범위만 재검수한다. 미변경 PASS는 동일 소스 근거로만 재사용한다.
최종 미술 PASS 영상만 사용자에게 보여 주고, 전체 승인은 유효한 범위별 판정과 coverage로 결정한다.

## 5. 가이드·중첩 툴팁

자료실은 플레이에 필요한 규칙·유닛·코드·상태·원소·진행·편성을 설명하는 가이드다. 첫 여정 안내는 추천 편성·출격·보상 투자 순으로 읽고, 상세 진행표는 뒤에서 확인한다. 적을 쓰러뜨리는 데 오래 걸리면 화력, 조기 사망은 배치·유지력을 우선 점검하도록 안내한다. 전투 행동 수에 따른 자동 패배는 없다.
스킬/코드 설명의 고유명사는 짧은 툴팁으로 설명하고 자세한 자료실 항목으로 연결한다.
보상 카드의 이름·등급·본문·태그 위를 눌러도 카드가 선택되어야 한다. 용어 호버 설명과 긴 본문의 스크롤은 유지하고 드래그를 보상 선택으로 처리하지 않는다.
CK3식 중첩 툴팁처럼 부모에서 자식으로 마우스를 옮길 수 있어야 하며 즉시 닫힘·화면 밖 잘림·자기 재귀를 막는다.
닫기·화면 전환·풀 재사용 시 연결과 잠금을 정리한다. 용어 원본은 `WikiCatalog`와 `CodeText`를 공유한다.

## 7. 저장과 검증 격리

현행 런 저장은 **v17**다. v12~v16을 이관하며 활성 7칸의 빈 위치, 보관 순서, 코드 인스턴스 GUID·축전량·취득 시세,
넥타르·영구 중첩, 체력·생사·초월 자원, 진행/테마를 보존한다. [진행 호환](Detail_01_Progression.md)·[보상 저장](Detail_17_Reward_Codes.md)
v16의 생명력 필드는 무시한다. HUD·이어하기·결과 창에서 런 목숨을 제거하고 결과 창은 파티 생존 인원을 표시한다. 전멸 시 런 저장을 삭제하고 결과 확인 뒤 메뉴로 돌아간다.
쓰기 가능 시점은 `RunManager.CanSaveNow`를 따른다. 전투·보상 선택 도중 임의 저장하지 않는다.
이관은 불러오는 순간 원본을 덮지 않으며 다음 정상 저장에서 새 형식을 쓴다.
해금·사용자 설정은 계정 데이터로 구분한다. 옛 TrainedCharacterCollection은 현행 성장 시스템이 아니다.

`DebugMode.BeginSession()`과 검증 Player의 별도 productName으로 사용자 저장을 격리한다.
개발 검증 때문에 실제 ProjectSettings·사용자 런·구매팩 GUID·오디오를 덮어쓰지 않는다.
검증용 productName 변경은 빌드 뒤 원래 직렬화 바이트로 되돌린다.

## 8. 개발·빌드·검수

엔진 기준은 `ProjectSettings/ProjectVersion.txt`, 시작 씬은 `MainMenu → Game`, 빌드 씬은 EditorBuildSettings다.
Windows/Mac 빌드 진입점은 `Assets/Scripts/Tools/Editor/DemoBuild.cs`의 `BuildWindows` / `BuildMac`이다.
플랫폼 Build Support가 필요하며 빌드 출력 폴더는 해당 스크립트가 다시 생성한다.

현행 검증은 `Managers/UI/DevTools/VerifyHarnessRunner`와 분리된 시나리오 파일에서 실제 Unity Play Mode로 실행한다.
기능·경계·캠페인·저장/복원·UI 입력·VFX·성능 검사를 변화 범위에 맞춰 고른다. 옛 5스탯 Debug/BalanceSim 메뉴를 안내하지 않는다.
편성·배속·환경·seed·현재 소스 manifest·결과/예외·촬영본을 함께 기록하며 실행하지 않은 검사를 합격으로 쓰지 않는다.
임시 csproj 컴파일은 보조 검사이고 Unity 실행이나 실제 Player 검증을 대체하지 않는다.

독립 전투 비교는 [`Tools/BalanceSim`](../../../Tools/BalanceSim/README.md)의 .NET CLI를 사용한다. `Unit`·스킬/효과·`ActionScheduler`의 현행 소스와 YAML을 공유하며, `CombatRoundLifecycle`·`CombatKillEconomy`·`CombatFieldLayout`은 게임과 콘솔의 공통 진입점이다. 콘솔은 렌더링·사용자 저장 없이 편성/배치/레벨/보상/시드별 고정 전투를 반복하고 승률·행동 수·실제 피해를 `Logs/`에 기록한다. 데이터 폴더를 복사해 `--data`로 지정하면 원본 수치 변경 없이 비교할 수 있다. 시드 세션의 `CombatRandom`은 호스트에 독립적인 수열이며, 일반 게임은 시드 세션 밖에서 기존 Unity 난수를 유지한다. 동일 조건 대조는 `verify-parity.ps1`와 실제 Play Mode의 `simulation_parity` 시나리오를 사용한다. 고정 50Hz에서 지휘 동시 공격·복합 편성·전멸·성장 복원 50조건의 행동/피해 사건과 결과를 대조했다(2026-10-27). 조건·수정·실패 이력은 `Logs/BalanceSim/ParityVerification20261027.md`가 근거다. 전역의 모든 시드·배속·상태 조합을 승인하는 검사는 아니다. 독립 전투 결과를 자연 런 승률·Play Mode QA·미술·오디오·성능 승인으로 확대하지 않는다.

자연 진행 평균은 전투·보상·운영을 포함한 기존 공유 난수로 측정한다. 고정보스는 운과 별개로 공통 전력을 시험하는 관문이다. `composition_campaign`의 `failure_branches` 트리거는 준비 직전 상태와 난수, 전투 직전 상태와 난수, 적 ID·열 배치와 원 패배를 실패 체크포인트에 저장한다. 별도 `failure_branches` 시나리오는 자연 런이 끝난 뒤 원 패배 재현 및 식량 우선·보관 코드 판매 선택을 제한적으로 재생한다. 판매 분기는 자동 코드 재배치 전에 판매·식량 확보를 먼저 결정한다. 완료된 분기는 기록에서 재개하며 동일 준비 상태·난수의 결과는 재사용한다. 실제 재화·구매 횟수·휴식 제한을 지키며 원 실패를 성공으로 교체하거나 자연 평균의 표본 수에 분기를 합치지 않는다. 분기 파일·결과는 `Logs/`에 둔다. 구제된 분기의 전체 경과는 `failure_continuations`로 따로 관찰한다. 구제 승리를 먼저 재현한 뒤 보상 선택·난수를 초기화하지 않고 같은 전투 상태에서 이어가며, 이후 기존 자연 운영을 적용한다. 원래 런의 분기 전 기록과 이후 분기 기록을 연결해 비교하고, 구제 성공으로 선별된 조건부 결과를 자연 평균에 합치지 않는다.

`checkpoint_progression_core`는 기본8슬롯 보존,4테마 주기,무료 긴 휴식 UI·재사용 제한·저장 이관을 실제 Play Mode에서 검사한다. 자연 캠페인은 무료 휴식을 별도 기록하고 전투 라운드 평균에서 제외한다. 과거24·48 고정보스 위치로 생성된 실패 진단은 당시 진행 규칙의 자료이며 현행34·68의 자연 평균과 같은 조건으로 합치지 않는다. 보스 잔여 체력은 전투 종료의 풀 정리 전에 보존한다. 진단용 배율·강제 코드 장착·관측 중절은 실제 게임 제한에 적용하지 않고 자연 평균에도 합치지 않는다.

성능은 자연 전투·UI 조작에서 측정한다. 고정 프레임 캡처나 Editor 결과를 사용자 장치 성능으로 일반화하지 않는다.
프로파일링·폴링/할당·풀 수명·이벤트 구독·자원 로딩·연출 겹침도 게임 전체 기술 검수에 포함한다.
현재 전체 QA 및 상용 미술 최종 승인은 **미완료**다. 구체적인 다음 범위는 [백로그](Design_Backlog.md)에 둔다.

## 9. 에셋·사운드 보존

초상화/스탠딩은 `Resources/Sprite/{Portraits,Standings}`·`SpriteResource`의 규칙을 따른다.
아군 초상화는 얼굴·상반신을 읽기 쉬운 별도 구도로 제작하고, 전신 스탠딩을 그대로 복제해 등록하지 않는다. 작은 HUD는 `UIPortraitCrop.Face`를 통해 얼굴 중심으로 표시한다.
원화 비율과 alpha를 유지하며 임포트 정책은 `Editor/PortraitTextureImportPolicy.cs`를 따른다.
공허 기본형은 큰 결정형 면·절제된 외곽선·백색/먹색/금색 골격과 원소색 결정을 유지한다.
기존 Sprite·VFX·오디오 `.meta` GUID를 재생성하지 않는다.

SFX는 `95_sfx_cues.yaml` 논리 키와 `SfxCueRoutes`를 통해 재생한다. 스킬 코드에 긴 음성 파일 경로를 산재시키지 않는다.
현재 임시 음성 매핑은 큐 데이터가 원본이다. 구매팩 및 임시 HSR 음성은 `.gitignore` 배포 규칙을 따른다.
저장소에 없다는 이유로 로컬 팩/음성을 삭제하거나 공개 소스로 강제 추가하지 않는다. 실제 음량·타이밍 검수는 무음 영상으로 대신하지 않는다.
