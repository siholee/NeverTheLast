# 상세 기획서 07 — UI·연출·기술

최종 갱신: **2026-10-15**

현재 화면 구조와 유지 규약을 둔다. 이전 레이아웃·작업 보고서·검수 회차는 [보관소](../../../Docs/Archive/README.md)에 있다.
실제 화면과 수치는 `Managers/UI/`·`Entities/View/`·`Effects/Vfx/`를 기준으로 대조한다.

## 1. 화면 설계

원신 계열의 정보 계층·배치·정렬, 블루 아카이브의 밝고 청량한 분위기를 기본으로 한다.
홈은 명일방주의 캐릭터 스탠딩과 주요 진입점 구조를 참고한다. Apple 유리 재질은 가독성을 해치지 않는 범위에서 사용한다.
단순한 반투명 사각형의 반복이나 두꺼운 윤곽선으로 품질을 대체하지 않는다.

군청색을 기본 UI 색으로 통일하며 체력·피해·원소·상태 같은 의미 정보에만 별도 색을 쓴다.
패널·버튼·텍스트 그룹은 동일한 여백과 정렬 기준을 공유하고, 텍스트는 실제 글자의 시각 중심으로 수직 정렬한다.
선택을 나타내는 좌측 수직 `I` 장식선은 사용하지 않는다. 버튼의 hover·pressed·selected·disabled는 구분되어야 한다.
공통 구현은 `UITheme`·`UIBuild`·`UIIcons`·`CodeText`·공통 툴팁을 재사용한다.

| 화면 | 정보와 배치 |
| --- | --- |
| 홈 | 비율을 유지한 스탠딩, 새 여정·이어하기·자료실·설정. 장식보다 주요 진입점 우선 |
| 편성 | 해금 캐릭터의 역할·원소·코드와 추천 조합, 1~5명 선택·중복 금지 |
| 준비·전투 상단 | 진행 위치·생명·골드·단계·예고·배속과 별도 일시정지. 식량은 표시하지 않음 |
| 스테이지 예고 | 아이콘은 현재/다가오는 슬롯을 구분하고 hover 툴팁으로 내용 예고 |
| 파티 TAB | ‘보상 코드’·‘고유 스킬’ 탭으로 구분. 선택 유닛의 스탯·활성 7칸·개인 보관함·공용 보급 |
| 상점 | 화면 대부분을 덮는 넓은 창. 라부아지에 스탠딩·탭·상품·구매/판매 상태. 코드 3장씩 페이지 |
| 휴식 | 히미코 스탠딩, 짧은/긴 휴식의 비용·회복·부활과 사용 가능 상태 |
| 보상 | 큰 선택지를 수평으로 배치. 무료 수령·대상 선택·리롤·만사 추가 구매를 구분 |
| 자료실 | 실제 게임 가이드. 항목·본문·선택 탭 모두 여백과 수직 중심을 맞춤 |
| 설정·ESC | 전투 속도·오디오·저장/나가기 등 필요한 조작. TAB 파티 창과 역할을 구분 |
| 전투 결과 | 승패·피해/지원·골드/EXP를 읽을 수 있게 단계별 표시 |
| 사건 | VN 대사·선택지·스탠딩, 편성·보상 흐름과 겹치지 않게 전환 |

상점·파티·보상처럼 뒤의 전장을 볼 필요가 없는 화면은 넓게 사용한다. 작은 창에 목록을 압축하지 않는다.
검증 기준 해상도는 사용자가 지정한 **1920×1080**이며 다른 해상도의 합격을 이 결과로 대신하지 않는다.

## 2. 전장 카드와 정보 HUD

아군과 적은 **동일한 적 카드 기본 구조**를 사용한다. 별도의 넓고 무거운 아군 프레임을 만들지 않는다.
원화의 얼굴·가슴·손과 실루엣을 살리고, 하단 정보판은 모든 자원·상태 아이콘이 컨테이너 안에 들어가도록 같은 여백을 준다.
유닛명은 상시 표시하지 않는다. 원화 hover 툴팁에 **이름·원소·한줄소개**를 표시한다.

초월기 자원은 캐릭터 위에 있는 **원소색 원형 게이지**로 보여 준다. 위치는 legacy/main의 원형 HUD 배치를 따른다.
원은 원화에 살짝 가려지는 크기이며 충전 퍼센트 텍스트는 제거한다. 마나형·스택형·상시형의 의미는 구분한다.
아이콘은 심플한 고딕 형태로 통일한다. 피격 수·고유 스택·강인도·보호막은 해당 개체의 실제 값을 읽는다.
일반 마나의 충전 숫자는 표시하지 않는다. 별도 고유 자원은 유닛별 표시 규칙을 사용하며 만종·텐션은 0도 표시하고, 프레이아의 치유 에너지·아누비스의 영혼은 각각 자신의 단위를 유지한다. 현행 수리야는 적에게 종언 표식을 쌓으므로 자신의 탄창·강화탄 배지를 표시하지 않는다. 공통 레이아웃 갱신은 이를 다른 자원으로 덮어쓰지 않는다.
메뉴·자료실이 타격 순간의 히트스톱 중 열려도 닫은 뒤에는 선택한 전투 배속을 복구한다. 별도로 일시정지한 상태는 유지한다. 로비 자료실의 문서 링크와 용어 상세 링크는 현재 열린 자료실 안에서 이동한다.

새 버프·디버프·원소 부착은 하단 상태 아이콘 외에 카드 위의 빈 공간에 잠깐 나타나는 **테두리 없는 텍스트**로 알린다.
저항·제거·재부여와 피해/치유 알림은 의미를 구분하고 한 번의 적용을 반복 팝업으로 부풀리지 않는다.
피해 숫자는 배경·원화 위에서도 읽히는 크기·명암·위치·짧은 동작을 가진다. 상태 안내와 겹치지 않는다.

강인도는 적에게 생성된 경우에만 표시하며 파괴는 별도 피드백을 준다. 공통 격파 피해를 연출로 암시하지 않는다.
재보는 [18 재보](Detail_18_Treasury.md)의 아군 공용 SP형 표시를 따른다.

## 3. 행동 읽기와 배속

행동 순서에서 현재 행동 예고 → 실제 행동자/종류 → 시전 → 피격·지원 효과 → 숫자/상태 → 종료를 구분한다.
행동서열의 확장 슬롯은 **행동 종료까지 유지**한다. 짧은 고정 초 뒤 닫거나 빈 카드를 남기지 않는다.
실제 효과가 적용된 패시브만 알린다. 예약과 실행, 취소·사망·제어로 중단된 행동을 구분한다.
예약 삽입·AV 변경·사망 제거는 기존 슬롯을 재사용해 보간하며 실제 예고를 늦게 표시하지 않는다.

배속은 **1·2·4배**이고 일시정지는 별도다. 1배는 처음 보는 사람, 2배는 규칙을 아는 사람이 흐름을 읽을 수 있는 속도,
4배는 빠른 진행을 위한 속도다. 정지 중 모션·자원·피해가 진행되지 않아야 한다.
게임 규칙의 턴/AV와 벽시계 연출을 분리한다. 자동전투의 논리 판정을 프레임 수로 정하지 않는다.

## 4. VFX·카드 모션

메이플스토리 신규 캐릭터 수준의 매끄러운 플립북과 타격감을 목표로 하되 UI와 같은 밝은 파스텔 분위기를 유지한다.
‘메이플 투명도 80%’는 해당 게임 설정에서 보이는 정도를 참조한 것이며 모든 레이어의 alpha를 기계적으로 동일하게 두는 지시가 아니다.
눈을 찌르는 전체 화면 섬광·빠른 깜박임·과한 bloom 대신 절제된 실루엣·국소 광·선명한 중심을 사용한다.
광과민성 위험이 없는 제품임을 미술 검수만으로 인증하지 않는다.

기본 직접 공격 문법은 **제자리 시전/사격 + 실제 대상의 피격 효과**다. 긴 투사체 비행·카드 왕복 돌진·대상을 잇는 선은 기본 문법에 넣지 않는다.
짧은 반동·부분 전진·복귀로 무게를 주며 광역은 시전자 1회 뒤 대상별 효과로 표현한다.
같은 대상의 후속 타격은 이미 끝난 접점에서 이어지고 논리 콜백은 정해진 타격 정점에 한 번만 실행한다.
예외가 필요한 스킬은 실제 효과의 의미와 타이밍을 먼저 확인한다.

공통 부품은 `96_vfx.yaml`·`VfxDefinitionCatalog`·`VfxComposer`·`CommonHandpaintFx`로 조합한다.
구매한 Handpaint 시트의 그리드·FPS·정점 시간을 보존하고 프레임 보간·alpha 본체/광 중심을 사용한다.
Hovl 소스팩과 기존 GUID는 보존하지만 기본 런타임 연출은 현행 Handpaint 경로를 따른다.
색·크기·방향·anchor·타이밍으로 구분하고 스킬마다 별도 절차적 그림을 무분별하게 추가하지 않는다.
카드 등장·hover·클릭·드래그·피격·사망·전장 드랍·소환과 공격 모션을 모두 검수 범위에 포함한다.
상태/원소 알림은 실제 적용 성공 뒤에만 나오며 보호막·치유·해제·충전·소비를 서로 다른 의미로 표현한다.

프레임 캡처의 정점 확인과 실제 시간 영상의 연결성을 각각 확인한다. 정지 프레임 PASS는 4배속·오디오·실기기 FPS 합격이 아니다.
미술 독립 검수는 Opus 5.5에 효과군 2~6부품 또는 캐릭터 1~3스킬처럼 **작은 범위**로 순차 의뢰한다.
Root가 결함을 소스/원본과 대조해 직접 보정하고 바뀐 범위만 재검수한다. 미변경 PASS는 동일 소스 근거로만 재사용한다.
최종 미술 PASS 영상만 사용자에게 보여 주고, 전체 승인은 유효한 범위별 판정과 coverage로 결정한다.

## 5. 가이드·중첩 툴팁

자료실은 플레이에 필요한 규칙·유닛·코드·상태·원소·진행·편성을 설명하는 가이드다. 첫 여정 안내는 추천 편성·출격·보상 투자 순으로 읽고, 상세 진행표는 뒤에서 확인한다. 80턴 시간 초과는 화력, 조기 사망은 배치·유지력을 우선 점검하도록 안내한다.
스킬/코드 설명의 고유명사는 짧은 툴팁으로 설명하고 자세한 자료실 항목으로 연결한다.
CK3식 중첩 툴팁처럼 부모에서 자식으로 마우스를 옮길 수 있어야 하며 즉시 닫힘·화면 밖 잘림·자기 재귀를 막는다.
닫기·화면 전환·풀 재사용 시 연결과 잠금을 정리한다. 용어 원본은 `WikiCatalog`와 `CodeText`를 공유한다.

## 7. 저장과 검증 격리

현행 런 저장은 **v15**다. v12~v14를 이관하며 활성 7칸의 빈 위치, 보관 순서, 코드 인스턴스 GUID·축전량·취득 시세,
넥타르·영구 중첩, 체력·생사·초월 자원, 진행/테마를 보존한다. [진행 호환](Detail_01_Progression.md)·[보상 저장](Detail_17_Reward_Codes.md)
쓰기 가능 시점은 `RunManager.CanSaveNow`를 따른다. 전투·보상 선택 도중 임의 저장하지 않는다.
이관은 불러오는 순간 원본을 덮지 않으며 다음 정상 저장에서 새 형식을 쓴다.
해금·사용자 설정은 계정 데이터로 구분한다. 옛 TrainedCharacterCollection은 현행 성장 시스템이 아니다.

`DebugMode.BeginSession()`과 검증 Player의 별도 productName으로 사용자 저장을 격리한다.
개발 검증 때문에 실제 ProjectSettings·사용자 런·구매팩 GUID·오디오를 덮어쓰지 않는다.
검증용 productName 변경은 빌드 뒤 원래 직렬화 바이트로 되돌린다.

## 8. 개발·빌드·검수

엔진 기준은 `ProjectSettings/ProjectVersion.txt`, 시작 씬은 `MainMenu → Game`, 빌드 씬은 EditorBuildSettings다.
Windows/Mac 빌드 진입점은 `Assets/Scripts/Tools/Editor/DemoBuild.cs`의 `BuildWindows` / `BuildMac`이다.
플랫폼 Build Support가 필요하며 빌드 출력 폴더는 해당 스크립트가 다시 생성한다.

현행 검증은 `Managers/UI/DevTools/VerifyHarnessRunner`와 분리된 시나리오 파일에서 실제 Unity Play Mode로 실행한다.
기능·경계·캠페인·저장/복원·UI 입력·VFX·성능 검사를 변화 범위에 맞춰 고른다. 옛 5스탯 Debug/BalanceSim 메뉴를 안내하지 않는다.
편성·배속·환경·seed·현재 소스 manifest·결과/예외·촬영본을 함께 기록하며 실행하지 않은 검사를 합격으로 쓰지 않는다.
임시 csproj 컴파일은 보조 검사이고 Unity 실행이나 실제 Player 검증을 대체하지 않는다.

성능은 자연 전투·UI 조작에서 측정한다. 고정 프레임 캡처나 Editor 결과를 사용자 장치 성능으로 일반화하지 않는다.
프로파일링·폴링/할당·풀 수명·이벤트 구독·자원 로딩·연출 겹침도 게임 전체 기술 검수에 포함한다.
현재 전체 QA 및 상용 미술 최종 승인은 **미완료**다. 구체적인 다음 범위는 [백로그](Design_Backlog.md)에 둔다.

## 9. 에셋·사운드 보존

초상화/스탠딩은 `Resources/Sprite/{Portraits,Standings}`·`SpriteResource`의 규칙을 따른다.
원화 비율과 alpha를 유지하며 임포트 정책은 `Editor/PortraitTextureImportPolicy.cs`를 따른다.
공허 기본형은 큰 결정형 면·절제된 외곽선·백색/먹색/금색 골격과 원소색 결정을 유지한다.
기존 Sprite·VFX·오디오 `.meta` GUID를 재생성하지 않는다.

SFX는 `95_sfx_cues.yaml` 논리 키와 `SfxCueRoutes`를 통해 재생한다. 스킬 코드에 긴 음성 파일 경로를 산재시키지 않는다.
현재 임시 음성 매핑은 큐 데이터가 원본이다. 구매팩 및 임시 HSR 음성은 `.gitignore` 배포 규칙을 따른다.
저장소에 없다는 이유로 로컬 팩/음성을 삭제하거나 공개 소스로 강제 추가하지 않는다. 실제 음량·타이밍 검수는 무음 영상으로 대신하지 않는다.
