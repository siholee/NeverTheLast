# P0 — 게임이 성립하기 위해 필요한 것
## 1. 츠쿠요미 순환 — 상한 없는 곱연산

`순환(Lv.44)`은 아군이 죽을 때마다 생존 아군 하나에게
**주는 피해 ×1.25 / 받는 피해 ×0.75**를 부여한다. 중첩 정책이 `Stack`이고 키에 카운터가 붙어
**같은 유닛에 무제한으로 쌓인다.**

| 아군 사망 수 | 주는 피해 | 받는 피해 |
| --- | --- | --- |
| 1 | ×1.25 | ×0.75 |
| 2 | ×1.56 | ×0.56 |
| 3 | ×1.95 | ×0.42 |
| 4 | **×2.44** | **×0.32** |

파티가 5인이므로 자연 상한은 4중첩이지만, **전멸 직전에 남은 하나가 2.4배 화력과 3배 내구를 얻는다.**
역전 장치로는 매력적이나 상한이 명시되어 있지 않다.

**정할 것** — 중첩 상한(예: 2)을 둘 것인가, 아니면 역전 장치로 유지할 것인가.

---

## 2. 곱연산 방어의 누적

받는 피해 배율은 전부 곱해진다. 한 유닛이 동시에 받을 수 있는 것만 모아도:

| 출처 | 배율 |
| --- | --- |
| 갑옷 숙련 | ×0.97 |
| 피그말리온 궁극기 장미의 가시 | ×0.50 |
| 츠쿠요미 순환 4중첩 | ×0.32 |
| **누적** | **×0.14 (86% 감소)** |

여기에 CON 기반 체력과 STR 기반 방어(최대 24~33%)가 별도로 곱해진다.
**§1이 해결되지 않으면 이 조합이 전부 동시에 성립한다.**

**정할 것** — 받는 피해 감소에 **하한(예: ×0.35)** 을 둘 것인가, 아니면 개별 수치를 낮출 것인가.

---

## 3. 다단히트 × 피해당 발동

세이 리메이크로 일반행동은 단일 타격이 되었고, 피해당 발동은 4턴 궁극기 `성역`으로 이동했다.
같은 구조가 다른 곳에도 있다.

| 대상 | 구조 |
| --- | --- |
| 아마테라스 `태양의 박자` | `OnNormalAttackHit`마다 DEX +4 스택 (상한 6). 다단히트면 한 방에 만중첩 |
| 처형 패시브 (`천살성` / `당연한 운명`) | `OnDamageDealt`마다 판정 — 다단히트에서 발당 검사 |
| 시 `시의 종언` | 적중마다 스택 — 다단히트 무기를 들면 스택이 폭증 |

**정할 것** — 앞으로 다단히트 스킬을 추가할 때 **발당 발동을 기본으로 할지, 공격당 1회를 기본으로 할지.**
기본값을 정해 두지 않으면 스킬마다 판단이 갈린다.

## 4. 내구 티어 스케일링

내구는 **고정값**으로 피해를 깎는다. 그런데 이 게임은 피해가 레벨에 선형 비례해 자란다.

| 구간 | 대략적 피해 | 내구 10의 경감률 |
| --- | --- | --- |
| Lv.1 | 200~300 | 3~5% |
| Lv.50 | 1,500 | 0.7% |
| Lv.100 | 3,000 | 0.3% |

**T1 값 그대로 두면 후반에는 없는 것과 같다.** 방어력은 기준값을 레벨에 연동해 이 문제를 피했지만,
내구는 "고정 경감"이 정체성이라 같은 수법을 쓸 수 없다.

### 선택지

| --- | --- |
| 1발 300 | 3% |
| 6발 × 59 | **17%** |

세이식 유도탄 빌드에 대한 자연스러운 대항 수단이므로, 이 성질을 유지할지도 함께 정한다.

## 5. 영입 사건 복원

### 판단 근거

사건은 테마마다 하나씩 **4개**로 늘었지만, **넷 다 `continue`뿐인 복선형이다.**
개수는 늘었는데 전력이 변하는 사건은 여전히 0개다.

| 미사용 액션 | 원래 담당하던 사건 |
| --- | --- |
| `recruit` | 수르트, 츠쿠요미 영입 |
| `battle_recruit` | 케찰코아틀 시련 |
| `battle_item` | 격노한 케찰코아틀 → 마카나 (아이템은 사문화되어 삭제됨) |
| `pay_gold` | 케찰코아틀 공물 |
| `grant_passive` | 월신의 가호 |

**현재 게임에는 전력이 변하는 사건이 하나도 없다.**
동시에 골드의 유일한 소비처(`pay_gold`)도 함께 사라져 항목 5가 더 급해졌다.

캐릭터가 늘면서 **막고 있는 것도 함께 커졌다.** 지금 Locked는 17명이고,
그중 다섯(호루스·바스테트·세트, 그리고 옥타비아·카이사르)은 전투 데이터와 아트가 모두 끝나 있다.
사건 하나가 막고 있는 콘텐츠가 캐릭터 절반이다.

### 선택지

| 안 | 내용 | 비고 |
| --- | --- | --- |
| **A** | 운영 테마마다 영입 사건 하나씩 신규 작성 | 세계관 정합. 테마별 소속 캐릭터를 그 테마에서 얻는다 |
| **B** | 기존 사건에 영입 선택지를 덧붙인다 | 5스테이지 슬롯 하나를 그대로 쓴다. 복선과 영입이 한 장면에 섞인다 |
| **C** | Locked 일부를 캐릭터 선택에서 바로 개방 | 사건 없이 해결. 서사 손실 |

> **권장: A + C.** C로 당장의 편성 부족을 풀고, A로 사건의 역할을 회복한다.
> A를 택하면 테마별 소속이 그대로 후보가 된다 —
> 로마 군단 → 옥타비아·카이사르, 메히코 → 케찰코아틀, 아스완 → 호루스·세트.

## 10. 회피율·코드 발동률 존폐

### 결정 사항

**DEX의 회피, INT의 발동률을 살릴 것인가 걷어낼 것인가?**

### 판단 근거

| 파생 | 현재값 | 상태 |
| --- | --- | --- |
| `GetDerivedEvasionChance()` | **0 고정** | 회피 판정 코드는 존재하나 파생값이 0 |
| `GetDerivedCodeActivationChance()` | **1.0 고정** | INT 기반 발동률이 무효화됨 |

문서상 DEX는 "속도 + 회피", INT는 "발동률 + 마나 효율"을 담당하지만 **각각 절반이 죽어 있다.**
코드 보유 한도(`max(3, INT)`)마저 폐지했으므로 **INT의 실질 기능은 마나 효율 하나뿐이다.**

> 한도를 없앤 이유는 밸런스가 아니라 결함이었다. 해금은 낮은 레벨부터 채워지므로 한도에 걸리면
> **가장 강한 고레벨 코드부터 잘렸고**, INT가 낮은 적(거인·씨앗 계열)은 설계된 해금의 절반도
> 얻지 못했다. 잘린 사실이 로그에도 남지 않아 기획과 실제가 조용히 어긋나 있었다.
> INT의 새 역할을 정하는 것은 이 항목의 범위다.

### 선택지

| 안 | 내용 |
| --- | --- |
| **A** | 파생 공식 부활 (예: 회피 `DEX × 0.3%`, 발동률 `50% + INT × 2%`) |
| **B** | 정식 제거 — 문서에서 지우고 DEX/INT에 다른 역할 부여 |
| **C** | 항목 1의 선택지 C와 통합 — DEX/INT를 화력 파생에 편입 |

> 항목 1에서 **선택지 C(5스탯 파생 화력)** 를 택하면 이 문제가 자연히 해소된다. 함께 결정하는 것을 권한다.

## 11. 서포트 카드 격차 정책

### 결정 사항

**첫 런(카드 없음)과 숙련 런(고급 카드)의 성장 격차를 얼마로 허용하는가?**

### 판단 근거

훈련 1회당 집중 스탯 강화량:

```
카드 없는 서포트 4명 (전원 특기 일치):
  1 + 4 × (1 + 1) = 9

고급 카드 서포트 4명 (전원 등장 + 특기 일치 + 우정 훈련):
  1 + 4 × (6 + 8 + 8) = 89
```

**약 10배 격차.** 100스테이지 누적이면 +900 vs +8,900이다.

현재는 첫 런에서 카드를 얻을 수 있는 캐릭터가 아탈란테뿐이라 **이 격차가 아직 관측되지 않는다.**
항목 4(메인 확충)를 해결하는 순간 곧바로 드러난다.

### 선택지

| 안 | 내용 |
| --- | --- |
| **A** | 격차 유지 — 계승 보상을 크게 (로그라이트 메타 진행 강조) |
| **B** | 카드 보너스 상한 하향 (`trainingBonus` 0~6 → 0~3 등) |
| **C** | 카드 없는 서포트의 기본 보너스 상향 (`SupportStatBonusPerUnit` 1 → 3) |
| **D** | 난이도를 육성 완료 캐릭터 수에 연동 |

> **선행 검증 필요.** 항목 1·2(성장 곡선·스케일)가 정해지기 전에는 이 격차가 실제로 어느 정도 체감되는지 계산할 수 없다.

# P2 — 콘텐츠와 완성도

## 12. 신규 테마 (스프라이트 선행)

운영 테마가 셋이 되어 **로마 군단 → 메히코 → 아스완**으로 순환한다.
로마 군단 12종은 전용 초상화가 없어 기존 스프라이트를 임시로 돌려 쓴다.
아스완은 파멸·종말의 성기사와 이단심문관, 명계의 사령, 타락한 사제,
오시리스, 아문·라까지 **전용 자산 8종을 모두 적용했다.**
호루스 조우는 영웅 호루스 자산을 의도적으로 공유한다.

전용 적 초상화가 없어 노르드(적 12종)·구 아즈텍(적 9종)·일본 테마를 제거했다.
아즈텍은 메히코 테마 7종과 케찰코아틀 조우로 전면 교체했으며 전용 스탠딩·초상화를 등록했다.
**일본·노르드 테마는 다시 추가하기로 확정**되었다. 일본 테마에는 보관 중인 츠쿠요미의
영입 사건을 붙인다. 수르트는 Starter로 개방되어 노르드 영입 사건이 필수 획득 경로는 아니다.

**테마를 늘리려면 아트 자산이 먼저다.** 순서는 다음과 같다.

1. 전용 적 초상화 확보
2. `60_enemies.yaml`에 해당 `themeId`의 normal 6~9종 + elite 1~2 + boss 1 등록
3. `80_stages.yaml` `stageThemes`에 항목 추가 (`enemyThemeId`를 적 `themeId`와 일치)
4. 테마 사건 추가 — **영입 사건을 함께 넣어 보관 캐릭터를 되살릴 것**

> 제거된 적 데이터는 git 히스토리에 남아 있으므로, 스프라이트만 준비되면 스탯을 새 규격으로
> 옮겨 되살릴 수 있다(5스탯만 재산정하면 된다).

## 13. 고정 보스 재설계

`fixedBossStages`가 **비어 있다.** 25/50/75/100 지점의 체크포인트가 사라졌다.

정할 것 두 가지다.

**네 지점의 보스를 각각 무엇으로 할 것인가.** 100스테이지는 육성 모드의 최종 보스이므로
전용 제작을 권한다.

슬롯 규칙은 이미 구현되어 있다 — 고정 보스가 낀 라운드는 2번 슬롯을 건너뛰고 이후를 1씩 당겨
마지막 칸을 비운다. 따라서 `fixedBossStages`에는 **각 라운드의 10번째 스테이지**를 적으면 된다
(3라운드 → 30, 5라운드 → 50, …).

> 🔸 원안의 지점 표기(25/50/75/100)는 라운드 내 위치와 맞지 않는다.
> 25·75는 라운드 내 5번, 50·100은 10번이다. 라운드 경계에 맞출지 스테이지 번호를 그대로 쓸지 정해야 한다.

## 14. 중간 보스 난이도

8스테이지 중간 보스(사비나)가 **단독 출현이라 약 11초 만에 끝난다.**
같은 라운드의 7스테이지(일반 5기)가 27.7초 걸리는 것과 비교하면 오히려 쉬운 구간이다.

**로마 군단은 이 문제를 호위 편성으로 피했다.** 중간 보스 슬롯(9)에 아그리파+옥타비아를
에퀴테스 ×2 + 센츄리온과 함께 세운다. `stagePatterns`가 보스 단독 스폰보다 우선하도록
엔진을 고쳐 두었으므로, **콜로세움에도 같은 처방을 그대로 적용할 수 있다.**

남은 결정: 사비나에게 호위를 붙일 것인가, 아니면 콜로세움은 단독 보스라는 성격을 유지할 것인가.

> 보스(10스테이지)는 20.4초로 적절하다. 문제는 콜로세움의 중간 보스 슬롯뿐이다.


모든 영웅의 `startingProficiencies`에 최소 무기 1종을 데이터화했다. 방어구 숙련은 캐릭터별로 두며, 숙련이 없는 캐릭터는 의복을 사용한다. 설정상 필요한 복수 무기·방패는 시작 숙련에 함께 둘 수 있다.
보주·단궁·쇠뇌 숙련을 추가했고, 시의 만류귀종과 아탈란테의 궁수/민첩함이 추가 숙련을 연다.
이미 가진 숙련을 다시 얻으면 별도 중첩 효과 없이 자연스럽게 무시된다.

## 18. 소환수 실체화 — 기억 정령 모델

**결정됨.** 소환수는 붕괴: 스타레일의 *기억 정령*과 같이 다룬다.

| 규칙 | 내용 |
| --- | --- |
| 칸 | 차지하지 않는다 |
| 피격 | **대상이 된다.** 체력을 가지며 쓰러질 수 있다 |
| 종속 | 소환자에게 묶인다. 소환자가 쓰러지면 함께 사라진다 |
| 행동 | 일반 유닛과 같다 — **DEX 기반 행동 게이지**로 자기 턴을 갖는다 |
| 궁극기 | 일반 유닛과 같다 — **INT 기반**으로 충전하고 발동한다 |
| 특수 사례 | 피그말리온의 `갈라테아`(220)처럼 **소환자 자신이 소환수 판정**을 받는 경우도 있다 |

해당 소환수: **펜리르**(로키 282) · **마카라**(바루나 66) · **플라이어**(라이트 5).

### 승격에 필요한 작업

현재 소환수는 `Combat.Summons`를 통해 소환자에 붙는 **논리 객체**다. 실체화는 전투 엔진을 건드린다.

| 단계 | 내용 | 상태 |
| --- | --- | --- |
| 1 | `Unit.SummonOwner` / `IsSummon` / `ActiveSummons` / `DismissSummons` | 구현 |
| 2 | "필드 위에 있는가"를 `Unit.IsOnField` 하나로 통합 | 구현 |
| 3 | 판정 사용처 교체 — `Target`, `BaseNormalCode`, `NormalAttack`, `ActionScheduler`, `GridManager` 조회 4종, `위대한 비행` | 구현 |
| 4 | `GridManager.SpawnSummon` — 칸 없이 진영 목록에만 등록 | 구현 |
| 5 | 소환수가 지나는 경로의 `currentCell` 널 안전화 + `Unit.RefreshView()` | 구현 |
| 6 | 소환자 사망·수명 만료·라운드 종료 시 정리 | 구현 |
| 7 | 카드 UI — `Entities.View.SummonCardView`가 소환자 칸 옆에 세운다 | 구현 |
| 8 | 라운드 정리에서 소환수가 `heroList`에 남지 않는지 | 구현 |
| 9 | 펜리르(로키) 이관 — 초상화·소형 카드 포함 | 구현 |
| 10 | **마카라(바루나) 이관** | 🔴 |

7번은 **에디터 작업이 필요 없었다.** `UnitCardView`가 프리팹이 아니라 코드로 조립되므로
(`UnitCardView.Attach`) 칸이 아닌 아무 트랜스폼에나 같은 카드를 얹을 수 있었다.

마카라가 남은 이유는 기술이 아니라 **기획이다.** 원안에 체력·능력치 비율이 없다.
플라이어는 "라이트 능력치의 50%, 3턴"이 명시돼 있었고, 펜리르는 초상화가 준비되면서
같은 50% 규격을 임시로 빌려 이관했다(🟡 — 확정된 수치가 아니다).

### 카드 표시

소환수 카드는 **소환자 카드의 1/4 크기(한 변 1/2)** 로 아래 모서리에 겹쳐 세운다.
아군은 왼쪽 아래, 적은 오른쪽 아래 — 카드가 공격할 때 적 방향으로 전진하므로 반대편에 둔다.
1/9(한 변 1/3)도 후보였지만, 소환수는 체력을 가지고 격파당하므로 **체력 바를 읽을 수 있어야 한다.**
한 변이 1/3이면 바가 몇 픽셀로 뭉개져 "곧 죽는다"를 눈으로 알 수 없다.

### 승격이 바꾸는 것

소환수가 실제 개체가 되면서 **광역기의 대상 수가 늘어난다.** 적 광역기는 소환수도 때리고,
'공격한 대상마다' 세는 코드는 소환수까지 세며,
세이의 `창세` 같은 '아군 전체'에도 소환수가 포함된다. 의도된 방향이지만 밸런스 확인이 필요하다.

## 27. 씨앗 자폭 피해 규모 — ✅ 해결

비율을 **20%/40% → 8%/16%** 로 내렸다. 구조는 그대로 최대 체력 비례다.

| | 이전 | 지금 |
| --- | ---: | ---: |
| 자폭 | 최대 체력 20% | **8%** |
| 대폭발 | 최대 체력 40% | **16%** |

**상한도 구조 변경도 필요 없었다.** 씨앗과 아군의 체력이 같은 기울기로 자라서
아군 체력 대비 비율이 20레벨과 100레벨에서 거의 같기 때문이다 — 후보 B·C는 버렸다.

목표는 "방어막으로 받아 내는 크기"였다. 대폭발 한 방이 CON 비주력 아군 최대 체력의
**85~90%**라 맨몸이면 빈사가 되고 방어막 한 겹이면 넘어간다. 일반 씨앗은 26%씩이라
한 마리로는 위협이 못 되고 **넷이 동시에 터질 때만** 후열이 죽는다 —
광역으로 한꺼번에 쓸지 말라는 뜻이고, 그래도 쓸 거면 방어막이 답이다.

수치표는 [Detail_09 §7-A](Detail_09_Enemy_Catalog.md)를 본다.

## 28. 사망이 라운드를 넘는가 — 아누비스 '죽은 자의 소생'의 전제

아누비스 Lv.38 `죽은 자의 소생`(102)은 **전투가 끝나면 그 라운드에 쓰러진 아군 하나를
되살린다.** 코드는 구현했지만 지금은 눈에 보이는 차이를 만들지 못한다.

| 축 | 현재 동작 |
| --- | --- |
| 스냅숏 시점 | `GameManager.SaveAllyFieldState`가 **전투 시작 직전**에 필드 아군을 기록한다 |
| 복원 시점 | `EndRound`가 `RestoreAllyFieldState`로 그 스냅숏을 그대로 되돌린다 |
| 결과 | 쓰러진 아군도 다음 라운드에 **전투 시작 시점의 체력으로 되살아난다.** EXP도 복원 뒤에 지급되므로 사망 페널티가 없다 |

즉 **사망은 라운드 안에서만 유효하다.** 부활 코드가 값을 가지려면 사망이 라운드 밖까지
남는 규칙이 먼저 있어야 한다.

| 후보 | 내용 |
| --- | --- |
| **A** | 사망을 라운드 밖으로 넘긴다 — 쓰러진 아군은 다음 라운드에 편성 불가, 소생·회복 수단으로만 복귀 |
| **B** | 사망 페널티를 체력·EXP 손실로 표현하고, 소생은 그 손실을 되돌리는 코드로 바꾼다 |
| **C** | 코드 문구를 '전투 중 1회 부활'로 고쳐 라운드 안에서 완결시킨다 |

`Detail_08 §29.2`·`Detail_11`·`Detail_12`에 🔸로 표시해 두었다.

## 30. 2026-09-08 반영 완료 — 공허 8테마 전 병종 연결

공허는 **원소별 여덟 테마**(기본·불·물·바람·번개·풀·얼음·바위)로 갈라지고, 한 테마 안에서는
편성 전원이 같은 원소를 두른다. 테마 id 8~15 / 적 themeId 9~16.
용·사수·선봉대까지 8색 전투 데이터·스프라이트 연결을 마쳤다.

| 슬롯 | 편성 | 상태 |
| ---: | --- | --- |
| 1·2 | 프리즘 | ✅ 8테마 |
| 3 | 늑대 ×3 · 괴조 ×2 | ✅ 8테마 |
| 4 | 멧돼지 ×3 · 괴조 ×2 | ✅ 8테마 |
| 5 | 사건 스테이지 | — |
| 6 | 사슴 ×1 (엘리트) | ✅ 8테마 |
| 7 | 기사 ×3 · 사수 ×2 | ✅ 8테마 |
| 8 | 선봉대 ×3 · 사수 ×2 | ✅ 8테마 |
| 9 | 분쇄자 ×1 (엘리트) | ✅ 8테마 |
| 10 | 용 ×1 (보스) | ✅ 8테마 |

여덟 테마 모두 `enabled: true`로 전환했다. 사건 슬롯인 5를 제외한 모든 전투 슬롯이
같은 원소의 병종으로 완성돼 순환에 들어간다.

### 확정된 결정

- **사슴은 6스테이지**다. 5스테이지는 사건 슬롯이므로 비운다.
- **9는 엘리트, 10은 보스** 등급이다. 사슴도 엘리트다.
  일반 등급이 아니므로 셋 다 천살성 처형 대상이 아니다.
- **사슴의 궁극기는 소환수가 아니다.** 기억 정령([§18](Design_Backlog.md))과 달리
  **칸을 차지하는 진짜 유닛**으로 늑대·멧돼지·괴조를 불러낸다.
  같은 테마의 그 유닛 그대로이며(원소 변형까지 동일) **사슴과 같은 레벨**이고,
  사슴이 쓰러지면 함께 쓰러진다. **빈 칸이 없으면 소환은 실패한다**(대기열 없음).
- **순환 비중은 다른 테마와 같게 둔다.** 공허 괴수와의 전쟁이 이 게임의 기본 구도라
  공허가 순환의 다수를 차지하는 것은 의도된 결과다. 앞으로 다른 테마를 더 늘려 맞춘다.
- **고유 패시브(P)는 독립 등급이다.** 은·금 사다리 밖의 보라색 `Unique`이며
  대체하지도 대체당하지도 않는다 — [Detail_12 §3.3](Detail_12_Code_Weapon_Catalog.md).
- 아트 접미사는 표준 원소명(`_PYRO`·`_HYDRO`·…)을 쓴다. `_CONDUCTION`(전도)은 삭제했고
  `_NATURE`→`_DENDRO`, `_TORRENT`→`_HYDRO`로 옮겼다.

### 🟡 확인이 필요한 수치

- **사슴의 스탯**은 첫 등록을 위해 STR 40+5 · CON 48+5의 임시 엘리트 기준을 쓴다.
- **분쇄자·용의 스탯**은 기존 엘리트·보스(종말의 거인, 아문·라)에 맞춘 임시값이다.
- **`완전함`(최대 체력 ×3) × `천무지체`(공격마다 최대 체력 5%)** 가 곱해진다.
  분쇄자가 60레벨에 CON 약 414라면 최대 체력 124,200, 추가타 6,210이다.
- **용의 `완전한 부활` × `완전함`** 도 곱해져 실질 체력이 최대 체력의 6배가 된다.

| 플라이어 실체 | 🔴 **기억 정령으로 승격 예정**(§18). 현재는 칸·체력 없는 논리 소환수 |
| 플라이어 행동 | 🔴 **확정: DEX 기반 자기 턴, INT 기반 궁극기** — 일반 유닛과 동일.
  현재 구현은 승격 전 임시안으로 라이트의 1·2턴에 N, 3턴째 U를 추가행동으로 쓴 뒤 소멸 |
| 스냅샷 | DEX·INT·치명타 확률은 소환 시점 50%, 치명타 피해는 라이트 값을 사용 |
| 공격 태그 | 소환·추가행동·대상 범위만 부여. 물리/특수 및 접촉 여부는 미정 |
| U 마나 동률 | 최대 마나가 같은 아군 중 무작위. 마나 비사용자는 최대 마나 0 |
| P 소비 순서 | 라이트 자신의 U도 먼저 +1한 뒤, 해소 시점에 3스택을 소비 |
| 부정 효과 범위 | `StatusCategory.Negative`인 모든 상태를 제거 |
| 아트 | `LIGHT_PORTRAIT` / `LIGHT_STANDING` 등록 완료 |

특히 플라이어를 실제 `Unit`으로 승격할지와 U 충전 조건을 먼저 정해야 소환수 대상 버프·피격·사망·
행동 게이지 상호작용을 확정할 수 있다. 실제 개체화는 항목 18과 함께 결정한다.
