# UI 전면 재검토 · 2026-10-08

최종 갱신: **2026-10-08**. 현재 사용자 지시와 `rework/core-stats` 구현 기준.

## 기준 구조와 검수 방식

적 카드의 **스탠딩 원화 + 하단 정보판**을 전투의 기준으로 유지한다. 아군 역시 같은 구조를 사용한다. 원화를 새 흰 카드에 가두거나 줄이는 접근은 폐기했다. **최신 방향은 원신 계열 게임의 UI 구조와 블루 아카이브의 청량함이다. Apple 유리 재질은 선택 사항이며 사용자 최신 지시에 따라 완성도와 충돌하면 버린다.** 명일방주의 구조와 스타레일 HUD는 이전 관찰 기록이며 최신 미술 방향을 강제하는 기준으로 사용하지 않는다. Apple의 유리 재질은 헤더와 배경의 깊이를 위한 참고이고, 본문 가독성보다 우선하지 않는다. 기본 UI 잉크는 군청이며 원소·피해·체력·상태에만 의미 있는 색을 사용한다.

종전 검증 통과는 기능 검사 결과였다. 사용자가 거부한 이전 화면에 출시 수준의 시각 품질 인증을 붙이지 않는다. 이번에도 자동 검사 통과와 시각 검수 결과를 따로 기록한다. `Logs/UIResetTreasure20261008/Rejected-First`는 이번 첫 결과의 실제 실패 증거이며, Opus의 독립 지적은 `opus-independent-review.md`에 남긴다.

## 합격을 나누어 판단할 항목

- 전투: 아군과 적의 이름·현재 체력·초월 자원을 동일 위치에서 읽을 수 있는가. 원화의 얼굴과 상태 알림이 겹치는가. 상태 알림에는 말풍선과 윤곽 프레임을 만들지 않는다.
- 행동 설명: 1·2·4배속과 별도 정지를 유지하는가. 행동 서열의 확장은 실제 행동 종료까지 유지하는가. 준비 상태가 전투 중 그대로 남지 않는가.
- 편성: 원화와 이름 칸을 분리했는가. 현재 선택과 추천을 구분할 수 있는가. 목록 끝이 잘렸을 때 계속 스크롤할 수 있다는 신호가 있는가.
- 코드: 활성 7칸과 보관의 티어·이름·효과 문법이 일치하는가. 빈 칸은 사용법을 안내하는가. 선택 칸과 드롭 가능한 칸을 혼동하지 않는가. 드래그 중 툴팁을 숨기고 취소·교환·보관·전투 잠금이 작동하는가.
- 상점·보상: 커다란 빈 아이콘 영역보다 효과 비교를 우선하는가. 가격·구매 제한·받을 유닛·비활성 사유를 읽을 수 있는가. 전체 카드와 버튼의 구매 결과가 일치하는가.
- 자료실·툴팁: 용어 링크의 중첩 패널이 서로 또는 원래 링크를 덮지 않는가. 뒤로 가기·검색·첫 화면·닫기를 중복시키지 않는가. 탐색 기록과 검색 위치를 복원하는가.
- 공통: 클릭·호버·키보드 선택·비활성 상태가 분리되는가. 제목·본문·보조문구의 계층이 분명한가. 사용자 최신 지시에 따라 1920×1080과 UI/글자 배율 조합에서 글자·하단판·버튼이 잘리지 않는가.

기능 검사뿐 아니라 실제 캡처를 직접 확인하고 수정한다. 프로젝트 상태의 시각적 완성도를 대기업 출시 품질이라고 무조건 단정하지 않는다. 확인되지 않은 화면이나 남은 결함은 검수 기록에 별도 남긴다.

## 최신 구조 변경 · 얇은 화면으로 다시 설계

사용자가 “뚱뚱해지기만 했다”고 지적한 `Rejected-Fat-Source` / `Rejected-Fat-960`의 큰 내부 카드는 폐기했다. 크기를 키워 글자를 넣는 방식에서 목록·본문·조작의 정렬로 전환했다.

- 헤더 100→64px, 상단 바 72→56px, 준비 리본 128→72px. 반복된 라틴 소제목과 장식 면 제거.
- 활성 7코드는 세로 7행, 개인 보관은 4열 이름 목록. 코드 상세는 프레임 없이 오른쪽 열.
- 상점은 3개 비교 열, 보상은 132px 비교 행, 보급은 104px 목록. 보상·보급은 내용량에 따라 창 높이를 조절하고 선택 흐름에서는 필요한 공간 확보.
- 편성의 후보·선택 원화·출전 명단 사이 중첩 배경 제거. 자료실의 6개 안내는 상자 대신 목차 행으로, 분류는 아이콘+이름 한 줄로 표시.
- 설정은 단일 탭 이름과 가는 선택 표시, 본문은 읽기 면 하나. ESC 메뉴는 기능 이름·결과 설명을 같은 행에 정렬.
- 휴식은404px 비교 창, 로그는 기록량에 맞춘 높이. 공통 헤더에 기능별 작은 기호/제목 기준선을 사용하고, 사건/결과의 빗금은 제거했다.
- 부여 알림은 얼굴과 정보판의 실제 화면 영역을 검사한다. 다른 유닛 얼굴 위로 이동시키지 않으며 빈 자리를 기다려 순서대로 표시한다.

[원신 · COGNOSPHERE 공식 배포 화면](https://play.google.com/store/apps/details?id=com.miHoYo.GenshinImpact&hl=en)의 나틀란 탐색 스크린샷도 확대 확인했다. 전장을 넓게 남기고 지도·기능 아이콘을 가장자리에 모은 배치를 관찰했다. 메뉴 전체를 직접 플레이했다는 의미는 아니며, 본문/편성은 그 관찰과 이 프로젝트의 정보량에 맞춘 자체 구성이다.

`Slim1-1920`은 첫 구조 변경의 3개 기능 시나리오 통과. `Slim2-960`은 10개 기능 시나리오 통과했지만, 보급품 1종에서도 창이 과도하게 넓게 비어 있어 추가 보정을 진행했다. 이 단계의 캡처를 최종 승인본으로 취급하지 않는다. 최신 최종 판정은 `Logs/UIResetTreasure20261008/root-final-review.md`에서 해상도별 기능 결과와 직접 관찰을 함께 확인한다.

## 추가 공식 UI 조사 · 중앙 정렬과 게임 문법

[원신 공식 개발자 토론 · 2023-12-06](https://genshin.hoyoverse.com/en/news/detail/113872)의 실제 필터 설정·여행자 성장·성유물 성장·비경 진입 UI 이미지를 브라우저에서 확인했다. 이 자료는 4.3 개발 중 안내이며 2026 최신판 모든 메뉴를 플레이한 증거로 취급하지 않는다.

관찰: 읽을 수치는 일정한 우측 열, 원화/대상은 넓은 좌측 영역, 핵심 조작은 우하단에 모인다. 행 선택은 밝고 확실한 채움으로 구분하며 헤더/닫기/버튼은 각 영역의 중심선에 맞는다. 긴 상세 정보와 선택 목록은 역할이 다른 면으로 나뉘어 계층을 만든다. 이 관찰을 바탕으로 정보의 밀도와 아트 비중을 다르게 배분하고, 임의의 새 기능을 추가하지 않는다.

사용자 최신 지시의 div는 이 프로젝트에서 RectTransform 컨테이너에 대응한다. 검수는 컨테이너 경계의 일치뿐 아니라 실제 TMP 글자, 아이콘 중심, 버튼 내용의 상하 중앙과 같은 행의 시각적 기준선을 포함한다. 좌우 패딩만 정돈해서 합격으로 처리하지 않는다. Apple 재질 고집은 이번 의뢰의 필수 조건에서 제거했다.

## 메뉴 범위 비교 보강

공식 개발자 자료를 보완하기 위해 UI 사례 아카이브의 원신 모바일 [상점](https://interfaceingame.com/screenshots/genshin-impact-mobile-shop/), [캐릭터 상세](https://interfaceingame.com/screenshots/genshin-impact-mobile-attributes/), [자료실](https://interfaceingame.com/screenshots/genshin-impact-mobile-archive/), [아이템 교체](https://interfaceingame.com/screenshots/genshin-impact-mobile-weapon-selection/) 캡처도 브라우저에서 직접 읽었다. 초기 모바일 UI의 공개 사례이며 현재 PC판 전체 기능의 근거로 쓰지 않는다.

상점은 카테고리와 상품 표현을 구분하고 가격/구매는 상품의 행동 영역 안에 모인다. 상세/교체는 대상 이미지와 읽을 수치·효과·행동을 분리한다. 자료실은 큰 범주 기호로 입구를 만들고 선택 항목에 밝기·크기 차이를 준다. 실제 원신의 별·화폐·배경·외부 아이콘은 복제하지 않고 이 프로젝트의 티어 눈금·군청·기존 원화로 자체 문법을 만든다. 이번 방향은 Apple 재질로 덮는 것이 아니라 이러한 대상/목록/상세/행동의 게임 구조를 우선한다.

스타레일의 [캐릭터 상세](https://interfaceingame.com/screenshots/honkai-star-rail-character-details/)와 [메뉴](https://interfaceingame.com/screenshots/honkai-star-rail-character-menu/) 초기 공개 캡처도 직접 확인했다. 상세는 원화 공간을 크게 두고 능력치를 짧은 우측 열에 모으며, 메뉴는 세계/캐릭터를 남긴 채 기능 영역을 한쪽에 한정한다. 이 자료 역시 현행 버전 모든 메뉴의 직접 플레이 검증을 대신하지 않는다. NeverTheLast의 대량 코드 관리 화면은 정보량이 다르므로 그대로 복제하지 않고 선택/상세/행동의 역할 구분과 정렬 문법을 적용한다.
