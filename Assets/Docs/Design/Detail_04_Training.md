## 1. 육성 페이즈

육성 모드에서 스테이지 사이마다 실행된다.

**흐름**

```
보상 선택 완료
  → GameManager.EnterTrainingPhase()   [GameState.TrainingPhase]
  → UI에서 5스탯 중 하나 선택
  → CompleteTrainingPhaseWithFocus(focus)
      · TrainingManager.ApplyTraining(focus)
      · preparationActionUsed = true      ← 준비 페이즈 행동을 소모한 것으로 처리
      · 세이브
  → GameState.Preparation
```

준비 페이즈에서 직접 진입할 수도 있다 (`OpenTrainingFromPreparation`).

## 2. 집중 훈련 기본 수치

`TrainingManager` 상수

| 상수 | 값 | 의미 |
| --- | --- | --- |
| `SupportStatBonusPerUnit` | **1** | 서포트 카드가 없는 서포트 1명당 추가량 |
| `AffinityBonusPerUnit` | **1** | 카드 없는 서포트의 최고 스탯과 집중 스탯이 일치할 때 추가량 |
| `TrainingLevelGain` | **1** | 육성 페이즈마다 오르는 트레이닝 레벨 |
| `OffSpecialtyAppearanceRate` | **35** | 특기가 아닌 스탯 훈련 시 서포트 등장률(%) |
| `FailureEnergyPenalty` | **10** | 훈련에 실패하면 추가로 잃는 체력 |
| `MaxBond` | `SupportBondState.MaxBond` | 우정도 상한 |

```
상승 = floor( (훈련 레벨 기본치 + Σ서포트 보너스) × 컨디션 배율 × 개인 배율 × 서포트 효율 배율 )
```

기본치는 상수가 아니라 **훈련 레벨(1~5)별 표**다 — §2.2. 훈련 레벨은 같은 훈련을 성공할 때마다
오르고 5에서 멈춘다.

### 2.1 카드 없는 서포트 (육성 미완료 캐릭터)

**서포트는 편성이 정하고, 카드는 완주 기록이 정한다.** 메인 외 넷은 언제나 서포트로 참여하지만,
`SupportCardSaveData`는 그 캐릭터가 **육성을 완주했을 때**만 생긴다(`TrainedCharacterRecord`).
완주 기록이 없는 동료는 아래 값으로 참여한다.

| 조건 | 보너스 |
| --- | --- |
| 이번 훈련에 앉음 | +1 |
| 집중 스탯 == 서포트의 현재 최고 5스탯 | +1 추가 |

| 판정 | 카드 없음 | 카드 있음 |
| --- | --- | --- |
| 특기 훈련에 앉을 확률 | `DefaultSpecialtyRate` 45% | `specialtyRate` 20~85% |
| 특기에 못 앉았을 때 | 35%로 다른 훈련, 나머지는 결석 | 같음 |
| 훈련 보너스 | +1 (+1 특기) | `trainingBonus` + `specialtyBonus` + 우정 |

> 🔸 예전 문서에는 "카드가 없으면 등장 판정 없이 항상 참여한다"고 적혀 있었으나 **코드와 다르다.**
> `RollPlacement`는 카드 유무와 무관하게 모든 서포트의 자리를 굴린다. 카드가 없으면
> 특기율만 기본값 45%를 쓴다.

### 2.1.1 런 도중 합류한 동료

서포트 목록은 편성표가 아니라 **현재 살아 있는 아군**에서 뽑는다
(`GetSupportUnits` = `heroList` 중 메인이 아닌 활성 유닛). 그래서 사건으로 영입한 동료
(`GameManager.RecruitSupportUnit`)는 **벤치에 앉은 그 순간부터 서포트다.**

| 시점 | 동작 |
| --- | --- |
| 영입 직후 | 벤치에 스폰(빈 자리가 없으면 필드). 그 즉시 서포트 목록에 든다 |
| 같은 턴의 훈련 화면 | `EnsureSupportPlacement`가 **새로 합류한 동료의 자리만** 굴린다. 이미 굴린 자리는 건드리지 않는다 |
| 힌트 후보 | 그 동료의 `levelPassives`(카드가 있으면 카드의 보유 패시브) |
| 라운드·저장 | 벤치 유닛은 필드 스냅샷 복원 대상이 아니고 런 세이브에는 `isBench`로 실린다 |

**로스터가 커지면 힌트 공급도 같이 는다.** 서포트가 넷에서 여덟이 되면 한 훈련에 앉는
평균 인원이 약 0.5명에서 1명으로 늘어 힌트가 대략 두 배가 된다. 스킬 Pt 수입은 그대로이므로
**늘어나는 것은 고를 폭이지 배우는 개수가 아니다** — 총 습득 수는 언제나 Pt가 정한다.
힌트 레벨 할인이 "한 계열을 파는" 선택에 값을 붙인다.

### 2.2 체력

`TrainingState.Energy` — 0~100, 런 범위. 스테이지가 넘어가도 저절로 차지 않는다.
**런 하나를 관통하는 단일 예산**이며, 이 예산을 어떻게 쪼개 쓰느냐가 육성 루프의 유일한 긴장이다.

| 훈련 | 스탯 | 체력 | 스킬 Pt | 훈련 레벨 1~5 기본 상승치 |
| --- | --- | ---: | ---: | --- |
| 근력 | STR | −20 | 2 | 3 · 4 · 5 · 6 · 8 |
| 민첩 | DEX | −18 | 2 | 3 · 4 · 5 · 6 · 8 |
| 체력 | CON | −16 | 2 | 3 · 4 · 5 · 6 · 8 |
| 행운 | LUK | −14 | 3 | 3 · 4 · 5 · 6 · 8 |
| 지능 | INT | **+5** | 4 | 2 · 3 · 4 · 5 · 6 |

**몸을 쓰는 훈련이 비싸고, 머리를 쓰는 훈련은 오히려 쉰다.** 지능은 상승치가 한 단계 낮은 대신
실패하지 않고 체력을 되돌린다 — 휴식 말고 하나 더 있는 가벼운 선택지다.

**실패율은 체력 하나만 본다.**

| 구간 | 체력 | 실패율 |
| --- | --- | --- |
| 안전 | 60~100 | 0% |
| 주의 | 30~59 | `(60 − 체력) × 0.6` → 최대 18% |
| 위험 | 0~29 | `18 + (30 − 체력) × 1.6` → 최대 66% |

실패하면 **상승 0 · 훈련 레벨 그대로 · 스킬 Pt 0 · 체력 추가 −10 · 컨디션 한 칸 하락**이다.
컨디션 하락까지 붙는 이유는, 대가가 그 턴 안에서 끝나면 실패율 60%를 감수하고 굴리는 쪽이
늘 이득이 되기 때문이다.

**리듬** — 평균 비용 17에 휴식 +50이므로 정상 상태는 **훈련 3회 : 휴식 1회**, 곧 가동률 75%다.
가장 비싼 근력조차 가득 찬 체력에서 세 번까지는 안전지대에서 출발한다(100 → 80 → 60).
100스테이지 런이면 훈련 약 75회 · 휴식 약 25회가 된다.

### 2.3 컨디션

5단계 배율이며 훈련 상승치에 그대로 곱해진다.

| 최상 | 좋음 | 보통 | 나쁨 | 최악 |
| ---: | ---: | ---: | ---: | ---: |
| ×1.10 | ×1.05 | ×1.00 | ×0.95 | ×0.90 |

훈련이 끝날 때마다 흔들린다 — 55%는 그대로, 나머지는 한 칸 오르내린다.
체력이 40 미만이면 나빠지는 쪽으로 기운다. **확실히 올리는 수단은 휴식뿐이다.**

### 2.4 휴식

준비 페이즈 행동 하나를 쓴다(`GameManager.RestFromPreparation`). 세 가지를 한 번에 돌려준다.

| 효과 | 값 | 근거 |
| --- | --- | --- |
| 훈련 체력 | **+50** (`RestEnergyRecovery`) | 훈련 3회분 |
| 컨디션 | **한 칸 개선** | 훈련은 흔들기만 하므로 되돌릴 수단이 하나는 있어야 한다 |
| 파티 체력 | **최대 체력 30%** (`RestPartyHealRatio`) | 최후의 안전판. 완전 회복은 값을 치르는 쪽의 몫 |

> 예전에는 휴식이 파티를 **완전 회복**시켰다. 스테이지마다 공짜 엘릭서를 쓰는 셈이라
> 상점의 회복약과 회복 보상이 통째로 무의미했다 — [Detail_05 §1.3](Detail_05_Economy.md).

**보스 스테이지에서는 훈련도 휴식도 막힌다**(`IsPreparationLimitedToDeck`).
10스테이지 주기마다 체력을 미리 채워 두어야 하고, 보스 직전의 체력 회복은 상점이 맡는다.

**스킬 Pt의 소비처는 스킬 힌트 습득 하나다** — §6. 훈련마다 2~4씩 쌓이고,
준비 페이즈의 스킬 화면에서만 빠져나간다.

## 3. 서포트 카드

육성을 완료한 캐릭터가 남기는 훈련 보조 데이터 (`SupportCardSaveData`).

### 3.1 카드 필드와 생성 공식

`RunManager.BuildSupportCard()` — 런 완주 시 1회 생성된다.

| 필드 | 생성 공식 | 범위 |
| --- | --- | --- |
| `specialtyTraining` | 80% 확률로 최고 스탯, 20%는 5스탯 무작위 | STR/DEX/CON/INT/LUK |
| `specialtyRate` | `clamp(rand(35,60) + 트레이닝레벨 / 8, 20, 85)` | 20~85 |
| `specialtyBonus` | `clamp(1 + 특기스탯값 / 35 + rand(0,1), 1, 8)` | 1~8 |
| `trainingBonus` | `clamp(rand(0,2) + sourcePower / 250, 0, 6)` | 0~6 |
| `skillTransferRate` | `clamp(10 + 전수가능패시브수 × 6 + LUK / 8 + rand(0,10), 5, 70)` | 5~70 |
| `initialBond` | `clamp(20 + 트레이닝레벨 / 3 + rand(0,15), 0, 75)` | 0~75 |
| `bondGainRate` | `clamp(1 + rand(0,2) + 트레이닝레벨 / 50, 1, 6)` | 1~6 |
| `friendshipBonus` | `clamp(1 + specialtyBonus / 2 + rand(0,2), 1, 8)` | 1~8 |
| `sourcePower` | `5스탯합 + 트레이닝레벨 × 3 + Σ(패시브 stage × 10)` | — |

**설계 의도**

- `sourcePower`가 `trainingBonus`에 반영되므로 **잘 키운 캐릭터일수록 상시 보너스가 크다**
- `specialtyRate`도 트레이닝 레벨에 비례 → 잘 키울수록 **자주 등장한다**
- 무작위 요소가 섞여 있어 같은 캐릭터를 다시 육성할 이유가 생긴다

### 3.2 카드 보유 서포트의 훈련 기여

| 조건 | 보너스 |
| --- | --- |
| 등장 | `+trainingBonus` |
| 등장 + 특기 일치 | `+specialtyBonus` 추가 |
| 등장 + 특기 일치 + **우정도 75 이상** | `+friendshipBonus` 추가 (= **우정 훈련**) |

### 3.3 등장 판정

```
특기 일치  → specialtyRate (%)  로 판정
특기 불일치 → 35% (OffSpecialtyAppearanceRate) 로 판정
```

## 4. 우정도(Bond)

| 항목 | 값 |
| --- | --- |
| 소유 | `RunManager.SupportBonds` — **런 범위 상태** |
| 초기값 | 카드의 `initialBond` (없으면 0) |
| 증가 | 등장 시 `bondGainRate`, 특기 일치면 **+1 추가** |
| 우정 훈련 발동 | **75 이상** |

### 4.1 우정도를 건드리는 코드

찬드라가 둘을 함께 갖는다. **앞뒤가 맞물린다** — 하나는 닿는 속도를, 하나는 닿은 뒤의 크기를 올린다.

| 코드 | Lv | 보유 | 효과 | 곱해지는 자리 |
| --- | ---: | --- | --- | --- |
| 109 카피바라 | 10 | 찬드라 · 프레이아(Lv1) | 우정도 획득 **+25%** | `bondGainRate` |
| 108 봉우 | 27 | 찬드라 · 수리야 | 우정 훈련 보너스 **+50%** | `friendshipBonus` |

프레이아는 앞쪽 절반만 가져간다. 초기 로스터에서 거의 항상 편성되는 서포트라
**우정도가 빨리 차오르는 길을 하나 더 여는 것**까지가 몫이고, 크기를 키우는 봉우는 찬드라에게 남는다.

둘 다 **필드에 서 있기만 하면** 적용된다(`TrainingManager.BondGainMultiplier` ·
`FriendshipBonusMultiplier`). 여러 명이 들어도 가장 큰 하나만 센다.
| 초기화 | 런 시작 시 (`StartRun` → `SupportBonds.Clear()`) |
| 저장/복원 | `RunSaveData.supportBonds` |

> `RunManager`가 없는 상황(에디터 진입 직후 등)을 위한 폴백 인스턴스가 `TrainingManager`에 있다.

## 5. 훈련 1회 처리 순서

`TrainingManager.ApplyTraining(focus)`

```
1. RollSupportTraining(focus) — 서포트별로:
     a. 육성 기록 조회 → 서포트 카드 확인
     b. 특기 일치 여부 판정
     c. 등장 판정 (카드 없으면 무조건 등장)
     d. 등장 시:
          카드 있음 → trainingBonus
                     + (특기일치 ? specialtyBonus : 0)
                     + (특기일치 && 우정 >= 75 ? friendshipBonus : 0)
                     우정도 += bondGainRate + (특기일치 ? 1 : 0)
          카드 없음 → 1 + (최고스탯 일치 ? 1 : 0)

2. 총 강화량 = 1 + Σ(등장 서포트의 보너스)

3. 메인에 적용:
     main.AddStatUpgrade(focus, gain)
     main.GainTrainingLevel(1)
     ApplySkillTransfers(main, rolls)
     main.AddExp(30 + 5 × Stage)        → 레벨업 시 RefreshLevelPassives() 트리거

4. TrainingResult 반환 (UI 표시용)
```

### 5.1 TrainingResult

| 필드 | 내용 |
| --- | --- |
| `Focus` | 선택한 집중 스탯 |
| `StatGain` | 총 강화량 |
| `SupportBonus` | 서포트 기여 합계 |
| `AffinityBonus` | 그중 특기/우정 보너스 몫 |
| `NewTrainingLevel` | 갱신된 트레이닝 레벨 |
| `SupportMessages` | 서포트별 로그 (`이름: 참여, +N, 우정 A->B / 우정 훈련 / 패시브 X 전수`) |
| `TransferredPassiveIds` | 이번에 전수받은 패시브 ID |

## 6. 스킬 힌트와 습득

우마무스메의 힌트 제도를 그대로 옮겼다. **훈련은 힌트만 흘리고, 배우는 것은 플레이어가
준비 페이즈에서 스킬 Pt를 치러 고른다.**

```
훈련 → 등장한 서포트가 확률로 힌트를 흘린다   (TrainingManager.ApplySkillHints)
     → 힌트가 런 상태에 쌓인다                (SkillHintState)
준비 페이즈 → 스킬 화면에서 스킬 Pt로 습득     (TrainingManager.TryLearnSkill)
```

> 예전에는 훈련이 패시브를 **즉시 전수**했다. 플레이어가 개입할 여지가 없었고,
> 전수된 코드는 `grantedPassiveCodeIds`에 남지 않아 **라운드가 끝나 유닛을 스냅샷에서
> 다시 세우는 순간 사라졌다**. 지금은 습득이 전부 영구 경로(`GrantPermanentPassive`)를 지난다.
> 이 개편으로 스킬 Pt는 죽은 자원에서 이 시스템의 유일한 화폐가 됐다.

### 6.1 힌트 발생 조건

등장한 서포트마다 훈련 1회에 **한 번** 굴린다. 등장하지 않은 서포트는 굴리지 않는다.

| 서포트 | 힌트 확률 |
| --- | --- |
| 카드 보유 | `skillTransferRate` (0~70%) |
| 카드 없음 | `CardlessHintRate` **20%** |
| 특기 훈련에 앉음 | 위 값에 `HintSpecialtyBonus` **+15%p** |

**카드는 편성이 아니라 완주 기록이 만든다**(§2.1). 메인 외 넷은 첫 런에서도 서포트로 참여하지만
그 넷의 카드는 아직 없으므로, 카드 보유자만 힌트를 흘리게 두면 **완주 기록이 생기기 전까지
스킬 화면이 늘 비어 있다.** 카드 없는 동료의 20%가 그 구멍을 메운다.

영입으로 합류한 동료도 같은 규칙을 그대로 쓴다 — §2.1.1.

첫 런 기준 대략의 흐름은 이렇다. 서포트 한 명이 고른 훈련에 앉을 확률은 특기면 45%,
아니면 약 4.8%다. 넷이면 한 훈련에 평균 0.5명이 앉고, 거기에 힌트율 20%(특기면 35%)가 붙어
**훈련 1회당 약 0.11개**, 100스테이지 런의 훈련 75회면 **8~9개**의 힌트가 쌓인다.
같은 런의 스킬 Pt 총량이 170 안팎이므로 은 8개를 살 수 있다 — 힌트 수와 값이 맞물린다.

`skillTransferRate`는 이름이 전수 시절 그대로다(저장 포맷 필드라 바꾸지 않았다).
지금 뜻은 **힌트율**이다.

### 6.2 힌트 후보

| 서포트 | 후보 목록 |
| --- | --- |
| 카드 보유 | 카드의 `ownedPassiveCodes` 중 `transferable`인 것 |
| 카드 없음 | 그 동료 정의의 `levelPassives` |

여기서 다시 거른다 — **공용 해금 패시브 구간(ID 1~179)** 밖, 메인이 이미 아는 것,
고유 패시브(`Transferable == false`), 이미 힌트 레벨이 최대인 것은 빠진다.

남은 후보를 **은과 금으로 갈라 놓고** 금 쪽을 `EnhancedHintChance` **20%** 로 뽑는다.
한 통에 섞으면 금이 몇 개냐에 따라 금 힌트 빈도가 제멋대로 흔들린다.

### 6.3 힌트 레벨과 값

같은 힌트를 다시 받으면 레벨이 오르고 값이 싸진다. 한 서포트를 같은 훈련에 계속 앉히는
선택에 보상이 붙는다.

| 힌트 레벨 | 비용 배율 | 은(20 Pt) | 금(60 Pt) |
| ---: | ---: | ---: | ---: |
| 1 | ×1.00 | 20 | 60 |
| 2 | ×0.85 | 17 | 51 |
| 3 (상한) | ×0.70 | 14 | 42 |

**기본값은 은 `SilverSkillCost` 20 Pt · 금 `EnhancedSkillCost` 60 Pt다.**
훈련 1회가 2~4 Pt를 주고 100스테이지 런의 훈련 횟수가 약 75회이므로, 한 런의 스킬 Pt 총량은
**170 안팎**이다. 곧 한 런에 은 8개, 또는 은 4개와 금 2개쯤을 배운다.

### 6.4 은금 사다리 — 금은 은을 밟고 올라간다

**금(강화) 코드는 대응하는 은(일반) 코드를 이미 배운 뒤에만 살 수 있다.**
선행 코드가 없으면 스킬 화면에 `선행 필요: ○○`로 잠긴 채 남는다.

사다리는 새로 적지 않는다. 은 코드가 이미 선언하고 있는
`PassiveCode.SupersededByCodeId`(= 나를 대체하는 금 코드)를 **거꾸로 뒤집어** 쓴다.
`PassiveCatalog`가 공용 구간을 한 번 훑어 `금 → 선행 은` 역색인을 만든다.
사다리를 새로 이어도 색인에 손댈 것이 없다 — 은 코드의 선언 한 줄이 곧 조건이다.

현재 아군이 끝까지 탈 수 있는 사다리는 셋이다.

| 은 | 금 |
| --- | --- |
| 2 기사회생 | 103 완벽한 재기 |
| 11 천살성 | 13 당연한 운명 |
| 70 의술 | 32 의신의 가호 |

`41 투사`도 은이지만 그 금(`1524 하루종일도 할 수 있어`)이 공허 전용 코드라 공용 구간 밖에 있다.
힌트로는 은까지만 올라간다. 전체 사다리 목록은 [Detail_12 §3.3](Detail_12_Code_Weapon_Catalog.md).

같은 계열의 두 등급을 함께 들면 `SupersededByCodeId`가 은 쪽 발동을 재우므로 효과가
겹쳐 쌓이지 않는다 — [Detail_12 §3.3](Detail_12_Code_Weapon_Catalog.md).

### 6.5 습득이 막히는 경우

스킬 화면의 카드에 사유가 그대로 적힌다.

| 사유 | 조건 |
| --- | --- |
| `이미 보유` | 메인이 그 코드를 이미 배웠다 |
| `선행 필요: ○○` | 금인데 대응 은이 없다 |
| `스킬 Pt 부족` | 값이 모자란다 |
| `습득 불가` | 고유 패시브 등 전수 불가 코드 |

**고유 패시브는 어떤 경로로도 넘어오지 않는다.** `UniquePassiveCode`가 생성 시점에
`Transferable = false`이므로 힌트 후보에서부터 걸러진다.
서포트가 넘겨줄 수 있는 것은 해금 패시브뿐이다.

> 스킬 Pt로 먼저 사 둔 코드는 나중에 레벨 해금 조건을 만족해도 다시 붙지 않는다
> (`Unit.RefreshLevelPassives`). 막지 않으면 같은 패시브가 두 벌 돌아 효과가 두 번 적용된다.

> **열화 전수본 제도는 폐지되었고 잔재도 전부 제거했다.** 예전에는 고유 P마다
> `TransferVersionCodeId`를 두고 열화판을 대신 넘겼으나, 그 필드와 사문 코드
> 230·231·233·224를 모두 삭제했다. 232만 이시스의 독립 해금 패시브
> `생명의 물`로 재편입되어 살아 있다.

## 9. 육성 밸런스 튜닝 노브

> 캐릭터 정의의 `mainStatTrainingBonus`/`subStatTrainingBonus`는 집중 훈련 1회의 획득량과 별개인
> 최종 스탯 보정 축이다. 일반은 주 +20%/부 +10%, 부스탯 둘이면 각 +5%, 세이·시는 +25%/+15%를 사용한다.

| 노브 | 현재값 | 영향 |
| --- | --- | --- |
| 훈련 체력 비용 | 14~20 (지능 −5) | 훈련 1회의 기회비용 |
| `RestEnergyRecovery` | 50 | 훈련 가동률(현재 75%) |
| `RestPartyHealRatio` | 30% | 휴식과 상점 회복약의 경계 |
| `FailureEnergyPenalty` | 10 | 저체력 강행의 대가 |
| 실패율 곡선 | 60/30 경계 | 안전지대의 넓이 |
| `CardlessHintRate` | 20% | 첫 런에서 힌트가 도는 속도 |
| `HintSpecialtyBonus` | +15%p | 특기 훈련에 앉히는 이유 |
| `EnhancedHintChance` | 20% | 금 스킬의 희소성 |
| `SilverSkillCost` / `EnhancedSkillCost` | 20 / 60 Pt | 한 런에 배우는 스킬 수 |
| `SupportStatBonusPerUnit` | 1 | 편성 인원수의 가치 |
| `AffinityBonusPerUnit` | 1 | 편성-훈련 시너지의 가치 |
| `OffSpecialtyAppearanceRate` | 35% | 특기 외 훈련의 기회비용 |
| 우정 훈련 임계값 | 75 | 장기 투자 회수 시점 |
| `specialtyRate` 상한 | 85% | 특기 훈련의 안정성 상한 |
| `skillTransferRate` 상한 | 70% | 힌트가 흐르는 속도 |

### 9.1 현재 밸런스 관찰

- 서포트 4명 전원이 카드 없이 특기 일치 시: `1 + 4×(1+1) = 9`/회. 100스테이지면 최대 **+900**
  (스탯 1점 = 위력 10 / 체력 100이므로, 이 강화량이 곧 후반 전투력의 핵심이다)
- 서포트 4명 전원이 고급 카드 + 우정 훈련 시: `1 + 4×(6+8+8) = 89`/회 — **10배 가까운 격차**
- 🔸 카드 유무에 따른 성장 격차가 매우 크다. 첫 런(카드 없음)과 이후 런의 난이도 체감이 극단적으로 갈릴 수 있다.
  현재 첫 런에서 카드를 얻을 수 있는 캐릭터가 아탈란테뿐이므로, **이 격차가 실제로 관찰되기 전에 캐릭터 확충이 선행되어야 한다.**
