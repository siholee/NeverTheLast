# 상세 기획서 16 — 원소와 원소 반응

> **3계층 문서.** 원소 두 축(속성·부착), 부착 규칙, 23쌍 원소 반응, 반응을 건드리는 코드,
> 아군의 부착 수단, 속성으로 판정하는 전장 상태, 테마별 반응 설계.
>
> 최종 갱신: 2026-10-07 — 공통 지속피해 4종·동일 원소 반응 폐지·불+풀 화상 전환. 원소 부착 효과 명중·확산 수신자별 저항·반응 상태 판정 상속 유지. 코드 원본은 `Effects/Negative/ElementalReactions.cs`, `Combat/ActionDot.cs`
> 와 `Unit.GrantCombatElement`다.

> **2026-10-07 구현 반영:** 감전·화상·맹독·저주 공통 시계와 츠쿠요미를 구현했다. 불+풀은 화상이며 같은 원소 반응은 바람·바위만 남긴다. 상세는 아래와 `Combat/ActionDot.cs`.


원소는 **전투 중 결정을 내리지 않는 이 게임에서 편성이 만드는 연쇄**다. 누가 어떤 원소를 걸고,
그 위에 누가 두 번째 원소를 얹는지를 전투 전에 짜 두면, 자동 전투가 그 설계를 대신 실행한다.

## 1. 원소 종류

`None, Pyro, Hydro, Dendro, Anemo, Electro, Cryo, Geo, Void` — 8종 + 무속성.

| 코드 | 이름 | 코드 | 이름 |
| --- | --- | --- | --- |
| `Pyro` | 불 | `Cryo` | 얼음 |
| `Hydro` | 물 | `Anemo` | 바람 |
| `Dendro` | 풀 | `Geo` | 바위 |
| `Electro` | 전기(번개) | `Void` | 공허 — **반응하지 않는다** (§4.9) |

> 기획서와 게임 안 문구에서 `Electro`는 **전기**와 **번개**를 함께 쓴다. 같은 원소다.

## 2. 속성과 부착 — 별개의 두 축

적에게 원소를 부착할 때는 시전자 특수공격력 대 대상 특수방어력의 효과 명중 판정을 거친다.
실패한 재부착은 기존 부착과 남은 기간을 보존하며 반응을 일으키지 않는다. 아군·자기 자신에게 주는 부착은 확정이다.
성공한 부착에서 생긴 반응 상태는 이 명중을 상속하고, 확산의 새 수신자는 각자 판정한다([Detail_02 §3.5](Detail_02_Combat.md)).

원신과 같은 모델이다. **유닛의 속성(고유 원소)은 원소 반응의 재료가 아니다.**
바위 유닛이라는 사실만으로 바위가 '부착'된 것은 아니며, 반응을 일으키려면
누군가 실제로 원소를 걸어 주어야 한다.

| 축 | 담는 곳 | 반응 재료 | 조회 | 걷히는가 |
| --- | --- | --- | --- | --- |
| **속성(고유 원소)** | `_judgementElements` | ✕ | `HasCombatElement` | 걷히지 않는다 |
| **부착 원소** | `_combatElements` | O | `HasCombatElement` · `HasAttachedElement` | 반응·만료·라운드 종료 |

- **조건 판정**(원소 숙련 `X 원소를 보유한 적에게 +N%`, 원소 친화 등)은 두 축을 함께 보므로 속성만으로도 성립한다.
- **반응 재료**는 `HasAttachedElement`, 즉 부착 축만 본다.
- 자기 속성과 같은 원소를 부착받아도 다른 원소와 똑같이 **지속시간이 붙는 일반 부착**이다.
  여기서 예외를 두면 지속 없는 영구 부착이 생겨 두 축이 다시 섞인다.
- **판정 전용 원소**도 있다. 스사노오 `뇌신`(242)은 자신에게 바람·번개 *판정*을 더할 뿐 부착하지 않는다.
- 페이즈가 갈리는 보스는 `ChangeInnateElement`로 **속성만** 바꾼다. 이미 걸린 부착은 건드리지 않는다.

## 3. 부착 규칙

| 항목 | 값 |
| --- | --- |
| 부착 지속 | **5턴** (`Unit.CommonElementAuraDuration`). 부착된 유닛의 턴으로 센다 |
| 근거 | 원신의 1U 오라 감쇠 시간(9.5초)을 턴으로 옮긴 값 |
| 부여 | `GrantCombatElement(element, duration, source)` |
| 재부착 | 같은 원소를 다시 받으면 **지속이 새로 채워진다** — 바람·바위만 같은 원소 반응의 방아쇠가 된다(§4.8) |
| 초기화 | 라운드 시작/종료 시 `ResetCombatElements()` — 속성만 남는다 |
| 신호 | `Unit.AnyCombatElementGranted` — 이시스 `사막의 광휘`(325) 등이 듣는다(§5.2) |

### 3.1 부착 지속 보정

부착은 `UnitStatus`가 아니라 `Unit`이 직접 들고 있는 타이머다. 그래서 상태 지속을 늘리는
`GrantedStatusDurationAdditiveModifier`로는 닿지 않고, 별도의
**`GrantedElementDurationAdditiveModifier(source)`** 가 받는다.

읽는 쪽은 **부착을 건 유닛**이다. 맞는 쪽이 아니라 거는 쪽이 오래 남기는 것이므로,
`Unit.GrantCombatElement`가 `source`의 효과를 훑어 합산한다. 지금 쓰는 것은
여덟 갈래 고리(423) 하나뿐이다.

### 3.2 유발자 없는 부착

`GrantCombatElement(element)`처럼 **source 없이** 건 부착은 반응의 유발자가 **대상 자신**이 된다.
위력이 대상의 특수공격력을 따라가고 오사방지(§4.6)도 걸리지 않는다. 🔸 지금 이 경로를 쓰는 코드는 없다.

## 4. 원소 반응

두 원소가 한 유닛에게 겹치면 반응이 일어난다. **두 원소가 모두 소모되고** 결과가 남는다.
7원소 × 자기 조합 포함 **23쌍**이며, 공허는 반응에 참여하지 않는다.

### 4.1 반응 행렬

|  | 불 | 물 | 풀 | 전기 | 얼음 | 바람 | 바위 |
| --- | --- | --- | --- | --- | --- | --- | --- |
| **불** | — | 증발 | 화상 | 과부하 | 융해 | 확산 | 단조 |
| **물** | | — | 개화 | 감전 | 빙결 | 확산 | 풍화 |
| **풀** | | | — | 활성 | 휴면 | 확산 | 성장 |
| **전기** | | | | — | 초전도 | 확산 | 접지 |
| **얼음** | | | | | — | 확산 | 경화 |
| **바람** | | | | | | 확산 | 확산 |
| **바위** | | | | | | | 진동 |

계열로 묶으면 다음과 같다.

| 계열 | 반응 | 성격 |
| --- | --- | --- |
| 증폭 (2) | 증발 · 융해 | 해로움 |
| 확산 (7) | 바람 + X 여섯 쌍, 바람 + 바람 | 퍼뜨림 / 광역 피해 |
| 제어 (2) | 빙결 · 진동 | 해로움 |
| 즉발 (1) | 과부하 | 해로움 |
| 지속피해 (3) | 화상 · 감전 · 풍화 | 해로움 |
| 디버프 (2) | 활성 · 초전도 | 해로움 |
| 버프 · 보호막 (4) | 성장 · 단조 · 개화 · 경화 | **이로움** |
| 무효 (2) | 접지 · 휴면 | 두 원소만 지운다 |

### 4.2 세 가지 기본 규칙

| 규칙 | 내용 |
| --- | --- |
| **귀속** | 결과는 언제나 **원소가 부착된 유닛**이 가져간다. 버프도 마찬가지다 |
| **위력** | 전부 **유발자의 특수공격력** 비례(버프·효과가 반영된 최종값). 받는 쪽은 **특수방어력**으로 경감한다 |
| **소모** | 참여한 두 부착 원소가 걷힌다. 속성(고유 원소)은 걷히지 않는다 |

버프 반응은 **자기 자신에게 원소를 둘러 만드는 것이 정규 운용**이다. 적에게 잘못 만들면
적을 이롭게 하고, 그것이 이 시스템의 상성이다. 특수공격력은 피해 계수가 아니므로
**특수공격력이 높은 서포터가 반응을 키우는 자리**를 가져간다.

반응이 만드는 피해는 `CodeType.Effect` · **단일 · `ElementalReaction` · 비접촉** 태그다(`DealReactionDamage`).
`ElementalReaction` 태그와 `CodeType.Effect`가 있으면 방어력이 아니라 **특수방어력**이 경감한다 — [Detail_02 §3.2](Detail_02_Combat.md).

**공통 수식** (K = `100 + 6 × (유발자 레벨 − 1)`, [Detail_03 §1.2](Detail_03_Character.md))

```
반응 위력(r)   = 유발자 특공 × r × 전장 반응 배율          ReactionPower
반응 증폭      = 1 + 특공 / (특공 + K)                     DamageMitigation.ReactionAmplifier
스탯 반응 배율 = 30% × 특공 / (특공 + K)                   StatRatio (0 ~ 30%)
```

표준 특공(60 + 3.5/Lv)이면 레벨과 무관하게 증폭은 약 1.37배, 스탯 반응은 약 11%다. 비율식이라 레벨이 끝없이 올라도 한쪽으로 쏠리지 않는다.

### 4.3 계열별 상세

**증폭 (2)** — 부착 직전에 들어간 그 공격을 되짚어 키운다. 두 반응의 계산 축은 같다.

| 조합 | 이름 | 효과 |
| --- | --- | --- |
| 불 + 물 | **증발** | `특공 × 0.4` + **그 공격 피해 × (반응 증폭 − 1)** |
| 불 + 얼음 | **융해** | 〃 |

> 부착은 언제나 피해 **뒤**에 오므로(`TakeDamage` → `GrantCombatElement`), "이번 공격을 키운다"를
> 사후 추가 피해로 환산했다. 유발자가 **같은 대상에게** 방금 입힌 피해만 되짚는다
> (`Unit.LastResolvedDamage` / `LastResolvedTarget`). 피해가 없는 부착으로는 성립하지 않고
> 다음 순위로 넘어간다. 반응 피해 증폭 코드(§5.1)는 고정 피해 몫에만 곱한다.

**확산 (7)** — 바람의 전용 계열. 여섯 쌍은 **판정상 하나의 반응**이다.

| 조합 | 이름 | 효과 |
| --- | --- | --- |
| 바람 + 불/물/풀/전기/얼음/바위 | **확산** | **부착된 유닛과 같은 진영 전체**에 그 원소를 부여 |
| 바람 + 바람 | **확산** | 같은 진영 전체에 `특공 × 0.7` 피해 |

> **확산이 뿌린 부착은 다시 반응하지 않는다**(`GrantCombatElement(..., suppressReaction: true)`).
> 부착 지점이 곧 반응 지점이라 이 차단이 없으면 확산 → 반응 → 확산이 무한히 돈다.
>
> 진영은 **부착된 유닛 쪽**이다. 적에게 만들면 적 전체, 자신에게 만들면 아군 전체다.
> 바람 + 바람도 마찬가지라, 자기에게 바람을 두 번 두르면 **아군 전체가 맞는다.**
> 바람 + 바람은 판정상 즉발 계열이라 우선순위·내부 쿨다운도 과부하와 같다.

**제어 (2)**

| 조합 | 이름 | 효과 |
| --- | --- | --- |
| 물 + 얼음 | **빙결** | `round(2 × 특공/특방)`턴 (1~3턴) 행동 불가 |
| 바위 + 바위 | **진동** | `round(특공/특방)`턴 (1~2턴) 기절 |

> 빙결·진동은 [Detail_02 §5](Detail_02_Combat.md) **제어 분쇄**의 대상이다.

**즉발 (1)**

| 조합 | 이름 | 효과 |
| --- | --- | --- |
| 불 + 전기 | **과부하** | `특공 × 1.2` 피해 |

**지속피해 — 자연 발동과 수명 시계를 분리한다.**

| 생성 | 이름 | 1회 기준 피해 | 자연 발동 | 기본 수명 |
| --- | --- | --- | --- | --- |
| 물 + 전기 | 감전 | 생성자 현재 특공 60% | 대상 일반행동 시작 | 대상 일반행동 2회 |
| 불 + 풀 | 화상 | 생성자 현재 특공 20% | 대상 모든 실제 행동 시작 | 대상 일반행동 2회 |
| 코드 직접 부여 | 맹독 | 대상 현재 최대 HP 1.5% | 대상 일반행동 시작 | 대상 일반행동 2회 |
| 코드 직접 부여 | 저주 | 생성자 현재 특공 50% | 생성자 일반행동 시작 | 대상 일반행동 2회 |
| 물 + 바위 | 풍화 | 기존 반응 특공 60% | 기존 일반/추가/초월기 시작 | 기존 대상 턴 2회 |

네 공통 지속피해는 특수방어력 경감·치명 없음. 종류별 대상당 1개이며 서로 다른 종류는 공존한다. 성공한 재부여는 `max(남은 기간, 새 기본 기간+기간 보너스)`로 갱신한다. 원 생성자가 살아 있으면 귀속을 유지하고 사망한 뒤 새 생성자가 성공적으로 부여하면 교체한다. 생성자 사망 후 피해는 마지막 특공 값을 보존한다. 저주의 생성자가 사망하면 자연 발동은 멈추지만 야마의 즉시 발동은 가능하다.

새로 붙은 행동의 종료로 수명을 즉시 소모하지 않는다. 지속피해 수명은 실제 일반행동 완료에만 감소한다. 추가·특수·협동·초월기는 수명을 소모하지 않는다. 반응 생성은 성공한 두 번째 부착 판정을 상속하며 직접 부여는 통상 효과 명중 75%를 사용한다. 피해는 원 생성자의 지속피해 보상, 츠쿠요미의 독립 오라, 대상의 현재 취약을 한 번씩 적용한다. 야마의 즉시 발동은 원본·남은 기간을 소비하지 않는다.

**디버프 (2)** — 배율 = 스탯 반응 배율, 3턴.

| 조합 | 이름 | 효과 |
| --- | --- | --- |
| 풀 + 전기 | **활성** | **특수방어력이 경감하는** 피해(지속피해 · 반응)를 더 받는다 |
| 전기 + 얼음 | **초전도** | **방어력이 경감하는** 일반 피해를 더 받는다 |

**버프 · 보호막 (4)** — 배율은 디버프와 같은 스탯 반응 배율, 3턴.

| 조합 | 이름 | 효과 |
| --- | --- | --- |
| 풀 + 바위 | **성장** | 방어력% 증가 |
| 불 + 바위 | **단조** | 속도% 증가 |
| 물 + 풀 | **개화** | 최대 체력% 증가 |
| 얼음 + 바위 | **경화** | `특공 × 1.5` 보호막. 반응 피해 증폭 코드(§5.1)가 이 양에도 곱해진다 |

| 조합 | 이름 | 효과 |

### 4.4 우선순위

여러 쌍이 동시에 성립하면 **하나만** 발동한다. 방금 부착된 원소가 반드시 참여해야 한다.

| 순위 | 계열 | 이유 |
| --- | --- | --- |
| 1 | 증폭 | 진행 중인 공격에 얹는다. 이번에 못 쓰면 사라진다 |
| 2 | 확산 | 원소를 퍼뜨려 다음 반응의 재료를 만든다 |
| 3 | 제어 | 판을 가장 크게 바꾼다. 분쇄·내부 쿨다운이 따로 누른다 |
| 4 | 즉발 피해 | 과부하 · 바람 + 바람 |
| 5 | 지속피해 | 밀려도 다음 부착에서 다시 잡힌다 |
| 6 | 디버프 | |
| 7 | 버프 · 보호막 | 자기 부착으로 만드는 것이라 경합이 드물다 |
| 8 | 무효 | 다른 반응이 가능하면 굳이 고를 이유가 없다 |

동순위면 **남은 부착 지속시간이 가장 긴 원소**(= 가장 최근에 붙은 것)와 짝짓는다.
구현에서는 `ReactionKind`의 **선언 순서가 곧 우선순위**다.
내부 쿨다운(§4.7)에 걸린 쌍과 피해가 없는 증폭은 후보에서 빠지므로 다음 순위가 발동한다.

### 4.5 판정 흐름

```
GrantCombatElement(원소, 지속, 유발자)
 ├ 부착(이미 있던 원소면 지속만 갱신) → AnyCombatElementGranted
 └ suppressReaction이 아니면 ElementalReaction.TryResolve
     ├ 23쌍 중 성립하는 쌍을 모은다 (방금 붙은 원소 포함, 둘 다 '부착' 축)
     ├ 내부 쿨다운·증폭 피해 없음은 제외
     ├ 계열 순위 → 남은 지속으로 하나를 고른다
     ├ 오사방지에 걸리면 여기서 끝 (부착은 남는다)
     └ 두 원소 소모 → 계열별 결과 → AnyElementalReaction
```

### 4.6 오사방지 — 아군이 아군에게 만든 해로운 반응

잔의 `오사방지`(104)를 든 유닛이 진영에 서 있으면, **같은 진영끼리 만든 해로운 반응**
(제어·즉발 피해·지속피해·디버프)이 발동하지 않는다. 버프·보호막·무효는 그대로 터진다.
**증폭은 막지 않는다** — `ElementalReaction.IsHarmful`에 들어 있지 않다. 증폭은 유발자가 *그 대상에게* 방금 입힌
피해를 되짚으므로 아군을 때리는 공격이 없는 한 같은 진영에서 성립하지 않는다.

버프 반응은 자기 진영에 원소를 둘러 만드는 것이 정규 운용인데, 그 과정에서 감전·과부하·초전도가
걸리면 **자동 전투라 되돌릴 수단이 없다.** 그 사고만 골라 지우는 장치다.
**적이 아군에게 건 반응은 막지 않는다** — 그건 상대의 정당한 수단이다.

부착 자체는 막지 않으므로 재료는 그대로 남고 반응만 쉰다.

### 4.7 재발동 내부 쿨다운

같은 대상에서 **같은 반응**이 연달아 터지는 것을 막는다.

| 계열 | 간격 |
| --- | --- |
| 제어 | **3턴** |
| 지속피해 · 즉발 | **1턴** |
| 그 외 | 없음 |

**부착 자체는 막지 않는다.** 막으면 원소 숙련 코드(`X 원소를 보유한 적에게 +10%`)가
함께 꺼져 원소 딜러가 서로를 방해하게 된다. 반응만 쉬고 부착은 남는다.

간격은 **대상의 턴**으로 세며 라운드마다 초기화된다(`Unit.IsReactionReady`).
여섯 갈래 확산은 판정상 한 반응이라 쿨다운 키도 하나다(`ReactionId.Diffusion`).

### 4.8 같은 원소 반응

같은 원소 반응은 바람+바람의 확산과 바위+바위의 진동만 유지한다. 그 외 같은 원소의 재부착은 부착 기간만 갱신하고 피해·버프·제어를 만들지 않는다. 속성은 여전히 부착 재료가 아니다.

### 4.9 공허는 반응하지 않는다

부착할 원소가 없어서가 아니라 **의도된 설계**다.
공허 괴수와의 전쟁이 이 게임의 기본 컨셉이므로, 공허는 원소 판을 함께 굴리는 여덟 번째
원소가 아니라 **원소 바깥에 서 있는 것**이어야 한다. 공허 괴수의 기본형(무속성 변형)이
원소 빌드에 아무 재료도 내주지 않는 것도 같은 이유다.

### 4.10 공통 규칙 요약

| 규칙 | 내용 |
| --- | --- |
| 판정 시점 | `Unit.GrantCombatElement` — 부착 직후 한 번 |
| 중첩 | 지속피해는 `ExtendDuration`, 버프·디버프는 `Replace` |
| 상태 ID | 감전 5910 · 화상 5911 · 풍화 5912 · 반응 버프 5913 · 활성/초전도 5914 (`ElementalReaction.*StatusId`) |
| 알림 | `Unit.AnyElementalReaction(유발자, 대상, 반응 이름)` |
| 디버그 | `DebugReactionLog`가 같은 신호를 받아 기록한다 (F1 패널) |

## 7. 전장 상태 (Field) — 속성으로 판정한다

**판 전체에 걸리는 것.** `Combat.Battlefield`가 한 번만 적어 두고 피해 계산이 그때그때 읽는다.

| 지속 | **깐 유닛의 턴**으로 센다. 깐 유닛이 쓰러지면 걷힌다 |
| 적용 | 양 진영 모두 · **속성** 기준 |
| 초기화 | 라운드 종료 |

| 필드 | 효과 |
| --- | --- |

🔸 지금 필드를 까는 코드는 없다. 페널티를 무시하는 쪽은 `IFieldPenaltyImmunity`를 구현한다.

## 8. 테마마다 노리는 반응

**적이 아무 원소나 부착하면 안 된다.** 버프 반응은 부착된 유닛이 가져가므로 적이 만들면 플레이어를 이롭게 한다.
테마마다 해로운 쌍 하나를 정체성으로 고르고 버프가 되는 원소는 일부러 부착하지 않는다.

🔸 공허의 시험장(테마 1)의 적은 원소가 없다. 새 테마를 들일 때 이 표를 다시 채운다.
